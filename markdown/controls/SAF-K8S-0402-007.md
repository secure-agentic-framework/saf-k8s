# SAF-K8S-0402-007 - OIDC authentication integration

- Domain: D04 - Identity, Access, and Secrets Management
- Knowledge Area: 4.2 - Service Accounts and Workload Identity
- Maturity: Practitioner
- Classification: baseline

## Statement

Authenticate governed human Kubernetes API access through an approved identity provider. Verify trusted token issuer, signature, audience, expiry and applicable claims. Bind mapped human identities and groups to reviewed RBAC, and establish a measured offboarding interval.

## Objective

Attribute approved human API access to distinct identities, enforce least privilege, and verify how authentication and authorization end during offboarding.

## Rationale

API JWT validation can accept an already issued token until expiry while RBAC independently changes access. Identity-provider login, MFA, reauthentication, refresh and session invalidation depend on the deployed integration, policy and client. Verify each of these layers for the selected use.

## Scope

Applies to human Kubernetes API users and related interactive access paths. Treat workload identities and emergency access as separately governed paths. Document the supported Kubernetes and provider integration versions.

## Enforcement

- Primary Enforcement Point: Kubernetes JWT authentication and separate reviewed RBAC, with upstream identity provider login and offboarding policy.
- Implementation Surface: Use structured AuthenticationConfiguration where supported or a documented compatible OIDC configuration. Verify signature, issuer, audience, lifetime, required claims, reserved name handling and mapped RBAC. Exercise loss of access, outstanding token validity, refresh or reissuance, and provider-specific support for required MFA and session rules.
- Owner Primary: Identity and Access Management
- Owner Supporting: Platform Engineering; Security Engineering
