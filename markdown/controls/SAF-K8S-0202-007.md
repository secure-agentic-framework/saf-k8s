# SAF-K8S-0202-007 - Pod user namespace isolation

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.2 - Container Runtime Security
- Maturity: Foundational
- Classification: baseline

## Statement

For supported Linux workloads, require Pods to opt in to user namespaces with spec.hostUsers set to false. Verify the effective kubelet and runtime mapping so UID and GID zero inside the Pod map to nonzero host IDs. Require documented approval and compensating controls for exceptions.

## Objective

Constrain workload privileges at the Linux user namespace boundary by mapping Pod root identities to unprivileged host IDs.

## Rationale

Kubernetes v1.36 made Linux Pod user namespaces generally available. Kubelet assigns host UID and GID mappings to opted-in Pods. The effective Pod mappings establish this control. SAF-K8S-0202-012 covers rootless node components, where the optional kubelet runningInUserNamespace report concerns node processes.

## Scope

Applies to Linux Pod workloads in production pools with a compatible Kubernetes release, kubelet, container runtime, kernel and filesystems. Test support for the workload and its volume configuration. Document unsupported cases, their approved exceptions, and compensating controls.

## Enforcement

- Primary Enforcement Point: Pod admission for the opt-in and kubelet, runtime and kernel for the effective identity mapping.
- Implementation Surface: Verify the deployed API server and kubelet versions, feature configuration and pool and workload compatibility. Enforce explicit Pod opt-in in the applicable scope. Corroborate the effective kernel UID and GID mappings against the node process context for representative running Pods. Resolve nested mappings through their parent namespaces before drawing conclusions about host IDs. Maintain reviewable exception records. On supported Linux pools that use Pod user namespaces, preflight kubelet upgrades against the target release's documented UID/GID range constraints and helper behavior; inspect the kubelet user's subordinate UID/GID ranges, record whether `getsubids` is installed where applicable, and identify existing Pod mappings or failed sandbox events that may be incompatible with the target kubelet. Resolve incompatibilities through a supported, workload-aware maintenance procedure before proceeding, and retain per-pool evidence.
