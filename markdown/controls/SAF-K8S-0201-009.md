# SAF-K8S-0201-009 - Kubelet systemd unit hardening

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.1 - Kubelet and Node Configuration Hardening
- Maturity: Foundational
- Classification: baseline

## Statement

Apply a systemd hardening profile compatible with the deployed kubelet and node. Define capability bounds, protection against additional privilege acquisition, restricted filesystem access and socket families as applicable. Verify effective running process restrictions and retained kubelet duties.

## Objective

Constrain the kubelet's operating-system authority while preserving the approved node functions.

## Rationale

NoNewPrivileges limits subsequent privilege acquisition during execution. Capability bounds must be evaluated independently. Filesystem and socket restrictions depend on systemd, kernel and service dependencies, and the effective runtime outcome needs verification.

## Scope

Applies to governed systemd-managed kubelets and equivalent managed-node controls. Identify systemd, kernel and runtime versions, mount and device dependencies, required socket families and applicable provider evidence.

## Enforcement

- Primary Enforcement Point: Effective systemd configuration, Linux process security state and retained node and workload operation.
- Implementation Surface: Review service, drop-in and dependency configuration. Specify required permissions and exception ownership. Probe effective capability bounds and privilege, mount and socket restrictions, then exercise node readiness and new workloads under the hardened profile.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; OS/Infrastructure
