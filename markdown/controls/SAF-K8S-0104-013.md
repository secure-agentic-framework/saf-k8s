# SAF-K8S-0104-013 - Kubernetes upgrade strategy, validation, and rollback planning

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.4 - CIS Benchmarks and Patch Management
- Maturity: Foundational
- Classification: baseline

## Statement

Maintain a supported Kubernetes upgrade plan with assigned component owners, version skew and sequencing requirements, compatibility and service validation, and an exercised recovery strategy. Define routine and emergency decision rights and record recovery limits.

## Objective

Upgrade through supported component versions while maintaining expected workload and control-plane behavior and recoverability.

## Rationale

Upgrade support depends on the deployed version and distribution, provider responsibility, component ordering and configuration or data changes. Recoverability can require restoration, recreation or a forward fix when a downgrade is unsupported.

## Scope

Applies to governed Kubernetes upgrades and relevant control plane, worker, runtime, network, storage, and supporting add-on boundaries. Inventory supported technology and owned versus provider-operated responsibilities.

## Enforcement

- Primary Enforcement Point: Approved versioned upgrade execution and exercised, supported service recovery at each applicable boundary.
- Implementation Surface: Verify supported version edges, preflight compatibility, backup and restoration, API and workload outcomes, and post-upgrade versions. Record an abort threshold, recovery owner and evidence from the applicable restore, recreation, forward fix or supported rollback.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Change Management
