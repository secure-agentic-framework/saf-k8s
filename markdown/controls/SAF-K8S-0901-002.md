# SAF-K8S-0901-002 - Parameter server and all-reduce security

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.1 - Distributed Training Workload Security
- Maturity: Advanced
- Classification: ai-specific

## Statement

Parameter server and all-reduce distributed training architectures must implement protections against gradient poisoning, worker impersonation, and Byzantine fault injection through authenticated aggregation, gradient validation, and anomaly detection on contributed updates.

## Objective

Prevent adversarial manipulation of model training through the gradient aggregation process by detecting and rejecting poisoned, impersonated, or Byzantine-faulty worker contributions.

## Rationale

Parameter servers and all-reduce rings aggregate gradient updates from all workers to update the shared model. An attacker who can impersonate a worker or inject crafted gradient values can poison the model, introduce backdoors, or degrade model accuracy. Byzantine workers can submit arbitrary values that corrupt the aggregation without detection.

## Scope

Applies to all distributed training topologies that use parameter server or all-reduce aggregation patterns. Covers both synchronous and asynchronous training configurations. Excludes single-worker training and inference workloads.

## Enforcement

- Primary Enforcement Point: Training operator configuration, parameter server deployment manifests, and gradient aggregation middleware.
- Implementation Surface: Bind authenticated worker identities to the approved round or collective membership. Validate eligible updates before aggregation, record bounded anomaly decisions and exclude unauthorized or quarantined contributions. Use the training runtime and operator settings appropriate to the topology. A parameter server can apply a reviewed robust aggregation strategy when its participant and fault assumptions hold. An all-reduce deployment must establish compatible authorization and validation at the controlled participation and reduction boundaries. Select and test channel protections, thresholds, failure handling and model-quality checks for the deployed runtime.
- Owner Primary: ML Platform Engineering
- Owner Supporting: Security Engineering; ML Engineering
