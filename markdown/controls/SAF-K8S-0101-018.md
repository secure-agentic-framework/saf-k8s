# SAF-K8S-0101-018 - API server anonymous authentication disablement

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.1 - Kubernetes API Server Security
- Maturity: Foundational
- Classification: baseline

## Statement

Production Kubernetes clusters must disable anonymous authentication on the API server. Replace control-plane health checks that depend on anonymous access with authenticated health checks before applying the change. Verify that requests without credentials are rejected and that the control plane remains healthy with authenticated probes and clients.

## Objective

Prevent unauthenticated access attempts from reaching the Kubernetes API server as anonymous requests.

## Rationale

When anonymous authentication is enabled, Kubernetes can assign requests without credentials the system:anonymous identity, which remains subject to authorization. Default or configured authorization rules can permit anonymous access to public endpoints. Disabling anonymous authentication removes this request path and also rejects unauthenticated health probes, which may prevent the API server from becoming or remaining Ready.

## Scope

Applies to all production Kubernetes clusters and to non-production clusters that host sensitive data, shared workloads, or provide a path to production. For managed services, applies to all customer-exposed API server authentication settings and compensating controls when provider-managed settings are fixed.

## Enforcement

- Primary Enforcement Point: API server authentication configuration.
- Implementation Surface: API server manifest flags or authentication configuration, authenticated control-plane probes, managed Kubernetes security settings, and tests of unauthenticated rejection and authenticated availability.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Cloud Platform Engineering
