# SAF-K8S-0505-006 - API server private endpoint and authorized network enforcement

- Domain: D05 - Network Security and Communication
- Knowledge Area: 5.5 - API Server and Service Exposure Protection
- Maturity: Practitioner
- Classification: baseline

## Statement

Restrict each enabled Kubernetes API server endpoint to approved management access paths. Use a verified private network boundary, an authorized-source policy on applicable endpoints, or an equivalent provider-supported control. Check every enabled endpoint and address family.

## Objective

Reduce API server exposure by limiting management reachability to approved networks and verifying the working administrative path.

## Rationale

Enforce the network boundary before API authentication where the endpoint design permits it. DNS visibility, IP reachability and API authentication are separate. A private address still requires verification of reachable sources and routes.

## Scope

Applies to production Kubernetes control planes and non-production endpoints with access to production secrets or infrastructure. Inventory enabled IP and DNS endpoints, cloud management paths, node and automation access, and approved exceptions.

## Enforcement

- Primary Enforcement Point: Effective provider endpoint controls or self-managed listener routing and firewalls.
- Implementation Surface: For GKE, review DNS endpoint IAM and perimeter controls separately from IP endpoint authorized networks, including internal enforcement settings. For EKS, verify public endpoint CIDRs and private endpoint security-group rules independently. For AKS, distinguish public authorized ranges from private-cluster controls. For each topology, verify approved and denied paths to every actual endpoint and configured port, including DNS and address-family behavior.
- Owner Primary: Platform Engineering
- Owner Supporting: Network Engineering; Security Engineering; Cloud Platform Engineering
