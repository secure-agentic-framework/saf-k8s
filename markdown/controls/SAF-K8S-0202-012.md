# SAF-K8S-0202-012 - Rootless node verification and placement eligibility

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.2 - Container Runtime Security
- Maturity: Foundational
- Classification: baseline

## Statement

Where a cluster or node pool claims rootless operation, verify that the kubelet, runtime and applicable node networking components share the intended noninitial Linux user namespace with non-root host UID and GID mappings. Treat absent, stale or uncorroborated status as unknown. Where workload placement depends on rootless operation, independently control the grant, renewal and removal of a trusted eligibility label or equivalent scheduling policy.

## Objective

Substantiate claimed rootless node operation and govern placement of workloads that require it.

## Rationale

Kubernetes v1.37 enables the beta KubeletInUserNamespace gate by default and can report status.nodeInfo.runningInUserNamespace. The gate does not create a Linux user namespace. The status is a kubelet report, so use independent process observations to confirm effective namespace membership and UID and GID mappings.

## Scope

Applies to deployments claiming rootless Kubernetes node components. Verify the kubelet, CRI runtime, kube-proxy when applicable and active node CNI components. Record OS, runtime, network, storage and provider prerequisites and approved exceptions. Pod user namespaces have a separate scope.

## Enforcement

- Primary Enforcement Point: Effective node process configuration and independently managed workload eligibility policy.
- Implementation Surface: Correlate current Node status with host-side observations of process user namespaces, UID and GID maps, and subordinate mappings. For standard node selectors, verify Node authorization and NodeRestriction on reserved labels. Separately restrict other label writers to approved identities with scoped access. Define when corroborated evidence expires, when eligibility is granted or removed, and how existing placements are reviewed after withdrawal.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; OS/Infrastructure
