# SAF-K8S-0102-025 - etcd backup repository access review and alerting

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.2 - etcd and Cluster State Protection
- Maturity: Foundational
- Classification: baseline

## Statement

Review and alert on defined etcd backup access events using the sources that actually observe each customer-controlled path. Monitor coverage gaps and document provider-managed responsibilities, assurance and unavailable event classes.

## Objective

Surface actionable backup access exceptions and loss of visibility with clear ownership, evidence provenance and response deadlines.

## Rationale

Kubernetes API activity, storage object operations, file activity and media custody have distinct recording sources. Missing evidence requires investigation or an approved compensating process. Provider-operated backup events may be unavailable to the customer.

## Scope

Applies to governed production backup, transfer, retention and restore paths. Inventory owners, selected event types, access modes, identified provider boundaries, review schedules, alert routes and evidence retention.

## Enforcement

- Primary Enforcement Point: Verified source coverage, accountable review or configured alert rules, protected evidence retention and owned response.
- Implementation Surface: Test applicable allowed and denied marker access and provider or API event delivery. Verify rule evaluation, access-identity context, deduplication where used, alert receipt, response ownership and detection of missing or stale sources.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Backup and Recovery Operations
