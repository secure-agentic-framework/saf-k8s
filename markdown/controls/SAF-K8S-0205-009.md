# SAF-K8S-0205-009 - Service proxy path hardening for kube-proxy or replacements

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.5 - kube-proxy and Node Networking Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Harden the active Service proxy using supported version-specific settings. Review effective Kubernetes API permissions, node or container privileges, and applicable connection tracking settings separately. Preserve required Service behavior after approved changes.

## Objective

Constrain unnecessary access and features in the effective Service proxy without losing required forwarding.

## Rationale

API authorization and host privileges act at different boundaries. Connection tracking settings govern distinct resource and protocol behaviors and depend on the selected implementation. Workload network policy requires independent datapath evidence.

## Scope

Applies to governed kube-proxy, replacement and supported hybrid or provider-managed paths. Identify the active implementation and version for each path and record required privileges, settings, exceptions and owner.

## Enforcement

- Primary Enforcement Point: Effective API authorization, supported process privileges and applicable settings of the active proxy path.
- Implementation Surface: Verify required and denied API operations, effective process or node privileges, and the supported connection tracking and interface settings selected for the deployment. Exercise required Service traffic after changes. Record separately applicable CNI policy and provider evidence.
- Owner Primary: Platform Engineering
- Owner Supporting: Network Engineering; Security Engineering
