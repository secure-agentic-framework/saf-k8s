# SAF-K8S-0604-011 - SLSA provenance generation and target-level governance

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.4 - SBOMs and Vulnerability Intelligence
- Maturity: Practitioner
- Classification: baseline

## Statement

Specify the approved SLSA Build track version and target for each governed release path. Generate provenance for each exact artifact as required by that target. Verify the subject, applicable signature and trusted builder identity, expected build parameters and minimum assurance against an independently maintained trust policy before accepting the release.

## Objective

Retain auditable evidence of the artifact, verified build claims, assessed builder capabilities and policy that authorized acceptance.

## Rationale

Verified provenance authenticates recorded build assertions for its subject. SLSA Build levels depend on assessed properties of the actual producer, build platform and provenance protection. Determine the applicable level from configured trust and assessment evidence. A predicate field or signature alone is insufficient.

## Scope

Applies to all CI/CD pipelines producing deployable Kubernetes artifacts, including application images, AI workload images, and infrastructure operator images. The target SLSA level and roadmap must be reviewed at least annually or when pipeline risk materially changes.

## Enforcement

- Primary Enforcement Point: Build platform provenance generation, independent builder assessment and release or admission verification.
- Implementation Surface: Record the approved target, policy authority, covered release path, recognized signer and builder identity, trusted maximum level and assessment evidence. Verify the exact subject, provenance and applicable expectations. Track review dates, improvement actions and exceptions independently from self-reported build claims.
- Owner Primary: DevSecOps / Release Engineering
- Owner Supporting: Security Engineering; Platform Engineering
