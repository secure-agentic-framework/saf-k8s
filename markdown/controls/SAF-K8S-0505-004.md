# SAF-K8S-0505-004 - API server audit log analysis for network-based attack detection

- Domain: D05 - Network Security and Communication
- Knowledge Area: 5.5 - API Server and Service Exposure Protection
- Maturity: Practitioner
- Classification: baseline

## Statement

API server audit logs must be continuously analyzed for network-based attack indicators including unauthorized access attempts from unexpected source IPs, anomalous API request patterns indicating reconnaissance or exploitation, and authentication failures correlated with network origin to detect credential-based attacks.

## Objective

Detect selected signs of unauthorized API activity through timely collection and analysis of in-scope audit events. Validate supported events, source attribution limits, and the alert delivery path.

## Rationale

Kubernetes audit records depend on the configured policy, request stage and delivery path. Audit metadata can associate API activity with the authenticated or impersonated identity and recorded network addresses. Forwarded addresses can be client-supplied unless a verified proxy path strips and replaces them. The final address is immediate connection context. Correlate with independently trusted network telemetry where the original client identity matters.

## Scope

Applies to in-scope production Kubernetes API endpoints. Inventory audit policies and managed provider coverage. Verify authorized collection, gaps between stages, delivery and latency, trusted network attribution and review of detection results.

## Enforcement

- Primary Enforcement Point: API server audit policy and backend, governed event collection, and the detection and alert delivery pipeline.
- Implementation Surface: Use the minimum audit level and stages needed for each rule. Prefer Metadata when content is unnecessary. Test expected recorded and excluded API events, benign and flagged examples, and successful alert delivery. Validate explicit trusted proxy configuration and correlate source context with independent network telemetry before attributing activity to an originating client.
- Owner Primary: Security Operations
- Owner Supporting: Platform Engineering; Network Engineering
