# SAF-K8S-0201-013 - Kubelet client certificate rotation via TLS bootstrap

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.1 - Kubelet and Node Configuration Hardening
- Maturity: Foundational
- Classification: baseline

## Statement

Maintain a current, API-server-trusted client certificate for each governed kubelet's node identity. Use an approved enrollment path and renew and activate the replacement before expiry. When using native Kubernetes TLS bootstrap and rotation, verify the effective approver, signer and client trust.

## Objective

Maintain authenticated node-to-API-server communication with attributable enrollment and pre-expiry replacement of each kubelet client certificate.

## Rationale

Node client certificate issuance, approval, API-server trust and activation are related checks. Timely rotation and observable failures help prevent unexpected expiration and loss of node authentication.

## Scope

Applies to all governed kubelets, including initial and joined control-plane nodes and workers. Account for protected initial provisioning, native worker or node bootstrap, external CA, and provider-operated lifecycle. Verify equivalent node identity, trust, replacement and monitoring evidence for each applicable path.

## Enforcement

- Primary Enforcement Point: Kubelet bootstrap configuration, certificate signing workflow, and client certificate rotation monitoring.
- Implementation Surface: Verify node-bound client certificate subject and uses, effective bootstrap or provisioning trust, rotateCertificates when used, scoped CSR approval and signer policy, and API-server client CA trust. Observe expiry, renewal failures and delayed approval, and confirm continued authenticated node activity after replacement.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; PKI/Certificate Management
