# SAF-K8S-0304-013 - Tmpfs-backed handling for sensitive training intermediates

- Domain: D03 - Workload and Pod Security
- Knowledge Area: 3.4 - Secure Defaults and Resource Constraints
- Maturity: Foundational
- Classification: baseline

## Statement

Sensitive intermediate training data that does not require durable persistence must be written only to memory-backed ephemeral scratch space that is discarded when the Pod is removed. For tmpfs-backed emptyDir, set medium to Memory and verify either that node swap is disabled or that the mounted filesystem uses noswap. Verify equivalent swap protection and lifecycle behavior for other memory-backed implementations.

## Objective

Reduce exposure of sensitive temporary training data by keeping qualifying intermediate artifacts in memory-backed ephemeral storage rather than on node-local disks.

## Rationale

Sensitive training intermediates can contain fragments of training data, embeddings, or model state. A memory-backed volume gives that data a Pod-scoped filesystem. Linux can move tmpfs pages to disk when node swap is enabled and the mount permits swapping. Kubelet can continue without the noswap option on a kernel that does not support it. Verify the effective mount or disable node swap, and review any other paths the workload uses to write sensitive scratch data.

## Scope

Applies to AI and ML training workloads that stage sensitive intermediate data, tokenized samples, gradients, or temporary outputs that do not require durable persistence.

## Enforcement

- Primary Enforcement Point: Pod specification validation, verification of node swap and effective mount options, and workload design review for sensitive scratch data.
- Implementation Surface: Workload manifests mapping sensitive temporary data to memory-backed scratch volumes, node swap configuration or observed tmpfs noswap mount options, and a Pod replacement check.
- Owner Primary: AI/ML Platform team
- Owner Supporting: Platform Engineering; Security Engineering
