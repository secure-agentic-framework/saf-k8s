# SAF-K8S-0103-019 - API server load-balancer health-check failover

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.3 - Controller-Manager, Scheduler, and Cloud Controller Security
- Maturity: Practitioner
- Classification: baseline

## Statement

For approved production API endpoint designs with multiple backends, configure automated health-based selection and verify endpoint continuity within the documented availability objective. Govern equivalent provider-managed or alternate access designs and retain applicable availability evidence.

## Objective

Preserve the supported Kubernetes API access path through backend failures and recovery within defined availability limits.

## Rationale

API endpoint availability depends on clients, load balancers, backend health and shared dependencies. TCP liveness and API readiness convey different evidence. Automatic failover, client retry and failback behavior need deployment-specific verification.

## Scope

Applies to governed production API access paths. Inventory endpoint architecture, backend instances and failure domains, health probe and criteria, removal and recovery thresholds, client behavior and applicable provider assurances.

## Enforcement

- Primary Enforcement Point: Effective supported control-plane endpoint routing, health evaluation and tested failover and recovery.
- Implementation Surface: Observe approved healthy traffic, induce a bounded backend outage in authorized scope, measure endpoint continuity and re-entry, and verify reporting with no eligible backend where feasible. Retain probe semantics, timing, client behavior and applicable provider SLA scope.
- Owner Primary: Platform Engineering
- Owner Supporting: Site Reliability Engineering; Security Engineering
