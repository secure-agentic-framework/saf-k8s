# SAF-K8S-0905-009 - Model provenance verification at deployment

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.5 - AI Supply Chain and Model Lifecycle
- Maturity: Advanced
- Classification: ai-specific

## Statement

Before allowing an inference deployment, verify the provenance and integrity of the exact model artifact it references. Validate trusted signatures and required attestation stages, compare the actual deployment reference with the verified immutable digest, and block absent, invalid or mismatched evidence.

## Objective

Admit only model deployments whose exact artifact reference is bound to verified origin and integrity evidence.

## Rationale

Build-time signing (SAF-K8S-0905-046) and training pipeline attestation generation (SAF-K8S-0905-047) create the cryptographic evidence, but without deploy-time enforcement an unsigned or tampered model can still be deployed by bypassing the signing pipeline. Admission controller verification provides an independent enforcement point that catches supply chain bypasses.

## Scope

Applies to all model deployments to production inference endpoints on Kubernetes. Covers admission controller signature verification, attestation chain validation, and OCI digest confirmation. Excludes build-time signing (SAF-K8S-0905-046) and training pipeline attestation generation (SAF-K8S-0905-047).

## Enforcement

- Primary Enforcement Point: Kubernetes admission controllers (Kyverno, Gatekeeper) or deployment pipeline verification hooks.
- Implementation Surface: Use an approved admission controller or deployment verification path for actual sources and artifact forms. Verify registry or storage digests, bind the verified digest to the admitted model reference, confirm required signatures and attestation stages, and collect refusal and deployment evidence.
- Owner Primary: Security Engineering
- Owner Supporting: ML Platform Engineering; DevOps Engineering
