# SAF-K8S-0303-001 - Seccomp profile enforcement

- Domain: D03 - Workload and Pod Security
- Knowledge Area: 3.3 - Mandatory Access Controls
- Maturity: Practitioner
- Classification: baseline

## Statement

Supported unprivileged Linux containers must use an approved RuntimeDefault or Localhost seccomp profile. Where risk or workload syscall requirements justify a custom profile, limit it to the approved operations needed by the workload and audit and version the policy.

## Objective

Reduce the Linux kernel attack surface available to each covered container by enforcing an approved system-call filter.

## Rationale

A seccomp filter limits system-call access. RuntimeDefault behavior varies with runtime and version. A custom profile can enforce workload-specific rules when the filter, architecture and runtime are verified in representative execution.

## Scope

Applies to supported unprivileged Linux containers, including regular, init and ephemeral containers. Document and review applicable exceptions. Verify separate isolation controls for workloads requiring privileged execution.

## Enforcement

- Primary Enforcement Point: Use Pod or container securityContext.seccompProfile, Pod Security Admission or an equivalent policy for allowed profile types, and the node runtime for effective filter enforcement.
- Implementation Surface: Inspect the effective Pod and container profile fields and verify Localhost profile installation on every eligible node. Manage versioned custom filters with the Security Profiles Operator or an equivalent distribution mechanism. Verify workload behavior, rollout, replacement, rollback, and provider and architecture support.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Application Development teams
