# SAF-K8S-0304-004 - Ephemeral container security context enforcement

- Domain: D03 - Workload and Pod Security
- Knowledge Area: 3.4 - Secure Defaults and Resource Constraints
- Maturity: Foundational
- Classification: baseline

## Statement

Restrict ephemeral debug changes to approved identities and required pods/ephemeralcontainers verbs. Apply the namespace Pod Security Standard and any additional workload-specific restrictions to ephemeral container updates. Retain audit decisions for permitted and denied requests.

## Objective

Apply the workload security boundary to authorized ephemeral debugging.

## Rationale

Ephemeral containers are added after Pod creation through the pods/ephemeralcontainers subresource. They are independently subject to admission on that update. RBAC limits who can add them, and policy must cover the subresource so the workload's configured security restrictions continue to apply during debugging.

## Scope

Applies to all pods in production clusters whenever kubectl debug or equivalent tooling is used to inject ephemeral containers. Init containers remain a distinct Pod field. The ephemeral-container subresource adds debug entries without converting init containers.

## Enforcement

- Primary Enforcement Point: Use RBAC for the pods/ephemeralcontainers subresource and enforce applicable Pod Security Admission or equivalent policy on the authorized update or patch requests.
- Implementation Surface: Verify requested subresource verbs and approvals for the intended identities. Explicitly match pods/ephemeralcontainers in any supplementary workload policies. Collect audit metadata for the actor, verb, namespace, resource, subresource and response. Set alert severity and delivery in the audit consumer.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering
