# SAF-K8S-0103-008 - Cloud controller-manager deployment isolation

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.3 - Controller-Manager, Scheduler, and Cloud Controller Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Where the supported target architecture uses an external cloud controller-manager, execute provider-specific controllers separately from the core Kubernetes controller manager and document distinct controller ownership. Govern migration stages and provider-operated boundaries explicitly.

## Objective

Preserve distinct execution and controller ownership boundaries for provider-specific and core Kubernetes reconciliation.

## Rationale

Separate execution allows independent deployment, identity assignment and maintenance. Effective Kubernetes and cloud privileges, shared dependencies and observed failure isolation require separate checks. A temporary migration can have a different process layout.

## Scope

Applies to governed production integrations using an external cloud controller-manager. Identify Kubernetes and provider versions, steady-state assignments, migration constraints, local owners and applicable provider evidence.

## Enforcement

- Primary Enforcement Point: Effective component deployment, running process identity and configured controller ownership.
- Implementation Surface: Verify separate deployment and runtime instances, applicable externally configured provider settings and controller inventories. Exercise expected independent maintenance where supported and separately verify effective permissions and shared dependency risks.
- Owner Primary: Platform Engineering
- Owner Supporting: Cloud Platform Engineering; Security Engineering
