# SAF-K8S-0101-016 - API server audit log backend delivery and durable storage

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.1 - Kubernetes API Server Security
- Maturity: Foundational
- Classification: baseline

## Statement

Production Kubernetes clusters must retain API server audit events in a durable backend, using rotated files on persistent storage or forwarding to an approved destination that durably ingests the events. Verify retained events remain retrievable across API server restarts and exercise the documented delivery and recovery behavior for backend disruption.

## Objective

Ensure API server audit records are delivered to a durable storage or forwarding destination that preserves availability for investigation and monitoring.

## Rationale

Audit event selection is ineffective if records are lost during restart, disk pressure, or forwarding failure. Retention depends on persistent storage and end-to-end ingestion. Audit webhook buffering and retries can still lose events during delivery failure, so verify destination retention and monitor delivery failures and dropped events.

## Scope

Applies to all production Kubernetes clusters, including managed services exposing customer-configurable audit export settings. Covers kube-apiserver audit log path, rotation settings, webhook export configuration, and downstream durable ingestion.

## Enforcement

- Primary Enforcement Point: API server audit backend configuration and downstream durable ingestion path.
- Implementation Surface: API server manifest or managed-service audit export settings, audit file persistence and rotation, webhook delivery settings, and downstream ingestion, retention, and retrieval checks.
- Owner Primary: Security Engineering
- Owner Supporting: Platform Engineering; Compliance
