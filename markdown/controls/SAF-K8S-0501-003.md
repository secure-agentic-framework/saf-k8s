# SAF-K8S-0501-003 - Workload egress controls

- Domain: D05 - Network Security and Communication
- Knowledge Area: 5.1 - Network Policies
- Maturity: Foundational
- Classification: baseline

## Statement

Each workload must have egress NetworkPolicy rules that restrict outbound traffic to only the required external endpoints, and DNS-based egress policies must be used where FQDN-level control is needed to limit access to approved external services.

## Objective

Limit outbound network access from workloads to only explicitly authorized destinations, preventing data exfiltration and command-and-control communication.

## Rationale

Unrestricted egress allows compromised workloads to exfiltrate sensitive data, download additional payloads, or establish reverse shells to attacker-controlled infrastructure. Without workload-specific egress rules, network-based data loss prevention is ineffective and post-compromise containment depends entirely on higher-layer controls.

## Scope

Applies to all workloads in production clusters. Workloads requiring internet access must have egress rules limited to specific IP ranges or FQDNs. DNS-based egress policies apply where the CNI supports FQDN-based filtering (e.g., Cilium, Calico Enterprise).

## Enforcement

- Primary Enforcement Point: Kubernetes NetworkPolicy egress rules and CNI-specific DNS-aware egress policies, enforced at the pod network interface.
- Implementation Surface: Kubernetes NetworkPolicy egress rules (IP/port-based), CNI-specific FQDN-based egress policies (Cilium CiliumNetworkPolicy toFQDNs, Calico Enterprise destination.domains), Cilium Hubble flow logging for observe-first rollout, Calico flow logs, egress proxy configurations, and cloud metadata service (169.254.169.254) access restrictions tied to workload identity federation.
- Owner Primary: Network Engineering
- Owner Supporting: Application Development; Security Engineering
