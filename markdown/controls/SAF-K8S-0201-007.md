# SAF-K8S-0201-007 - Node eviction threshold tuning for workload pressure

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.1 - Kubelet and Node Configuration Hardening
- Maturity: Foundational
- Classification: baseline

## Statement

Select, apply and review effective kubelet hard eviction thresholds and shared node resource reservations for each applicable node pool. Use workload headroom and signal availability to reduce pressure-related disruption to the kubelet, runtime and OS.

## Objective

Support node responsiveness and workload recovery under pressure using applicable memory, filesystem space, inode and PID signals. A kubelet hard eviction of a selected Pod does not honor Pod termination grace or a PodDisruptionBudget.

## Rationale

Eviction thresholds and reservations can reduce pressure-related failures. Rapid memory changes can outrun kubelet observation and the kernel can invoke its OOM killer first. Filesystem and PID signal applicability depends on the node's effective configuration and platform.

## Scope

Applies to governed Kubernetes node pools, according to their reachable signals, reservations, runtime, filesystem layout and workload recovery requirements. Record service and pool-specific evidence for provider-operated settings and approved exceptions for unavailable coverage.

## Enforcement

- Primary Enforcement Point: Node provisioning templates and kubelet configuration files specifying evictionHard and related reclaim thresholds.
- Implementation Surface: Inventory the full effective evictionHard map and mergeDefaultEvictionSettings per pool. Inspect allocatable capacity, reserved resources, applicable pressure signals and alert ownership. Rehearse workload interruption and recovery, and review operational thresholds after relevant platform or workload changes.
- Owner Primary: Platform Engineering
- Owner Supporting: Workload Teams; Capacity Planning
