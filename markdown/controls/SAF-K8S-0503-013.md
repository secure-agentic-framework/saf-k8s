# SAF-K8S-0503-013 - Ingress web application firewall integration and request filtering

- Domain: D05 - Network Security and Communication
- Knowledge Area: 5.3 - Ingress, Egress, and DNS Hardening
- Maturity: Practitioner
- Classification: baseline

## Statement

Ingress controllers protecting internet-facing services must integrate with a web application firewall that applies request filtering rules appropriate to the exposed application risk.

## Objective

Reduce exploit delivery and malicious request exposure at the ingress layer by filtering abusive or malformed traffic before it reaches backend services.

## Rationale

TLS alone does not stop injection payloads, malformed requests, or exploit probes. Separating WAF integration from rate limiting makes request filtering and abuse throttling independently auditable.

## Scope

Applies to internet-facing ingress and internal routes whose risk requires application-layer request filtering. Covers WAF attachment, managed and custom request-filtering rules, request inspection boundaries, and evidence of configured actions. Evaluate ingress throttling under SAF-K8S-0503-014.

## Enforcement

- Primary Enforcement Point: Ingress request filtering controls.
- Implementation Surface: Record the installed WAF, attached managed rule versions, custom rules, inspected request components, exceptions and blocking mode. Verify a harmless policy canary and permitted traffic at the actual ingress path and retain WAF decisions and backend observations.
- Owner Primary: Network Engineering
- Owner Supporting: Application Security; Platform Engineering

### NIST-800-53R5 SI-10(6)

- Framework: NIST SP 800-53 Revision 5 5.2.0
- Requirement Title: Injection Prevention
- Relation Type: supports
- Strength: moderate
- Applicability: conditional
- Strength Reason Code: partial-control-coverage
- Applicability Condition: Applies when the deployed WAF is configured to inspect organization-defined SI-10 information inputs and block relevant untrusted data injections. WAF filtering is a supporting boundary control; application-level validation and injection prevention must be evidenced separately.

#### Framework Mapping Notes

A deployed WAF can provide supporting prevention for untrusted data injections in the organization-defined information inputs when its active rules inspect and block the relevant input. This control's harmless fixed-header marker demonstrates route attachment and a configured WAF decision only; it does not demonstrate application input validation, parameterized interfaces, output escaping, or prevention of prompt or command injection.
