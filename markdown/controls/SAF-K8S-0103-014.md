# SAF-K8S-0103-014 - Scheduler operational endpoint and placement authorization

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.3 - Controller-Manager, Scheduler, and Cloud Controller Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Production Kubernetes clusters must restrict kube-scheduler operational HTTPS endpoints to approved control-plane and monitoring paths. Restrict direct Pod binding through the Kubernetes API to authorized scheduling or explicitly approved operational identities, and govern workload fields that can influence placement.

## Objective

Protect scheduler operational interfaces and prevent unapproved direct Pod binding or placement overrides through Kubernetes API authorization and admission.

## Rationale

The scheduler determines where workloads run, making it a high-value target for attackers seeking to place pods on compromised nodes, co-locate with sensitive workloads, or bypass security-aware placement controls. The kube-scheduler HTTPS listener serves operational routes. The scheduler watches workloads and persists placement through the Kubernetes API. Controlling access to the HTTPS listener and authorizing Pod binding are separate safeguards. Direct placement fields such as spec.nodeName require their own admission policy where workload placement is sensitive.

## Scope

Applies to all production clusters. Covers scheduler secure serving, authorization for Kubernetes binding resources, and workload placement policy for the default and approved custom schedulers. For managed Kubernetes services, applies to customer-visible scheduler-access settings and compensating controls where scheduler internals are provider-managed.

## Enforcement

- Primary Enforcement Point: Scheduler secure serving and Kubernetes API authorization
- Implementation Surface: Review effective bind address, secure endpoint paths and approved monitoring access. Verify native Kubernetes RBAC for pods/binding and applicable binding resources. Validate admission policy for direct node assignment and approved scheduler selection when relevant, and verify a permitted workload still schedules.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Application Platform teams
