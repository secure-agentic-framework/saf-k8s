# SAF-K8S-0703-021 - GPU admission enforcement against unauthorized access and quota bypass

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.3 - Resource Governance and Priority
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Define the approved accelerator resource request and authorized workload or namespace policy for every governed GPU deployment. Enforce the selected Pod admission requirements and accelerator quota, and verify scheduling and device isolation under the deployed resource model.

## Objective

Admit governed workloads through the approved accelerator request path and keep their admitted usage within the defined namespace limits.

## Rationale

Identity and admission policies can require approved resource declarations before execution. Kubernetes quota accounts for namespaced requests and is independent of node capacity. Actual accelerator assignment and isolation depend on the deployed device plugin or DRA driver and workload boundaries.

## Scope

Applies to GPU-capable environments selected by the platform owner. Inventory resource types, drivers, workload submission paths, namespaces and applicable quotas and isolation policies.

## Enforcement

- Primary Enforcement Point: Kubernetes authorization, Pod and workload admission, ResourceQuota, and the deployed device allocation and isolation boundary.
- Implementation Surface: Require the selected resource declaration and workload authorization. Apply supported namespaced accelerator limits using the installed resource model. Verify ordinary denials and approved scheduling separately, and check the effective workload security policy, permitted controller identities and runtime device assignment in the actual environment.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; ML Engineering
