# SAF-K8S-0802-008 - GPU kernel module signing and Secure Boot enforcement

- Domain: D08 - GPU, Accelerator, and Confidential Computing
- Knowledge Area: 8.2 - GPU Driver, Library, and Toolkit Security
- Maturity: Advanced
- Classification: ai-specific

## Statement

Enforce an approved module and signer policy on governed Linux accelerator nodes. Verify effective kernel module signature enforcement and separately verify the required Secure Boot or measured-boot policy. Record effective loaded modules and investigate rejected or unexpected loads.

## Objective

Prevent unapproved modules from loading under the effective host policy and retain independently scoped kernel and boot evidence.

## Rationale

Boot-chain verification, signature presence, kernel key trust and running-kernel enforcement represent different boundaries. A scheduling label or signed file alone does not establish effective host loading policy.

## Scope

Applies to governed Linux accelerator nodes and their supported kernel, driver package and module versions. Identify trusted and revoked keys, required boot state, validated host evidence and relevant distribution differences.

## Enforcement

- Primary Enforcement Point: Running-kernel module verification and trusted key policy, with separate boot and workload controls.
- Implementation Surface: Document supported platform versions and module identities. Verify effective enforcement and trusted keyrings, signed-module provenance and actual loaded modules. Separately verify required Secure Boot and attestation evidence freshness and binding. Collect load decisions and confirm deployment restrictions against approved host evidence.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; GPU Infrastructure Engineering
