# SAF-K8S-0403-011 - Secrets KMS key rotation and re-encryption verification

- Domain: D04 - Identity, Access, and Secrets Management
- Knowledge Area: 4.3 - Secrets Management
- Maturity: Foundational
- Classification: baseline

## Statement

Kubernetes Secrets encryption keys must rotate on a defined schedule, and periodic re-encryption verification must confirm that no Secrets remain encrypted under retired keys.

## Objective

Ensure long-lived KMS keys protecting Kubernetes Secrets are rotated and that existing Secrets are re-encrypted so retired key material does not remain in use.

## Rationale

Changing the write key protects new writes while existing Secret records can still use an earlier key. Rewriting and independently verifying those records establishes current-key coverage before key retirement.

## Scope

Applies to all production Kubernetes clusters using KMS-backed Secrets encryption. Covers automated key rotation schedules, retired-key re-encryption checks, and verification that existing Secrets are protected under current keys.

## Enforcement

- Primary Enforcement Point: KMS rotation automation and re-encryption verification.
- Implementation Surface: Automated KMS rotation schedules and key-version audit evidence, with old-key decryption available until full current-key coverage is verified and backup recovery is accounted for. After confirming that new writes use the active key, Kubernetes v1.37 clusters serving storagemigration.k8s.io/v1 can run a StorageVersionMigration for the core secrets resource and verify Succeeded. Use an equivalent rewrite procedure where this API is unavailable. Independently check the stored key version for the complete in-scope inventory before retirement. Migration success records completion of the rewrite and requires separate key-version evidence.
