# SAF-K8S-0704-019 - Per-workload cloud identity binding for managed Kubernetes workloads

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.4 - Cloud Provider Security Integration
- Maturity: Foundational
- Classification: baseline

## Statement

Use an approved provider-specific workload identity mechanism for each workload or group with the same authorization needs. Bind its intended Kubernetes ServiceAccount or supported subject to only the required cloud resources and actions, and verify actual use and attribution.

## Objective

Give workloads narrowly scoped cloud access through a governed and traceable identity without relying on shared node credentials.

## Rationale

Provider integrations can assign grants at Kubernetes ServiceAccount or other subject boundaries. Replicas may share authorization by design. Confirm subject scope, cloud authorization, observed attribution granularity and separate node credential protections.

## Scope

Applies to governed managed Kubernetes workloads needing cloud API access. Cover the provider-specific federation or association, subject and resource scopes, approved shared identities, alternate credential sources and observable audit attribution.

## Enforcement

- Primary Enforcement Point: Provider workload identity trust and authorization, and Kubernetes workload admission and subject selection as applicable.
- Implementation Surface: Inventory workload subjects and approved cloud actions. Verify the deployed provider trust or association and the Kubernetes subject and projection settings appropriate to that integration. Test allowed and denied scoped cloud actions and verify audit attribution and node credential boundaries independently.
- Owner Primary: Cloud Platform Engineering
- Owner Supporting: Platform Engineering; Security Engineering
