# SAF-K8S-0203-014 - Verify provider-specific cloud metadata access modes

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.3 - Host OS and Kernel Hardening
- Maturity: Foundational
- Classification: baseline

## Statement

For each governed cloud node pool, identify the provider metadata access mechanism and require the strongest approved supported mode for required paths. On eligible EC2 nodes with metadata enabled, require IMDSv2 session tokens. Apply and document provider-specific access controls, compensating protections and exceptions.

## Objective

Remove approved-scope legacy or insecure metadata modes and verify effective provider-specific access requirements.

## Rationale

An EC2 session-token requirement, a fixed request-intent header, a client-authenticated channel and endpoint disablement enforce different properties. An Azure or Google HTTP request header does not prove client identity. Metadata protocol mode and exposure are assessed separately.

## Scope

Applies to governed cloud node instances and managed pools with provider metadata services. Inventory product, version and support, applicable modes, ownership and exceptions, approved node or workload dependencies, and effective configuration.

## Enforcement

- Primary Enforcement Point: Effective provider instance or node-pool settings and independently verified service behavior at each applicable access boundary.
- Implementation Surface: Check applied provider instance or node-pool settings and provider-owned evidence. Exercise version-specific approved and refused harmless requests where authorized and record exceptions. Retain separate evidence for endpoint disablement, routing, workload identity and node functionality.
- Owner Primary: Cloud Infrastructure
- Owner Supporting: Platform Engineering; Security Engineering
