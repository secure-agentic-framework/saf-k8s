# SAF-K8S-0902-003 - Inference request validation and input sanitization

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.2 - Inference Server and Model Serving Security
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Enforce the agreed request schema, content type and input-size limits on each supported inference route before dispatch. Define model-specific preprocessing, sanitization and input safety decisions separately where the application risk assessment requires them. Verify which deployed layer makes each decision.

## Objective

Limit invalid or excessive inference input and establish the expected request validation behavior before model execution on each governed route.

## Rationale

A gateway or serving process can enforce a specified wire format and size boundary. Model-specific preprocessing and semantic safety require their own validation, and different routes can have different limits and enforcement components.

## Scope

Applies to adopted inference request paths, including HTTP, gRPC, batch and streaming where deployed. Verify the actual gateway and inference boundaries and separately validate the model-specific input handling. Model robustness and response filtering are covered separately.

## Enforcement

- Primary Enforcement Point: Effective request validation at the gateway and inference endpoint for each supported protocol, with separate application preprocessing and input safety where required.
- Implementation Surface: Specify and test actual schemas, request formats, limits, authorized routes, bounded streaming or batch handling, and observable refusal before model dispatch. Verify independent application preprocessing and any semantic input detection through their applicable validation process.
- Owner Primary: ML Platform Engineering
- Owner Supporting: Security Engineering; Application Security
