# SAF-K8S-0504-007 - SPIFFE trust domain scoping and cross-cluster federation governance

- Domain: D05 - Network Security and Communication
- Knowledge Area: 5.4 - Zero Trust Architecture and Service Mesh
- Maturity: Advanced
- Classification: baseline

## Statement

Govern SPIFFE trust domains as security and administrative boundaries. Configure explicit federation when eligible workloads authenticate across different trust domains. Keep the approved bundle bound to its issuing domain and authorize the intended peer identity separately.

## Objective

Authenticate approved foreign trust domains and authorize the intended identities across those boundaries.

## Rationale

Kubernetes cluster boundaries and SPIFFE trust domains can differ. Bind each foreign bundle to the intended issuing domain so it can validate only the corresponding credentials. Authentication of a foreign credential enables a separate authorization decision for that identity.

## Scope

Applies wherever Kubernetes workloads authenticate across distinct SPIFFE trust domains, including deployments within one Kubernetes cluster or across several. Workloads that already share the same SPIFFE trust domain use that domain's trust. Verify organizational domain boundaries and the relying party's policy.

## Enforcement

- Primary Enforcement Point: Trust domain and federation boundary governance.
- Implementation Surface: Document trust domains, authenticated federation endpoints, expected endpoint identity, bundle refresh and failure handling. Preserve the trust-domain-to-bundle association and verify relying-party authorization using complete peer SPIFFE IDs. Test accepted and rejected peer identities.
- Owner Primary: Security Engineering
- Owner Supporting: Platform Engineering; Network Engineering
