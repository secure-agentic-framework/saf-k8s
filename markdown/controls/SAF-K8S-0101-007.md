# SAF-K8S-0101-007 - API server request concurrency and API Priority and Fairness

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.1 - Kubernetes API Server Security
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Configure API Priority and Fairness to classify Kubernetes API requests, allocate concurrency by priority, and handle requests over the applicable concurrency limit by queueing or rejecting them. Verify critical management flows, select appropriate flow distinguishers and inspect representative demand. With APF enabled, verify the sum of both API server in-flight concurrency settings. Where APF is disabled, verify the separate mutating and non-mutating concurrency limits.

## Objective

Preserve API responsiveness for critical management traffic by allocating concurrency and observing queueing and rejection for governed request classes.

## Rationale

AI/ML workloads frequently generate high API server load through large-scale job submissions, frequent status updates from distributed training coordinators, and batch pod creation. Without rate limiting and prioritization, these bursts can starve critical control-plane operations (leader election, node heartbeat processing), leading to cascading failures. API Priority and Fairness classifies requests into priority levels and applies fair queuing or rejection within the configured concurrency budget. Review priority shares, borrowing and queue behavior, including independently verified production capacity.

## Scope

Applies to all production Kubernetes clusters, especially those running large-scale AI/ML workloads. Covers APF FlowSchema and PriorityLevelConfiguration resources, as well as legacy rate limit flags. For managed Kubernetes services, verify provider APF defaults and configure customer-accessible flow schemas.

## Enforcement

- Primary Enforcement Point: API Server Configuration
- Implementation Surface: Verify flowcontrol.apiserver.k8s.io/v1 FlowSchemas and PriorityLevelConfigurations, nominal shares and borrowing/lending bounds, queue or reject behavior, and per-API-server effective flags. Observe classification, queue depth, wait and rejection by applicable priority. Identify exempt or long-running requests and managed-provider settings separately.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; AI/ML Engineering
