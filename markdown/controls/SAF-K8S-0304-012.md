# SAF-K8S-0304-012 - Training scratch volume size limits and ephemeral-storage quotas

- Domain: D03 - Workload and Pod Security
- Knowledge Area: 3.4 - Secure Defaults and Resource Constraints
- Maturity: Foundational
- Classification: baseline

## Statement

AI training workloads using disk-backed emptyDir scratch volumes must declare sizeLimit constraints and ephemeral-storage requests and limits. Training namespaces must enforce ephemeral-storage ResourceQuota or an equivalent admission policy. Node operators must monitor storage capacity and ensure kubelet measures local ephemeral storage on the deployed filesystem layout.

## Objective

Reduce the risk of node disk exhaustion and runaway training jobs through admission limits, kubelet usage enforcement, and capacity monitoring.

## Rationale

Training jobs can rapidly consume local disk. ResourceQuota caps declared aggregate ephemeral-storage requests and limits at admission. On supported filesystem layouts, kubelet evicts a Pod after detecting that disk-backed emptyDir usage exceeds its sizeLimit. Writes can exceed the limit before eviction.

## Scope

Applies to AI and ML training workloads that use emptyDir or equivalent ephemeral scratch space for staging data, caches, gradients, or intermediate outputs.

## Enforcement

- Primary Enforcement Point: Pod specification validation, namespace ResourceQuota admission, kubelet local storage measurement and eviction, and node capacity monitoring.
- Implementation Surface: Require disk-backed emptyDir sizeLimit and per-container ephemeral-storage declarations. Apply namespace quotas to declared requests and limits. Verify node filesystem accounting and observe the expected volume-specific eviction using a bounded test. Use separate memory accounting or storage-provider evidence for alternative scratch volumes.
- Owner Primary: AI/ML Platform team
- Owner Supporting: Platform Engineering; Security Engineering
