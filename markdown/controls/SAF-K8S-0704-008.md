# SAF-K8S-0704-008 - Cloud-to-Kubernetes event correlation for incident investigation

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.4 - Cloud Provider Security Integration
- Maturity: Practitioner
- Classification: baseline

## Statement

Maintain correlation logic for selected cloud and Kubernetes events using validated source coverage, bounded timestamps and effective identity and resource mappings. Record exact links, ambiguous and unmatched candidates separately. Confirm cause or workload effect with additional evidence where required.

## Objective

Support investigations with traceable cross-source event relationships and explicit confidence and coverage boundaries.

## Rationale

Provider activity records and Kubernetes audit events have distinct scopes, identities, time semantics and identifiers. Adjacent timestamps can suggest a candidate relationship. Reliable linkage requires documented keys and context, and observed correlation alone cannot establish causation.

## Scope

Applies to governed managed Kubernetes environments and selected incident scenarios. Inventory supported provider streams, Kubernetes audit scope, time windows, identity mapping and gaps for relevant identity, infrastructure and workload events.

## Enforcement

- Primary Enforcement Point: Audit source enrollment, validated identity and resource mappings, correlation rules and investigator adjudication.
- Implementation Surface: Retain source event IDs, source and effective identity evidence, timestamps and record lineage. Verify explicit correlation keys per integration and test matched, unmatched, stale and ambiguous candidates. Correlate workload impact with independently observed evidence and retain uncertainty and investigative disposition.
- Owner Primary: Security Engineering
- Owner Supporting: Cloud Platform Engineering; Platform Engineering; SOC
