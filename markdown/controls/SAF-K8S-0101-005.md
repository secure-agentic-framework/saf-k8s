# SAF-K8S-0101-005 - Streaming connection idle timeout enforcement

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.1 - Kubernetes API Server Security
- Maturity: Foundational
- Classification: baseline

## Statement

Production Kubernetes clusters must define a maximum application-idle period for enabled Pod exec, attach, and port-forward sessions. Enforce and verify the limit for each deployed stream path and protocol at the runtime, provider, or controlled access intermediary. Where a path lacks verified timeout enforcement, remove routine access to that path. Any emergency access exception must be approved, time-bound, and logged.

## Objective

Limit the window during which abandoned or forgotten interactive sessions remain open to the cluster, reducing the risk of session hijacking, credential reuse, and unmonitored privileged access through stale exec or port-forward tunnels.

## Rationale

Interactive streams can remain connected after use stops. A shorter verified idle period reduces the time an abandoned stream stays available. The enforcement component and observed behavior can differ across operations and protocols. On Kubernetes 1.36.1 with containerd 2.3.1, the CRI stream_idle_timeout repeatedly closed idle port-forward data streams in the reference tests. Idle attach closure varied between runs, and idle exec stayed open beyond the test window. The reference restricts routine attach and exec through authorization.

## Scope

Applies to all production Kubernetes clusters and to each enabled Pod exec, attach, or port-forward path. For managed Kubernetes, verify provider timeout behavior or enforce the same access restriction where evidence is unavailable.

## Enforcement

- Primary Enforcement Point: The component enforcing the specific stream limit and Kubernetes authorization for paths with unverified enforcement.
- Implementation Surface: Effective runtime, provider, or intermediary timeout configuration, paired healthy and idle session tests for each path, and authorization evidence for restricted paths and any approved emergency access.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering
