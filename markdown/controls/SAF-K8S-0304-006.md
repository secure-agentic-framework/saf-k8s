# SAF-K8S-0304-006 - Host volume mount restriction

- Domain: D03 - Workload and Pod Security
- Knowledge Area: 3.4 - Secure Defaults and Resource Constraints
- Maturity: Foundational
- Classification: baseline

## Statement

Host volume mounts (hostPath) must be denied by default through admission control, with exemptions only for documented infrastructure workloads (log collectors, monitoring agents) that have compensating controls and are tracked in the exemption register.

## Objective

Restrict direct node-filesystem access from Pods to approved infrastructure workloads.

## Rationale

A hostPath volume exposes a node filesystem path to a workload under the effective mount settings. This changes the filesystem trust boundary. Deny it by default and constrain any approved exception by workload, identity, path and access mode.

## Scope

Applies to all pods in production clusters. Infrastructure workloads that legitimately require host filesystem access (log collectors, node monitoring agents) must be isolated in dedicated namespaces with formal exemptions and compensating controls documented in the exemption register (SAF-K8S-0301-005).

## Enforcement

- Primary Enforcement Point: Use Pod Security Admission Baseline or Restricted, or equivalent admission policy, for default denial. Use separate narrowly scoped admission controls where an infrastructure exception is approved.
- Implementation Surface: Record the exact approved requester, workload, namespace, path, mount mode, owner and expiry. Check the effective exception gate, compensating controls and audit evidence, and remove expired approvals through the approved governance mechanism. Keep permitted path testing confined to an authorized representative fixture.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering
