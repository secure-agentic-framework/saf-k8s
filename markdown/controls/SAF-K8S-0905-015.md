# SAF-K8S-0905-015 - AI system control profile enforcement

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.5 - AI Supply Chain and Model Lifecycle
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Apply the approved lifecycle profile to each governed AI workload. Verify the exact deployment signature and integrity-monitoring configuration for a train-verify-lock profile. Require authorized update workflows and observed drift monitoring for continuous-learning profiles. Verify the applicable admission, update and runtime paths.

## Objective

Ensure security controls are calibrated to each AI system lifecycle classification, with static systems receiving integrity-focused controls and continuously learning systems receiving update authorization and drift monitoring requirements on Kubernetes.

## Rationale

Applying the wrong control profile leaves critical risks unaddressed: train-verify-lock systems without integrity verification lack tamper detection, while continuous learning systems without update authorization lack governance over model evolution. Classification from SAF-K8S-0905-001 is prerequisite to this enforcement step.

## Scope

Applies to all AI systems after lifecycle classification (SAF-K8S-0905-001). Covers the runtime enforcement of the control profile appropriate to each classification. Excludes the classification decision itself.

## Enforcement

- Primary Enforcement Point: Governed workload admission and deployment verification, applicable update authorization, and independent runtime integrity and drift monitoring.
- Implementation Surface: Verify trusted classification and profile admission, exact signed artifact identity at deployment, actual runtime monitor coverage and response, and authenticated continuous-learning update authority. Bind the authorized update to the actual artifact and audit record.
- Owner Primary: ML Platform Engineering
- Owner Supporting: Security Engineering; ML Engineering; Governance
