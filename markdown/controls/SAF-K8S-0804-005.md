# SAF-K8S-0804-005 - Attestation-conditioned enclave key release

- Domain: D08 - GPU, Accelerator, and Confidential Computing
- Knowledge Area: 8.4 - Confidential Computing for AI Workloads
- Maturity: Advanced
- Classification: ai-specific

## Statement

Release governed decryption keys or authorized equivalent resource access only when the configured verifier and relying-party policy confirm fresh, approved evidence for the intended workload, recipient and resource. Deny untrusted, mismatched or expired evidence and retain attributable release decisions.

## Objective

Restrict sensitive key or resource access to the approved attestation-bound recipient and current authorized purpose.

## Rationale

Hardware evidence, verifier appraisal, protected resource authorization and recipient binding can be handled by separate components. Provider implementations differ. Workload identity, placement and an available broker do not by themselves establish a valid release decision.

## Scope

Applies to governed confidential workloads using attestation-conditioned model or data access. Document actual trust roots, verifier and relying-party policy, supported recipient protections, evidence freshness, key custody, audit and revocation behavior.

## Enforcement

- Primary Enforcement Point: Effective verifier and configured resource release authority, with scoped recipient binding and decision audit.
- Implementation Surface: Verify supported evidence and caller bindings, recipient-specific protection and resource authorization. Exercise denial for invalid, stale and mismatched evidence, and verify authorized release and future requests following revocation. Document withdrawal limits for already released material and keep sensitive values out of logs.
- Owner Primary: Security Engineering
- Owner Supporting: Key Management; ML Platform Engineering; GPU Infrastructure Engineering
