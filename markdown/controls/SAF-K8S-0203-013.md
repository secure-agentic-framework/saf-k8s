# SAF-K8S-0203-013 - Kernel lockdown mode enforcement for runtime integrity

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.3 - Host OS and Kernel Hardening
- Maturity: Foundational
- Classification: baseline

## Statement

Require the approved Linux kernel lockdown mode on applicable governed node images and pools. Verify the reported effective mode, image identity and kernel support. Track provider obligations and approved exceptions for unsupported or unobservable nodes.

## Objective

Reduce opportunities for post-boot kernel modification through a supported and verified Linux lockdown policy.

## Rationale

Lockdown is a Linux Security Module with distinct supported modes and version-specific restrictions. Secure Boot status and boot arguments are inputs and do not independently prove the effective lockdown mode. Signer and module-name policies have separate enforcement boundaries.

## Scope

Applies to supported governed production Linux node images and pools. Document the approved integrity or confidentiality mode, compatible required operations, provider-owned assurance, and time-bounded exceptions.

## Enforcement

- Primary Enforcement Point: Effective running-kernel lockdown mode, supported boot configuration, and separately governed module or signer policy.
- Implementation Surface: Record the approved mode and observe the effective running state through securityfs or provider-supported evidence. Retain kernel and image identity, check required functions and applicable privileges, and review expected limitations and exception handling.
- Owner Primary: OS/Infrastructure
- Owner Supporting: Platform Engineering; Security Engineering
