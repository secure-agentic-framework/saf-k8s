# SAF-K8S-0907-002 - Training data privacy controls

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.7 - Feature Store Security and Data Access Controls
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Classify and approve each training dataset version for its intended use before processing. Minimize direct identifiers and unnecessary fields. Restrict actual data-plane access to approved identities, and retain attributable records of dataset version, operation, decision and time.

## Objective

Limit exposure of personal and sensitive data in training and retain access evidence for investigation and oversight.

## Rationale

Labels express intended handling. Storage and application enforcement determine who can read actual records. Field minimization addresses selected exposure risks and requires separate evaluation of disclosure and re-identification risk.

## Scope

Applies to governed raw, processed and feature data used for training. Review actual authority and intended purpose, access enforcement, de-identification claims, storage and application auditing, and audit retention separately.

## Enforcement

- Primary Enforcement Point: Dataset approval and schema validation, actual storage or gateway access policy, and data-access event collection.
- Implementation Surface: Bind approval to the dataset version and use, hold unapproved inputs, enforce a reviewed field schema, restrict storage reads and record scoped data-access decisions. Verify Kubernetes API audits separately from kernel, storage and application reads.
- Owner Primary: Data Engineering
- Owner Supporting: Privacy Engineering; Security Engineering; Compliance
