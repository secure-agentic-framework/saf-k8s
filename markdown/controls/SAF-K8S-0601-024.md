# SAF-K8S-0601-024 - Kubelet authorization for cached private images

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.1 - Container Image and Registry Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Kubelets running private registry images must verify pull authorization before allowing a workload to start from a cached image. Apply AlwaysVerify with the KubeletEnsureSecretPulledImages feature enabled where supported, or demonstrate equivalent enforcement for the deployed platform.

## Objective

Preserve private image access controls when an eligible node already holds the image.

## Rationale

A previously pulled image can remain available in a node cache. When the image-pull feature is enabled, the upstream default NeverVerifyPreloadedImages exempts images placed on the node outside the kubelet pull path. AlwaysVerify applies credential verification to all cached images. An identity using previously successful pull credentials can be verified from a local record. Verify credential distribution and rotation separately under SAF-K8S-0601-022 and SAF-K8S-0601-023.

## Scope

Applies to eligible kubelets in self-managed and managed Kubernetes node pools that run workloads using private registry images. Confirm the supported Kubernetes version, effective feature state and policy for each pool, including replacement nodes.

## Enforcement

- Primary Enforcement Point: Effective kubelet image pull credential verification policy or a provider control with equivalent observable behavior.
- Implementation Surface: Version-aware kubelet configuration and node-pool inventory. Verify effective AlwaysVerify where supported. With an approved private fixture and exact digest, confirm an authorized pull and cache entry, deny a cached-only workload lacking the required pull identity, and confirm cached use with the authorized identity. Record any provider limitations and equivalent controls. Validate revocation and rotation independently.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; DevSecOps / Release Engineering
