# SAF-K8S-0601-024 - Kubelet authorization for cached private images

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.1 - Container Image and Registry Security
- Maturity: Practitioner
- Classification: baseline

## Statement

For images requiring registry credentials, kubelets must verify pull credentials before allowing a workload to start from cache. Apply AlwaysVerify with the KubeletEnsureSecretPulledImages feature enabled where supported, or demonstrate equivalent enforcement for the deployed platform.

## Objective

Preserve private image access controls when an eligible node already holds the image.

## Rationale

A previously pulled image can remain available in a node cache. The upstream default NeverVerifyPreloadedImages exempts images that kubelet classifies as preloaded, including existing cache entries when the feature is first enabled or retained pull records are lost. AlwaysVerify applies verification regardless of image origin. Kubelet can match previously successful pull credentials against its local record without contacting the registry. Registry-side revocation can therefore leave prior credentials usable for cached starts. Verify credential distribution and rotation separately under SAF-K8S-0601-022 and SAF-K8S-0601-023, and verify revocation behavior independently.

## Scope

Applies to eligible kubelets in self-managed and managed Kubernetes node pools that run workloads using private registry images. Confirm the supported Kubernetes version, effective feature state and policy for each pool, including replacement nodes.

## Enforcement

- Primary Enforcement Point: Effective kubelet image pull credential verification policy or a provider control with equivalent observable behavior.
- Implementation Surface: Version-aware kubelet configuration and node-pool inventory. Verify effective AlwaysVerify where supported. With an approved private fixture and exact digest, confirm an authorized pull and cache entry, deny a cached-only workload lacking matching credentials, and confirm authorized cached reuse. Check the pull policies and preloaded image paths used by each eligible pool. Record provider limits and equivalent controls. Validate revocation and rotation independently.

- Owner Supporting: Security Engineering; DevSecOps / Release Engineering
