# SAF-K8S-0702-010 - Virtual cluster deployment for high-isolation multi-tenant Kubernetes environments

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.2 - Namespace Isolation and Multi-Tenancy
- Maturity: Advanced
- Classification: baseline

## Statement

Use a tenant-specific virtual control plane or dedicated cluster when the threat model requires stronger API separation than namespace-scoped controls provide. Restrict host access, review configured synchronization, and enforce any required runtime boundaries independently.

## Objective

Provide distinct, verified tenant API and control-plane boundaries and document the remaining shared infrastructure.

## Rationale

Kubernetes namespaces provide namespaced scope within one API and do not create separate cluster-scoped object stores. Virtual control planes can provide independent API state while host administrators, synchronized resources, nodes and runtime components may remain shared.

## Scope

Applies where namespace-only isolation does not meet tenant API or administrative requirements. Record tenant and host identities, worker placement, shared infrastructure, synchronized resources and independent network, storage, device and runtime requirements.

## Enforcement

- Primary Enforcement Point: Tenant control-plane provisioning, scoped credentials and host authorization, synchronization policy, and independently verified runtime controls.
- Implementation Surface: Pin the tested virtual cluster configuration and worker model. Test independent tenant API state, tenant and service identity scopes, and relevant host authorization. Inventory synced resources and host permissions. Verify required workload, network, storage and node isolation and record residual risk.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Cloud Platform Engineering
