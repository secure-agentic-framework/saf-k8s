# SAF-K8S-0606-020 - Helm values override restriction and dependency integrity governance

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.6 - CI/CD and GitOps Pipeline Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Restrict overrides of governed Helm values and validate the final merged configuration. Lock dependency resolution, separately verify each consumed dependency artifact against approved integrity and authenticity policy, and use governed sources for chart retrieval.

## Objective

Keep the rendered values and the exact dependency packages within the approved release policy.

## Rationale

Helm accepts values from multiple precedence layers. Validating merged values or rendered resources can enforce a policy at the deployed boundary. Chart.lock records resolution metadata and a consistency digest. Verify retrieved chart package bytes separately using approved digest or signature evidence appropriate to the artifact and source.

## Scope

Applies to governed Helm workflows and their direct and transitive dependency trees, including internal repositories and mirrors. Assess the actual deployment and reconciliation tools and supported override paths.

## Enforcement

- Primary Enforcement Point: Helm dependency resolution and artifact verification plus values and rendered-resource policy in CI, GitOps and admission as applicable.
- Implementation Surface: Review default, file and CLI value sources, permit approved overrides and verify merged values and rendered resources on actual deployment paths. Require declared and reviewed Chart.lock resolution where used. Verify the exact consumed dependency artifacts against approved per-artifact digest or signature evidence, enforce repository policy, and retain resolved versions, sources and verification records.
- Owner Primary: DevSecOps / Release Engineering
- Owner Supporting: Platform Engineering; Security Engineering
