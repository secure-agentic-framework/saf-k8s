# SAF-K8S-0804-001 - TEE-based model and data protection for AI workloads

- Domain: D08 - GPU, Accelerator, and Confidential Computing
- Knowledge Area: 8.4 - Confidential Computing for AI Workloads
- Maturity: Advanced
- Classification: ai-specific

## Statement

Require supported confidential computing for sensitive AI workload profiles where the approved threat model requires it. Identify the protected CPU and accelerator boundaries, verify actual supported runtime and hardware state with applicable evidence, and condition sensitive use on the approved assurance decision.

## Objective

Protect governed workloads within the documented, verified CPU and accelerator confidentiality boundaries.

## Rationale

Guest-private memory, GPU confidential mode, device assignment, external I/O and workload identity are distinct properties. TEE protections depend on product, configuration and threat model. Kubernetes admission can enforce placement declarations and does not attest the resulting hardware state.

## Scope

Applies to governed inference and training profiles requiring confidential execution. Inventory CPU and accelerator SKU and mode, verified runtime and workload identity, evidence freshness, reference values, supported external paths and exceptions.

## Enforcement

- Primary Enforcement Point: Platform-specific CPU and accelerator evidence and the trusted verifier, with separately enforced placement and pre-use policy.
- Implementation Surface: Identify the intended protected memory and I/O boundaries. Verify supported hardware and software configuration, effective runtime, attestation freshness and platform and workload measurements, and gate sensitive resource use. Confirm required protections for inference and training separately and record known exclusions and compensating controls.
- Owner Primary: ML Platform Engineering
- Owner Supporting: GPU Infrastructure Engineering; Security Engineering; Compliance
