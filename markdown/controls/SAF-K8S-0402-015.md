# SAF-K8S-0402-015 - Legacy service account token secret removal

- Domain: D04 - Identity, Access, and Secrets Management
- Knowledge Area: 4.2 - Service Accounts and Workload Identity
- Maturity: Foundational
- Classification: baseline

## Statement

Kubernetes clusters must disable or remove all legacy static service account token secrets of type kubernetes.io/service-account-token.

## Objective

Eliminate persistent, non-expiring credentials by removing legacy static service account token Secrets, ensuring that stale agent identities cannot be exploited through credentials that never expire.

## Rationale

Legacy Secret-backed service account tokens lack the time and audience restrictions of projected tokens. The API server can reject invalidated legacy credentials. The built-in cleaner tracks eligible inactive auto-generated tokens. Inventory and explicitly retire remaining legacy Secrets, including manually provisioned ones. Manage identity deactivation and its other credentials separately. This control was decomposed from SAF-K8S-0402-005.

## Scope

Applies to all clusters with legacy service account token Secrets, including both auto-generated and manually provisioned objects. Inventory objects by type and account references. Use legacy token usage metrics and audit events as supplemental activity evidence. Migrate approved dependencies to time-bound issuance before retiring persistent credentials.

## Enforcement

- Primary Enforcement Point: Inventory legacy Secret types and their consumers, then retire them through documented migration and reconciliation. Use admission to prevent new legacy token Secret objects in scope.
- Implementation Surface: Metadata-only Secret type inventory, ServiceAccount reference reconciliation, configured admission controls, and migration to approved time-bound issuance. Review legacy token usage metrics and audit events separately. Verify the built-in cleaner scope for the cluster version and explicitly retire manually provisioned tokens.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Application Development
