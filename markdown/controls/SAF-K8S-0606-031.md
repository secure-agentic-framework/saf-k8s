# SAF-K8S-0606-031 - GitOps reconciliation health and integrity monitoring

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.6 - CI/CD and GitOps Pipeline Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Monitor whether GitOps controllers successfully reconcile approved Git state in production. Collect reconciliation status, retain its history, and alert on failed or stale reconciliation. Verify controller software and configuration integrity through separate evidence.

## Objective

Confirm the approved revision and the time and outcome of its reconciliation. Detect failed, stalled, or overdue reconciliation and retain independent evidence of approved controller versions and configuration.

## Rationale

A healthy running workload can persist after reconciliation starts failing. Reconciliation status and freshness expose that gap. Source approval, controller provenance, and controlled configuration changes provide separate integrity evidence.

## Scope

Applies to production Kubernetes clusters managed through GitOps. Cover enrolled applications, controller reconciliation status and freshness, monitoring delivery, and controller integrity evidence.

## Enforcement

- Primary Enforcement Point: Flux or Argo CD reconciliation status and the monitoring system that collects it.
- Implementation Surface: Collect Argo CD Application sync and health status or Flux Ready conditions and reconciled revisions. Retain samples for the approved period and validate alert delivery against defined reconciliation-age and failure thresholds. Verify controller software provenance and approved controller configuration separately.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; SRE / Operations
