# SAF-K8S-0604-001 - SBOM generation for container and AI artifacts

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.4 - SBOMs and Vulnerability Intelligence
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Generate a machine-readable SBOM from each in-scope final assembled container image before release. Use an approved format such as SPDX or CycloneDX, record the generator and scan scope, and retain the inventory bound to the exact image manifest digest. Verify required component coverage and document known discovery gaps. Maintain separately scoped inventory and provenance for non-package model, weights and data artifacts.

## Objective

Provide a digest-bound record of observed software components for vulnerability, license and supply-chain workflows. Verify mandatory components against release requirements.

## Rationale

Image catalogers identify software from supported metadata and binary formats. An automated scan can omit vendored, unregistered or unsupported dependencies. Check observed coverage against independent package and build evidence, including direct and transitive components and native libraries used by the workload.

## Scope

Applies to released or deployed container images, including AI training, inference and data pipeline images. Verify the digest and scope of a third-party SBOM or generate and label an observed inventory from the exact image. Record non-package models, weights and datasets in their applicable artifact inventories.

## Enforcement

- Primary Enforcement Point: Release pipeline after the final image is assembled and before publication. Hold release when generation, digest binding or required coverage verification fails.
- Implementation Surface: Pin the SBOM generator, output format and active catalogers. Validate machine readability, check required Python and native dependencies, and retain scan evidence with the exact image digest. Use the supported publication or OCI attachment command for the selected tool and version. Check deployed coverage for GPU libraries and vendored or wheel-bundled components separately.
- Owner Primary: DevSecOps / Release Engineering
- Owner Supporting: ML Platform Engineering; Security Engineering
