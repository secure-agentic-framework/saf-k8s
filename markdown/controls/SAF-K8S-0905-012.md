# SAF-K8S-0905-012 - Development-to-production environment separation for AI workloads

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.5 - AI Supply Chain and Model Lifecycle
- Maturity: Advanced
- Classification: ai-specific

## Statement

Organizations must enforce development-to-production environment separation for AI workloads to prevent training environment credentials (data access tokens, cloud IAM roles) from leaking to production inference, using namespace isolation, workload identity federation with environment-scoped IAM roles, and admission control.

## Objective

Prevent credential leakage across environment boundaries by enforcing strict separation between training/development and production inference environments.

## Rationale

Without environment separation, training credentials (data access tokens, cloud IAM roles) that are broader than production needs can be exploited from compromised inference pods. Training environments typically require broad data access that would be dangerous in production.

## Scope

Applies to Kubernetes namespace and RBAC configurations separating training/development from production inference environments. Covers credential separation, workload identity scoping, and admission control validating absence of cross-environment credentials. Excludes model artifact lifecycle management covered by SAF-K8S-0905-006.

## Enforcement

- Primary Enforcement Point: Kubernetes namespace and RBAC configurations enforcing environment separation and admission control validating credential scoping.
- Implementation Surface: Kubernetes namespace and RBAC configurations enforcing development/staging/production environment separation, workload identity federation with environment-scoped IAM roles, and admission control validating absence of cross-environment credentials.
- Owner Primary: Security Engineering
- Owner Supporting: ML Platform Engineering; DevOps Engineering
