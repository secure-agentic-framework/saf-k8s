# SAF-K8S-0104-023 - Stage-based approval and risk assessment for production feature gates

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.4 - CIS Benchmarks and Patch Management
- Maturity: Practitioner
- Classification: baseline

## Statement

Require stage-appropriate approval and a documented security risk assessment for alpha- or beta-stage behavior allowed in production. Cover explicit enablement and effective behavior inherited from version defaults or provider settings.

## Objective

Ensure applicable alpha- and beta-stage production behavior has an attributable risk assessment and decision for its exact component and version.

## Rationale

Feature gates change component behavior and may have different defaults, maturity and support across versions and providers. Reviewing effective state and planned changes accounts for an active feature that has no explicit enablement setting.

## Scope

Applies to all production clusters and all alpha- or beta-stage feature gates on API server, controller-manager, scheduler, kubelet, kube-proxy, and managed service surfaces where feature gate behavior can be influenced or must be tracked.

## Enforcement

- Primary Enforcement Point: Cluster change approval and security review processes governing production feature gate enablement.
- Implementation Surface: Reconcile feature-gate decisions to component identity, release, stage, scope, configured state and effective state. Review explicit changes before deployment and inherited behavior before acceptance. Document managed-service constraints and their risk disposition. Reassess on version, stage, scope or risk changes, and route expired or revoked decisions to the configuration owner.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Architecture Review
