# SAF-K8S-0604-003 - SBOM storage and distribution as OCI artifacts

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.4 - SBOMs and Vulnerability Intelligence
- Maturity: Practitioner
- Classification: baseline

## Statement

Publish and retain an approved SBOM discoverable for each governed image repository and exact manifest or index digest. Where OCI distribution is selected, bind the artifact manifest to that digest and verify discovery and byte integrity at a consumer. Document approved alternate storage or discovery paths and verify repository access and producer trust separately.

## Objective

Let authorized consumers retrieve the selected inventory for the pinned image digest and detect missing, mismatched or unapproved artifacts.

## Rationale

OCI image manifests declare a subject, and OCI Distribution provides a repository-scoped referrers query and a compatible tag schema. Association can simplify discovery. Verify the selected artifact, its subject and its content. Repository grants govern access, while producer authenticity, inventory quality and retained audit evidence require independent checks.

## Scope

Applies to governed production and staging repositories and their approved alternatives. Record the exact registry service, version or configuration, supported discovery path, client, permissions and retention. Test each deployed pairing and applicable fallback.

## Enforcement

- Primary Enforcement Point: Image release publishes and records the approved SBOM. The registry enforces repository authorization and the required consumer verifies the selected inventory.
- Implementation Surface: Pin repository and subject digest. Publish and verify OCI manifests with explicit subject, artifact type and content descriptors. Use the OCI Distribution referrers API and referrers tag schema on a 404 where applicable, including pagination for deployed consumers. Verify manifest and blob digest and size, format, and approval. Assess effective read, write and delete authorization, producer authentication and audit independently.
- Owner Primary: DevSecOps / Release Engineering
- Owner Supporting: Platform Engineering
