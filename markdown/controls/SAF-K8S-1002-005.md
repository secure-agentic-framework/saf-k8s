# SAF-K8S-1002-005 - Metric endpoint authorization and RBAC

- Domain: D10 - Observability, Incident Response, and Governance
- Knowledge Area: 10.2 - Monitoring, Metrics, and Tracing
- Maturity: Practitioner
- Classification: baseline

## Statement

Organizations must enforce authorization controls on Kubernetes metrics APIs (metrics.k8s.io, custom.metrics.k8s.io, external.metrics.k8s.io) and metric exporters, restricting read access to monitoring infrastructure service accounts and authorized platform operators.

## Objective

Ensure that authenticated principals can only access metric data appropriate to their role, preventing workload tenants and developer accounts from reading cluster-wide or cross-namespace metric data.

## Rationale

RBAC limits which Kubernetes metrics requests each authenticated identity may make. Verify the effective bindings for autoscaling controllers, operators and workloads. Configure and review the adapter query scope as well as the API request namespace. An external metrics rule can query shared series on a namespaced request. Select the required Metrics API requests in the API server audit policy and verify delivery to the configured audit backend.

## Scope

Applies to the Kubernetes metrics API aggregation layer (metrics.k8s.io, custom.metrics.k8s.io, external.metrics.k8s.io) and to Prometheus RBAC for Kubernetes service discovery.

## Enforcement

- Primary Enforcement Point: Kubernetes RBAC, including ClusterRole bindings for system:metrics-reader, custom metrics API roles, and Prometheus service account RBAC for service discovery.
- Implementation Surface: Metrics Server RBAC (review permissions contributed by the upstream system:aggregated-metrics-reader ClusterRole and scope reader bindings to approved identities), explicit least-privilege custom.metrics.k8s.io and external.metrics.k8s.io access with verified adapter namespace filters and approved shared exceptions, Prometheus discovery RBAC limited to the resource types and namespaces it needs, and an audit policy and backend covering required metrics requests.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Operations,AI/ML Engineering
