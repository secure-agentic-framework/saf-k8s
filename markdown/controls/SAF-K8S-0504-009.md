# SAF-K8S-0504-009 - API-aware request contract validation

- Domain: D05 - Network Security and Communication
- Knowledge Area: 5.4 - Zero Trust Architecture and Service Mesh
- Maturity: Practitioner
- Classification: baseline

## Statement

Service-level access control must include API-aware security policies that validate request patterns against expected service contracts so malformed or unexpected operations are rejected before reaching backend logic.

## Objective

Reject requests that violate the declared application protocol contract before they reach backend logic, while retaining permitted requests.

## Rationale

Authorized traffic can still abuse services through unexpected request shapes or unsupported operations. Separating API contract validation from L7 authorization makes request-shape enforcement independently auditable.

## Scope

Applies to in-scope service routes enforced by a standalone API gateway, mesh gateway, or dedicated protocol-aware validation component. Prioritize sensitive data, administration and cross-trust-boundary routes. Verify the inspected protocol, request parts and applicable backend paths.

## Enforcement

- Primary Enforcement Point: API-aware request validation controls.
- Implementation Surface: Configure an API gateway or dedicated validator that supports the required contract format and request parts. Record the approved schema revision, route coverage and behavior for malformed, out-of-schema and permitted requests. Method, path and header matching alone does not validate an HTTP body schema.
- Owner Primary: Security Engineering
- Owner Supporting: Network Engineering; Application Development
