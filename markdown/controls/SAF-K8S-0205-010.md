# SAF-K8S-0205-010 - Node-level firewall rule restriction for cluster communication

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.5 - kube-proxy and Node Networking Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Restrict governed Kubernetes node traffic with approved host and provider boundary controls where applicable. Define required inbound and outbound flows by endpoint role, interface, IP family, protocol and port. Verify enforcement and cluster connectivity.

## Objective

Constrain node communication to approved flows at the documented boundaries without disrupting required operations.

## Rationale

Host and provider firewall controls govern different traffic paths. The selected interface, routing, address translation and CNI determine their reach and independence from workload policy. Confirm the effective enforcement point for each traffic class.

## Scope

Applies to governed production node profiles. Assign ownership for operating-system, infrastructure and provider controls. Identify required control-plane, node and declared workload or Service paths, authorized exceptions and provider limitations.

## Enforcement

- Primary Enforcement Point: Effective host or infrastructure boundary rules on each approved node traffic path.
- Implementation Surface: Record approved firewall rules and required traffic, effective hooks and additional policy planes. Exercise allowed and denied owned paths, attribute enforcement with counters or equivalent evidence, and confirm required health and rollback behavior.
- Owner Primary: Network Engineering
- Owner Supporting: Platform Engineering; Cloud Infrastructure; Security Engineering
