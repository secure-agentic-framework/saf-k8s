# SAF-K8S-0905-045 - Sandboxed external model behavioral vetting and disposition review

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.5 - AI Supply Chain and Model Lifecycle
- Maturity: Advanced
- Classification: ai-specific

## Statement

Organizations must evaluate externally sourced models against documented intended-use and risk criteria before internal approval. Execute candidates within an isolation profile selected for the candidate, environment, and assessed threats. Record pass, fail, reject, or escalated dispositions with the evidence and decision authority for each outcome.

## Objective

Assess candidate behavior against documented intended-use criteria, protect execution with the selected isolation profile, and bind each disposition to the observed evidence. Hold candidates when coverage or results are inconclusive.

## Rationale

Static analysis and runtime evaluation provide complementary evidence. Runtime results depend on the candidate, runtime, inputs, intended use, and evaluation criteria. Document the limits of each evaluation and the risks the isolation profile addresses. Stronger runtime isolation may be needed when a candidate or execution path requires a stronger boundary.

## Scope

Applies to externally sourced model candidates before internal approval or promotion. Include candidate identity, intended use, documented evaluation criteria and data, environment isolation, decisions and evidence limits. Follow the separate controls for source allowlists and re-signing.

## Enforcement

- Primary Enforcement Point: The model intake and vetting workflow, including the evaluation environment and the independent review or promotion gate that records the candidate disposition.
- Implementation Surface: Bind each evaluation to the exact model and runtime identity, intended use, versioned criteria and test data. Select representative datasets and baselines for the adopted use and risks. Document the evaluation methods, outcomes and limitations. For execution, verify the selected runtime, resource, filesystem, credential, and network boundaries. Record the evidence supporting each pass, fail, reject, or escalated decision and the required independent review. Hold candidates with insufficient evidence and reassess after changes to the model, runtime, use, evaluation, or isolation.
