# SAF-K8S-0902-001 - Inference server hardening

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.2 - Inference Server and Model Serving Security
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Inference servers (vLLM, Triton, TGI, KServe) must run with minimal privileges, mount model artifacts as read-only volumes, restrict network access to required endpoints only, and follow a defined patching cadence for serving frameworks, CUDA runtime, and API dependencies.

## Objective

Reduce the attack surface of inference servers by enforcing least-privilege execution, immutable model storage, network segmentation, and timely vulnerability remediation.

## Rationale

Inference servers are internet-facing or internally exposed services that process untrusted input. Running with excessive privileges or writable model mounts enables post-exploitation persistence and model tampering. Unrestricted network access allows lateral movement from a compromised inference pod. Unpatched serving frameworks, CUDA runtimes, and API dependencies contain known vulnerabilities that attackers actively exploit.

## Scope

Applies to all inference server deployments on Kubernetes, including vLLM, Triton Inference Server, TGI, and KServe InferenceService resources. Covers pod security context, volume mount configuration, network policies, and vulnerability management for serving stack dependencies. Excludes training workloads.

## Enforcement

- Primary Enforcement Point: Inference server pod security context, Kubernetes NetworkPolicy resources, volume mount specifications in deployment manifests, and container image vulnerability scanning pipelines.
- Implementation Surface: Inference server pod security context (runAsNonRoot, readOnlyRootFilesystem, drop all capabilities, no privilege escalation), read-only volume mounts for model artifacts, Kubernetes NetworkPolicy restricting inference pod egress, resource limits (CPU, memory, GPU), liveness and readiness probes, container image vulnerability scanning for vLLM, Triton Inference Server, TGI, and KServe, CUDA runtime patching pipeline, and GitHub security advisory monitoring for serving frameworks.
- Owner Primary: ML Platform Engineering
- Owner Supporting: Security Engineering; Platform Engineering
