# SAF-K8S-0902-010 - Infrastructure-layer prompt injection classification and instruction boundary enforcement

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.2 - Inference Server and Model Serving Security
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Kubernetes-hosted LLM serving owners must validate the request schema and preserve the authority boundaries of application-managed instruction roles before dispatch. Derive caller privileges and permitted message roles from approved identity and policy. Define how rejected inputs are handled and verify the model-facing request for each applicable path. Where the threat model calls for prompt screening, document the selected mechanism, measured outcomes, and limitations.

## Objective

Keep input data and caller-supplied fields within their authorized roles, preserve application-managed instructions at the serving boundary, and verify the effects of any adopted screening against documented criteria.

## Rationale

The serving application controls request schemas, caller authorization, message role construction and dispatch. Those checks enforce application-level decisions independently of model behavior. Model interpretation depends on the adopted model, adapter and context. Evaluate any screening in that setting, and verify authorization of consequential actions separately.

## Scope

Applies to Kubernetes-hosted LLM request assembly, input validation and role authorization across the in-scope gateways, application services, adapters, and model-facing routes. Evaluate the behavior of the adopted model and any screening for the supported input modalities. Related retrieval and downstream action controls apply to the corresponding paths.

## Enforcement

- Primary Enforcement Point: The serving application or gateway that authenticates the caller, authorizes its role, validates the request and assembles the model-facing message envelope.
- Implementation Surface: Define caller-to-role mappings and permitted application-managed message sources. Validate the route and schema before dispatch, preserve the expected role and data boundaries through serialization, and retain minimized decision evidence. Verify both permitted requests and rejection before dispatch across each adopted path. If screening is used, document the intended disposition, availability requirements, evaluation metrics and effects on permitted requests. Reassess after identity, serving, model or adapter changes.
- Owner Primary: Security Engineering
- Owner Supporting: ML Platform Engineering; Application Security
