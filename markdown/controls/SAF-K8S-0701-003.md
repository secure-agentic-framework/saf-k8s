# SAF-K8S-0701-003 - Encryption at rest for persistent volumes

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.1 - Persistent Storage Security
- Maturity: Foundational
- Classification: baseline

## Statement

All persistent volumes must be encrypted at rest using cloud provider-managed encryption, dm-crypt/LUKS, or storage-level encryption mechanisms, with encryption keys managed through a dedicated key management service and rotated according to organizational key rotation policy.

## Objective

Protect data stored on persistent volumes from unauthorized access in the event of physical media theft, improper disk decommissioning, or unauthorized access to underlying storage infrastructure.

## Rationale

Persistent volumes can hold sensitive training data, model artifacts, inference output, and configuration. Encrypting the backing storage helps protect data if the media, snapshot, or underlying storage infrastructure is exposed. Kubernetes API data encryption covers persisted API objects. Volume data requires an encrypted storage integration or encryption performed by the application. Apply any compliance obligations according to the relevant data and standard.

## Scope

Applies to all persistent volumes across all Kubernetes clusters, regardless of data classification. Covers cloud provider-managed encryption (e.g., AWS EBS encryption, GCE PD encryption, Azure Disk encryption), node-level dm-crypt/LUKS, and storage-backend-native encryption. Exceptions for ephemeral scratch volumes must be documented with justification.

## Enforcement

- Primary Enforcement Point: Driver-supported StorageClass parameters, effective backing-volume or filesystem encryption, and admission checks that restrict PVCs to approved and verified storage classes.
- Implementation Surface: Provider or storage driver encryption settings, approved StorageClasses, block-layer dm-crypt/LUKS or storage-backend encryption, and verification of the backing volume or filesystem each Pod uses. Record the key provider, custody, rotation policy, and behavior for existing volumes, snapshots, and restored data.
- Owner Primary: Platform Engineering
- Owner Supporting: Cloud Platform Engineering; Security Engineering
