# SAF-K8S-0605-010 - AI custom resource webhook abuse resistance and resource hardening

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.5 - Admission Control
- Maturity: Practitioner
- Classification: ai-specific

## Statement

For governed AI custom-resource validating webhooks, define a serving availability objective and enforce the selected resource, timeout and failure settings. Verify Ready backends and admission behavior during ordinary replacement and recovery. Size rate and concurrency controls for measured deployment needs and document their measured scope.

## Objective

Preserve required validation during expected operational changes and bound the outcome when the admission service is unavailable.

## Rationale

Kubernetes uses webhook timeout and failure policy for call errors, while a valid explicit denial rejects the request. Resource settings and requested replicas guide operation. Observe serving endpoints and admission outcomes, and assess capacity independently for the deployed workload.

## Scope

Applies to the validating webhooks that govern scoped AI operator resources in each deployed environment. Verify the actual webhook service, operator versions and node placement.

## Enforcement

- Primary Enforcement Point: Webhook serving configuration, narrow admission registration and deployment availability controls.
- Implementation Surface: Record explicit timeout and failure policy, enforced per-container resources, effective Ready replicas and service endpoints, and ordered replacement results. Verify the required response for unavailable backends. Require separate evidence for rate and concurrency policy, production sizing and availability under each claimed load profile.
- Owner Primary: Platform Engineering
- Owner Supporting: ML Platform Engineering; Security Engineering
