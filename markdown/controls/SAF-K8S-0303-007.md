# SAF-K8S-0303-007 - AppArmor profile distribution and node readiness

- Domain: D03 - Workload and Pod Security
- Knowledge Area: 3.3 - Mandatory Access Controls
- Maturity: Practitioner
- Classification: baseline

## Statement

Verify that every node eligible for AppArmor-dependent workloads supports enforcement and has the approved revision of each required profile loaded. Gate workload placement on trusted current readiness, and define the response to missing profiles, drift and readiness loss.

## Objective

Keep AppArmor-dependent workloads on eligible nodes with current, verified profile readiness and observable enforcement.

## Rationale

Kubernetes scheduling does not inspect AppArmor profile availability. The kubelet rejects an explicitly requested Localhost profile when the requested policy is unavailable. An omitted profile can admit a workload without runtime-default AppArmor confinement on a node where AppArmor is disabled.

## Scope

Applies to eligible nodes and workload pools that require AppArmor. Determine applicability from the node kernel and runtime, the actual profile class and the workload placement rules.

## Enforcement

- Primary Enforcement Point: Trusted node provisioning and profile verification, workload placement policy, and kubelet and runtime startup checks.
- Implementation Surface: Inventory eligible nodes, bind approvals to profile identity and revision, and verify node-local loaded mode and a harmless enforcement check. Exercise absent, stale and withdrawn readiness, and review scheduled and running workloads after changes.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Application Development teams
