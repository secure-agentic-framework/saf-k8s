# SAF-K8S-0907-005 - Feature engineering privacy controls and leakage validation

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.7 - Feature Store Security and Data Access Controls
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Validate and minimize feature data before publication. Independently check for disallowed identifiers, known target derivations and features unavailable at the intended prediction time. Hold any failed candidate before downstream reads.

## Objective

Limit sensitive exposure and preserve valid training features for the applicable prediction time.

## Rationale

Direct identifiers, target-derived signals and future observations are distinct risks and need independent evidence. An output schema and cutoff can address selected failure modes. Feature lineage and point-in-time joins require separate checks.

## Scope

Applies to preprocessing and feature publication for training and batch scoring. Verify actual source clocks, label availability, joins, producer and consumer paths, and audit retention.

## Enforcement

- Primary Enforcement Point: Preprocessing and feature publication gates, downstream reads and approved dataset policy.
- Implementation Surface: Use a versioned feature schema, identifier minimization, verified availability timestamps, feature and label lineage, and point-in-time join checks. Retain sanitized records for rejected and accepted candidates.
- Owner Primary: Data Engineering
- Owner Supporting: ML Platform Engineering; Security Engineering; Privacy Engineering
