# SAF-K8S-0604-014 - Source-to-artifact integrity linkage for built images

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.4 - SBOMs and Vulnerability Intelligence
- Maturity: Practitioner
- Classification: baseline

## Statement

Record and verify a durable link between the exact deployed OCI artifact and its approved source revision, resolved dependency integrity records and applied build configuration. Capture authenticated build evidence for the exact subject and verify it at release or admission.

## Objective

Enable reviewers to trace a deployed manifest or index to the authenticated recorded inputs, invocation and build platform.

## Rationale

A source reference or image label records a claim. Verify the approved source snapshot, consumed lock and configuration and exact output with authenticated provenance and a trusted builder. Independently corroborate the authenticity of build claims and any reproducibility assertion.

## Scope

Applies to all CI/CD pipelines producing deployable Kubernetes artifacts, including application images, AI workload images, and infrastructure operator images.

## Enforcement

- Primary Enforcement Point: Build provenance capture, producer authentication and downstream verification of the exact OCI subject and approved input evidence.
- Implementation Surface: Record the canonical source repository and immutable revision or archive hash, expected dependency and configuration digests, applied build parameters and identity. Verify the provenance signature and subject, enforce matching expectations, and retain the immutable evidence across promotion and rollout. Verify reproducibility independently by comparing rebuilt outputs.
- Owner Primary: DevSecOps / Release Engineering
- Owner Supporting: Security Engineering; Platform Engineering
