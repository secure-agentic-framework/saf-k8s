# SAF-K8S-0203-002 - Kernel parameter hardening via sysctl

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.3 - Host OS and Kernel Hardening
- Maturity: Foundational
- Classification: baseline

## Statement

Define and enforce a versioned sysctl profile for each governed Linux node role. Record the kernel key, approved value, scope, applicability and exception for each setting. Verify the effective values after provisioning and reboot, and validate required Kubernetes network, workload and device behavior.

## Objective

Apply reviewed kernel settings to the applicable node or Pod namespace while preserving required network and workload functions.

## Rationale

Kernel versions, namespaces and node roles determine the effects of sysctl values. Review IPv4 forwarding and reverse path validation against CNI routing. SYN cookies provide a fallback on backlog overflow. ASLR, privileged-process dump restrictions and kernel-information visibility each address distinct behavior.

## Scope

Applies to applicable Linux Kubernetes node roles and supported Pod namespaces. Review role-specific CNI, asymmetric routing, RDMA and accelerator dependencies. For provider-controlled settings, retain versioned evidence for the affected node pools and approved exceptions.

## Enforcement

- Primary Enforcement Point: Node provisioning templates applying sysctl configuration via /etc/sysctl.d/ drop-in files or cloud-init scripts.
- Implementation Surface: Versioned sysctl.d provisioning, effective procfs observations after provisioning and reboot, approved Pod-safe namespaced settings, observable normal-path checks for the affected CNI and workloads, and a pool-specific exception and recovery record.
- Owner Primary: Platform Engineering
- Owner Supporting: OS/Infrastructure; Security Engineering
