# SAF-K8S-0205-008 - kube-proxy or service proxy mode selection governance

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.5 - kube-proxy and Node Networking Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Require an approved and version-specific Service proxy decision for governed node profiles. Record the effective kube-proxy backend or supported replacement, workload requirements, compatibility and operations tradeoffs, and evidence for the selected datapath.

## Objective

Keep the Service proxy choice deliberate, observable and compatible with the required Service paths.

## Rationale

Linux kube-proxy modes and supported replacements differ in prerequisites, Service semantics, observability and policy interaction. Mode availability and lifecycle vary by Kubernetes release and platform. Platform requirements and representative measurements inform the decision.

## Scope

Applies to governed Kubernetes node profiles and provider-managed replacements. Identify supported Linux and Windows modes separately. Record approval, reviewed exceptions, provider limits and triggers for reevaluation.

## Enforcement

- Primary Enforcement Point: Approved versioned decision, applied configuration, running proxy or CNI status and evidence of actual Service traffic.
- Implementation Surface: Record available backends and versions, including Linux nftables where supported. Verify configured mode, effective runtime or provider state, selected endpoint behavior, lifecycle and required traffic. Assess applicable hardening and performance with separate scoped evidence.
- Owner Primary: Platform Engineering
- Owner Supporting: Network Engineering; Security Engineering
