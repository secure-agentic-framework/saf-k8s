# SAF-K8S-0501-004 - CNI-specific network policy extensions

- Domain: D05 - Network Security and Communication
- Knowledge Area: 5.1 - Network Policies
- Maturity: Practitioner
- Classification: baseline

## Statement

Where the deployed CNI product, edition, version, and configuration support them, use its policy mechanisms for requirements beyond standard Kubernetes NetworkPolicy. Depending on the product, these mechanisms may provide application-layer rules, DNS/FQDN-based egress controls, or cluster-scoped policy. These are distinct capabilities; verify each required feature and its enforcement semantics against the deployed product documentation.

## Objective

Enforce selected network flows beyond standard Kubernetes NetworkPolicy where the deployed CNI supports the required capability, such as HTTP method/path rules, DNS-derived destination controls, or cluster-scoped policy. Verify allowed and denied paths and the interaction between overlapping policy scopes.

## Rationale

Standard Kubernetes NetworkPolicy defines namespaced ingress and egress using IP addresses, ports, and protocols. HTTP method and path rules, DNS-name rules, and cluster-scoped policy require a feature-specific extension or a compensating control. Verify the feature requirements, supported dataplane, limits, and evaluation behavior against the deployed CNI product, edition, and version.

## Scope

Applies to clusters with governance requirements beyond standard Kubernetes NetworkPolicy. Record the deployed product, edition, version, dataplane, enabled features, policy resources, and managed-service limits. For overlapping cluster-scoped, namespace-scoped, and workload-scoped policies, verify the actual order, tier, action, and deny semantics. Document and test a compensating control for each requirement the deployed CNI cannot enforce.

## Enforcement

- Primary Enforcement Point: The deployed CNI's supported policy resources and enforcement dataplane, managed through the organization's approved configuration process.
- Implementation Surface: CiliumNetworkPolicy and CiliumClusterwideNetworkPolicy provide documented L3-L7 and DNS/FQDN features in supported Cilium configurations. Calico Open Source GlobalNetworkPolicy provides cluster-scoped policy and ordered evaluation. Calico Enterprise documents domain-based egress policy and application-layer policy with edition-specific prerequisites, limits and lifecycle status. Verify each required feature and the effective policy after delivery through the approved configuration process.
- Owner Primary: Network Engineering
- Owner Supporting: Platform Engineering; Security Engineering
