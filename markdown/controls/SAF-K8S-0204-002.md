# SAF-K8S-0204-002 - Kubernetes-specific runtime detection rules

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.4 - Runtime Threat Detection
- Maturity: Practitioner
- Classification: baseline

## Statement

Maintain approved Kubernetes-aware detection rules with explicit data sources, monitored behavior and retained identity context. Exercise rule loading, expected alerts, negative cases, alert delivery and safe disablement before rollout. Authorize blocking separately.

## Objective

Produce attributable and testable detections for selected Kubernetes runtime behavior.

## Rationale

Kernel events, Kubernetes API audit events, network flow metadata and resource signals observe different behavior. A runtime action alone does not prove a particular attacker objective. Correlation, activity scope and delivery depend on the supported sources and rule configuration.

## Scope

Applies to selected governed compute classes and their detection pipelines. Inventory driver, tool and rule versions, data completeness, rule coverage, approved exceptions, retention, event loss and failure ownership.

## Enforcement

- Primary Enforcement Point: Version-controlled detection configuration and supported source ingestion, Kubernetes workload identity enrichment and monitored alert delivery.
- Implementation Surface: Map each rule to explicit observed fields, documented detection hypotheses and expected test events. Exercise harmless positive and negative fixtures, missing identity or unavailable sources, controlled rollout and alert-only behavior. Review relevant changes in platform versions and threat exposure.
- Owner Primary: Security Engineering
- Owner Supporting: Security Operations (SOC); Threat Intelligence
