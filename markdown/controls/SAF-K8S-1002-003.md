# SAF-K8S-1002-003 - AI workload telemetry integration into cluster monitoring

- Domain: D10 - Observability, Incident Response, and Governance
- Knowledge Area: 10.2 - Monitoring, Metrics, and Tracing
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Integrate the approved AI workload telemetry into the cluster monitoring stack. Collect relevant training progress, inference service and model performance signals from the actual workloads. Where in-scope NVIDIA GPUs, drivers and DCGM are supported, collect the applicable hardware metrics using DCGM Exporter. Use a validated vendor-supported source for other accelerator platforms.

## Objective

Ensure that AI-specific telemetry is available in the cluster monitoring stack for performance monitoring and anomaly detection.

## Rationale

Integrated workload and accelerator telemetry can expose GPU health issues, stalled training, elevated inference latency and changes in measured model performance. Choose fields and levels of coverage appropriate to the deployed platform and document what each signal measures.

## Scope

Applies to Kubernetes clusters hosting in-scope AI workloads. Select training, inference and model performance telemetry according to each workload. Hardware telemetry applies where an accelerator is present and its exporter, device, driver, runtime and metrics are supported.

## Enforcement

- Primary Enforcement Point: AI workload metric endpoints, accelerator exporter configuration where applicable, and governed monitoring target selection.
- Implementation Surface: For supported NVIDIA GPU deployments, configure DCGM Exporter on the applicable nodes and verify supported fields with the enrolled driver and exporter. Use required device access, scheduling tolerations and least-privilege RBAC appropriate to the selected features. Instrument training and inference endpoints with workload-appropriate signals. Use Prometheus ServiceMonitor or PodMonitor where available, or an equivalent configured monitoring integration, and independently query attributed samples.
- Owner Primary: AI/ML Engineering
- Owner Supporting: Platform Engineering; Security Operations
