# SAF-K8S-0901-003 - Checkpoint security

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.1 - Distributed Training Workload Security
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Model checkpoints and optimizer state must be stored with encryption at rest, verified for integrity before restoration, and protected by access controls that restrict read and write operations to authorized training jobs and personnel.

## Objective

Protect model checkpoints from tampering, unauthorized access, and corruption to ensure that training can resume from a known-good state and that checkpoint data containing model weights is not exfiltrated.

## Rationale

Checkpoints can contain model weights, optimizer state and other valuable training artifacts. At-rest encryption protects stored data, access control restricts reads and changes, and pre-restore integrity verification prevents the workflow from continuing with unexpected checkpoint content.

## Scope

Applies to all model checkpoint and optimizer state files written during training to persistent volumes, object storage, or network file systems on Kubernetes. Covers both scheduled checkpoints and fault-recovery checkpoints. Includes checkpoint files in all formats (PyTorch .pt, TensorFlow SavedModel, ONNX).

## Enforcement

- Primary Enforcement Point: Encryption and access policies for the selected checkpoint storage backend, deployment controls for checkpoint mounts and workload identities, and integrity verification in the restore workflow.
- Implementation Surface: Verify at-rest encryption in the effective storage backend, including provisioner-specific StorageClass parameters where applicable, object-store encryption and key policies, or authenticated application-layer encryption. Bind each checkpoint and optimizer artifact to an integrity manifest from a trusted source and verify it before loading. Enforce data-plane read and write access through the applicable storage policy, filesystem authorization and mount configuration, using scoped workload and personnel identities. Use PV and PVC access modes to express binding and mount constraints and Kubernetes RBAC to authorize Kubernetes API operations. Define checkpoint retention and recovery for the selected storage and format.
- Owner Primary: ML Platform Engineering
- Owner Supporting: Storage Engineering; Security Engineering
