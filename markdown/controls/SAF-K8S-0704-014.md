# SAF-K8S-0704-014 - Managed Kubernetes audit log retention enforcement

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.4 - Cloud Provider Security Integration
- Maturity: Practitioner
- Classification: baseline

## Statement

Retain required provider and Kubernetes audit record classes for the approved periods. Verify effective retention and retrieval separately for each destination and for any archive used to meet the requirement.

## Objective

Preserve required audit records for the approved investigation and governance periods and demonstrate authorized retrieval.

## Rationale

Record selection, route, destination retention, archival and retrieval are independent. Kubernetes local audit rotation can remove older files even when recent records remain readable. Verify that the deployed retention layer covers each required record class and that retrieval remains possible.

## Scope

Applies to governed managed Kubernetes clusters and the approved monitoring platforms and archives they use. Document required classes, effective destinations, applicable periods, retrieval mode, exceptions and ownership.

## Enforcement

- Primary Enforcement Point: Effective per-source destination and archive retention, backed by observed retrieval for required records.
- Implementation Surface: Document each required audit class and its route. Check effective destination-level retention and overriding rules, archive retention and controls, and applicable access scopes. Preserve dated source and destination evidence, including authorized query or restore of representative records near the required age. Verify local API audit file age, size and backup limits separately where applicable.
- Owner Primary: Security Engineering
- Owner Supporting: Cloud Platform Engineering; Platform Engineering; SOC
