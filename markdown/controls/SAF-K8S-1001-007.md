# SAF-K8S-1001-007 - Supplemental application-level telemetry for AI workload events

- Domain: D10 - Observability, Incident Response, and Governance
- Knowledge Area: 10.1 - Logging and Audit
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Organizations must deploy supplemental application-level or runtime telemetry to capture AI workload events not visible to the Kubernetes API server, including model loading, GPU process activity, and inference request metadata. Capture selected request content only where explicitly approved for a documented evidence need.

## Objective

Ensure that security-relevant AI workload events occurring below the API layer are captured through supplemental telemetry to support detection, investigation, and compliance requirements.

## Rationale

The Kubernetes API server audit log captures API requests but does not observe in-process runtime events such as model loading inside an inference server, GPU memory operations, or inference request content. Without supplemental telemetry for these application-level events, organizations have no visibility into unauthorized model loading, GPU process hijacking, or inference abuse patterns.

## Scope

Applies to all Kubernetes clusters hosting AI/ML workloads where application-level events are security-relevant. Covers inference serving frameworks, GPU runtime monitoring, and training job application logs. For managed Kubernetes services, this control applies to customer-deployed telemetry agents and application-level log forwarding.

## Enforcement

- Primary Enforcement Point: Supplemental telemetry pipeline configuration and application-level logging configuration for AI workload pods.
- Implementation Surface: Application-level model and inference events from serving frameworks such as Triton, vLLM, or TorchServe. Use validated runtime sources for GPU process events and exporters such as DCGM Exporter for supported GPU metrics. Standard service mesh access logs can supply request metadata. Use separately authorized instrumentation for selected payload fields when needed, and verify forwarding and retention.
- Owner Primary: AI/ML Engineering
- Owner Supporting: Security Operations; Platform Engineering
