# SAF-K8S-0604-002 - ML-BOM (ML Bill of Materials) generation

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.4 - SBOMs and Vulnerability Intelligence
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Generate and retain a machine-readable ML inventory for each governed model release. Identify the selected format and version, bind the model revision and digest, and record available dataset descriptors and software dependencies. Verify required fields, artifact bindings and recorded relationships before release.

## Objective

Link the released model to its exact bytes, declared model card, dependencies and data descriptors. Corroborate production lineage and authorization with separate evidence.

## Rationale

CycloneDX ML-BOM and SPDX AI profile provide versioned ways to represent machine-readable model information. Inventory claims about training data, infrastructure, rights or lineage require independent evidence. Dataset and model hash checks establish the identity of the measured bytes.

## Scope

Applies to governed models trained, fine-tuned or deployed to Kubernetes. Obtain and verify third-party inventory when available. Label reconstructed data and unknown fields, and document release requirements for each model profile.

## Enforcement

- Primary Enforcement Point: Model release or registry intake. Verify required inventory, schema, model revision and digest before promotion. Retain the verified record with the released model.
- Implementation Surface: Use a pinned CycloneDX ML-BOM or SPDX AI profile implementation. Validate schema and verify the exact model binding, required metadata, data identifiers and software relationships. Record source limitations. Verify training attestations, infrastructure identity, data rights and applicable governance separately against their own evidence.
- Owner Primary: ML Platform Engineering
- Owner Supporting: DevSecOps / Release Engineering; Data Governance
