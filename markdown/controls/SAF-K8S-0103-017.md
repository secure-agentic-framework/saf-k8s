# SAF-K8S-0103-017 - Controller-manager and scheduler insecure-port disablement and non-public health-metrics exposure

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.3 - Controller-Manager, Scheduler, and Cloud Controller Security
- Maturity: Foundational
- Classification: baseline

## Statement

Production Kubernetes clusters must disable legacy insecure serving on component versions that implement it and verify its absence on current versions. Keep controller-manager and scheduler health and metrics endpoints on local or approved protected paths. Remote access requires explicit authorization, network controls and authentication at the component or a trusted intermediary.

## Objective

Eliminate unauthenticated control-plane exposure by disabling insecure ports and constraining health and metrics endpoints to non-public or explicitly protected access paths.

## Rationale

Historically, controller-manager and scheduler components exposed insecure or weakly protected HTTP endpoints for health checks, metrics, and diagnostics. If these endpoints are reachable on network-accessible interfaces, attackers can harvest operational data, probe control-plane health, or exploit misconfigured monitoring paths. Disabling insecure ports and restricting health or metrics exposure reduces this risk.

## Scope

Applies to all self-managed Kubernetes clusters. Covers legacy serving on versions that support it, secure health and metrics listener configuration, and approved monitoring paths. Upstream Kubernetes v1.24 removed the legacy `--port` and `--address` flags for both components. Current verification checks live listeners and effective bind addresses. For managed Kubernetes services, this is provider-managed and should be documented in the shared responsibility model.

## Enforcement

- Primary Enforcement Point: Controller-manager and scheduler endpoint exposure hardening
- Implementation Surface: Effective component flags or configuration, including secure port and bind address, live socket inventory, and reachability from approved and disallowed networks. Verify the applicable benchmark version and check authorization exemptions on health routes separately from transport security.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering
