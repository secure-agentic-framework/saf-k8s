# SAF-K8S-0101-003 - Encryption at rest for Secrets and sensitive API resources

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.1 - Kubernetes API Server Security
- Maturity: Foundational
- Classification: baseline

## Statement

Production Kubernetes clusters must encrypt Secrets and other sensitive API resources at rest using EncryptionConfiguration with a supported encryption provider (KMS v2 preferred for new deployments), and must verify that targeted resources are stored as ciphertext in etcd.

## Objective

Protect sensitive Kubernetes API resources from exposure through direct etcd access or etcd backup compromise by ensuring resource data is encrypted at rest using organization-approved cryptographic providers.

## Rationale

Kubernetes Secrets are base64-encoded but not encrypted by default in etcd. An attacker or insider with access to etcd data, whether directly or through backups, can read all Secrets in plaintext. EncryptionConfiguration targets specific API resources for encryption before they are written to etcd. KMS v2 is preferred over KMS v1 (deprecated in Kubernetes v1.28 and disabled by default since v1.29). KMS v2 derives a fresh data encryption key per encryption from a reusable secret seed. The remote KMS protects the stored seed, which rotates when the key encryption key changes. Seed reuse reduces the need for a remote KMS call per write. This control addresses API-resource-level encryption; see SAF-K8S-0102-001 for etcd storage-layer and provider envelope encryption, and SAF-K8S-0403-011 for Secrets KMS key rotation and re-encryption verification.

## Scope

Applies to all production clusters. Covers Kubernetes Secrets at minimum; organizations should evaluate extending EncryptionConfiguration to ConfigMaps, custom resources, and other API resources that contain sensitive data, or use `*.*` to match all API groups. The wildcard `*.` matches only the core API group. Review explicit identity exceptions and verify each intended resource class. For managed Kubernetes services, applies to enabling and verifying provider-managed API-resource encryption settings.

## Enforcement

- Primary Enforcement Point: API Server Configuration
- Implementation Surface: EncryptionConfiguration applied to the API server, encryption provider selection (KMS v2 preferred), and verification that targeted data is encrypted in storage and readable through the API. When enabling encryption for an existing cluster, rewrite pre-existing targeted resources and verify their stored form.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Key Management/Cryptography
