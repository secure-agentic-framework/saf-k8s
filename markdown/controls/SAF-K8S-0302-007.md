# SAF-K8S-0302-007 - Safe fsGroup and supplementalGroups volume ownership

- Domain: D03 - Workload and Pod Security
- Knowledge Area: 3.2 - Security Contexts and Capabilities
- Maturity: Foundational
- Classification: baseline

## Statement

Pods that use fsGroup or supplementalGroups must restrict assigned groups to approved workload identities. Limit fsGroup-driven ownership or permission changes to designated workload volumes and prevent the resulting process identity from writing sensitive paths, shared platform volumes, or host-backed filesystems outside its approved storage scope. When relying on Linux emptyDir.mode on Kubernetes v1.37, confirm that the API server and applicable kubelets enable EmptyDirVolumeMode and verify the actual mounted permission bits with the workload's fsGroup.

## Objective

Prevent filesystem group ownership settings from creating cross-workload tampering paths or unintended write access to sensitive storage.

## Rationale

Both settings can affect a container process group identity. fsGroup can also affect group ownership and permissions on supported mounted volumes, either through the kubelet or through a supporting storage driver. supplementalGroups adds process group memberships. Existing filesystem permissions may grant those groups access even when ownership is unchanged. The v1.37 emptyDir mode field is alpha and disabled by default. The API server can retain the requested mode when a kubelet with the gate off uses the default mode. fsGroup can further modify the effective permission bits.

## Scope

Applies to workloads that mount persistent volumes, shared datasets, model caches, or other writable storage in production clusters.

## Enforcement

- Primary Enforcement Point: Admission policy rules and workload validation that restrict approved fsGroup and supplementalGroups use for mounted storage.
- Implementation Surface: Approved fsGroup and supplementalGroups settings, the effective process groups, volume and mount policy, storage-driver behavior, and observed permissions on approved and protected storage. For explicit emptyDir modes, verify feature gate availability per eligible node and test declared versus mounted permissions.
- Owner Primary: Application Development teams
- Owner Supporting: Platform Engineering; Security Engineering
