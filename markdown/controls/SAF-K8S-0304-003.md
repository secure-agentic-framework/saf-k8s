# SAF-K8S-0304-003 - QoS class assignment for workload stability

- Domain: D03 - Workload and Pod Security
- Knowledge Area: 3.4 - Secure Defaults and Resource Constraints
- Maturity: Foundational
- Classification: baseline

## Statement

Security-critical and stateful workloads must use Guaranteed QoS. Set equal, positive CPU and memory requests and limits for each applicable container or use equivalent Pod-level declarations where supported and enabled. Document availability implications for Burstable and BestEffort workloads and prohibit BestEffort for security-sensitive workloads.

## Objective

Provide predictable CPU and memory allocation for critical workloads and account for eviction and CPU throttling in their availability design.

## Rationale

The kubelet ranks node-pressure evictions according to the resource signal. For memory pressure it considers whether usage exceeds requests, Pod Priority, and usage relative to requests. Guaranteed Pods can still be evicted under some conditions. CPU quotas remain enforceable through throttling, so size requests and limits for the workload and monitor the observed effect.

## Scope

Applies to all workloads in production clusters. Security-critical and stateful workloads must use Guaranteed QoS. Other application workloads may use Burstable QoS with documented acceptance of eviction risk. BestEffort QoS is prohibited for any workload handling sensitive data or performing security functions.

## Enforcement

- Primary Enforcement Point: Admission and CI policy validate effective CPU and memory inputs for designated workloads. Workload checks verify the assigned QoS class.
- Implementation Surface: Validate CPU and memory requests and limits in the applicable container or Pod resource fields and confirm the admitted Pod status.qosClass. Test required policy and approved exceptions. Review kubelet pressure thresholds and resource-specific eviction metrics, Pod Priority, and CPU throttling telemetry separately.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Application Development teams
