# SAF-K8S-0502-008 - Network policy design for AI-specific traffic patterns

- Domain: D05 - Network Security and Communication
- Knowledge Area: 5.2 - CNI Plugins and Pod Networking Security
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Restrict AI workload traffic using approved training peers, destination ports, registry endpoints, and inference clients. Verify the ports actually used by the selected training transport and scope training communication to authorized job identities.

## Objective

Ensure network policies correctly handle the unique traffic patterns of distributed AI workloads without blocking legitimate communication or creating excessive lateral movement exposure between unrelated workloads.

## Rationale

Distributed training may need direct communication between workers. Measure the listening and connection ports used by the selected NCCL version and transport before writing allow rules. Registry and inference traffic need their own destination and source restrictions, with separate controls for in-transit encryption.

## Scope

Applies to Kubernetes clusters hosting AI/ML training or inference workloads. Covers NCCL inter-node training traffic, model registry egress policies, inference endpoint ingress and egress policies, and parameter server communication patterns. Excludes in-transit encryption configuration and RDMA fabric compensating controls, which remain on SAF-K8S-0502-005.

## Enforcement

- Primary Enforcement Point: NetworkPolicy data-plane enforcement for supported Pod, namespace, IP, and port selectors. Use application-aware egress controls for registry hostname allowlists.
- Implementation Surface: Restrict training and parameter-server traffic to governed job labels and reviewed destination ports. Verify range enforcement on the installed CNI when using endPort. Restrict approved registry and storage destinations using reviewed Pod or IP selectors, or a name-aware CNI or egress gateway when policy depends on hostnames. Permit inference ingress from approved gateway or load-balancer sources.
- Owner Primary: Network Engineering
- Owner Supporting: ML Platform Engineering; Security Engineering
