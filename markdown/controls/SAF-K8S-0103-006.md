# SAF-K8S-0103-006 - Profiling endpoint disablement for controller-manager and scheduler

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.3 - Controller-Manager, Scheduler, and Cloud Controller Security
- Maturity: Foundational
- Classification: baseline

## Statement

Production Kubernetes clusters must disable HTTP profiling on the kube-controller-manager and kube-scheduler. Set --profiling=false on the controller-manager. For the scheduler, set enableProfiling to false in the effective KubeSchedulerConfiguration when --config is used, or set --profiling=false when started without a configuration file. Verify that the profiling index is unavailable and authenticated health checks remain functional.

## Objective

Remove the HTTP profiling surface on the controller-manager and scheduler and complement the API-server profiling control SAF-K8S-0101-020.

## Rationale

Where enabled, profiling handlers expose internal runtime information and can trigger costly diagnostics. The scheduler command reference states that the profiling flag is ignored when a component configuration file is supplied. Other debug interfaces require separate review.

## Scope

Applies to all production Kubernetes clusters. For managed Kubernetes services, verify through provider documentation that profiling is disabled on provider-managed controller-manager and scheduler processes, or document as a provider-managed control.

## Enforcement

- Primary Enforcement Point: Effective controller-manager and scheduler configuration.
- Implementation Surface: Controller-manager flag, scheduler component configuration or applicable flag, and authenticated HTTP availability checks for profiling and health.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering
