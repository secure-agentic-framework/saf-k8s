# SAF-K8S-0703-017 - PriorityClass assignment restriction and admission enforcement

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.3 - Resource Governance and Priority
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Require an explicit approved priorityClassName for governed Pods. Enforce priority tier use through namespace and workload policy, and authorize workload submission and PriorityClass object management separately. Where rules depend on submitter identity or workload type, validate templates at their supported entry points and retain enforcement at Pod admission.

## Objective

Enforce authorized priority assignments for governed workloads and prevent unauthorized changes to the cluster priority-class inventory.

## Rationale

Built-in Priority admission resolves an existing PriorityClass and assigns a numeric priority. RBAC authorizes resource operations. An admission rule or configured priority quota can constrain Pod class references beyond name resolution.

## Scope

Applies to governed Kubernetes namespaces, direct Pod creation and controller-produced Pods that use protected or required priority tiers. Inventory authorized submitters, workload templates, class values and any default class.

## Enforcement

- Primary Enforcement Point: Namespace RBAC and ClusterRole policy for resource operations, plus explicit PriorityClass reference rules at Pod and workload-template admission.
- Implementation Surface: Restrict management of cluster-scoped PriorityClass objects to administrators and restrict workload submission by namespace. Apply a namespace-specific reference allowlist or equivalent configured controls, define the behavior for missing and default classes, and test both direct and controller-issued Pod requests. Where identity and type matter, enforce them at original workload admission and account for controller identity at Pod admission.

- Owner Supporting: ML Engineering; Security Engineering
