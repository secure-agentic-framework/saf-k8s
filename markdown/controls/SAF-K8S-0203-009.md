# SAF-K8S-0203-009 - Workload identity replacement for cloud API access

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.3 - Host OS and Kernel Hardening
- Maturity: Foundational
- Classification: baseline

## Statement

Use provider-supported workload identity with scoped temporary credentials for eligible workload cloud API operations. Verify the actual selected principal and approved permissions, and govern alternate or fallback node identity paths separately.

## Objective

Make cloud API calls attributable to approved workload-specific identities with the required scope and lifetime.

## Rationale

Supported providers use different forms of workload identity, issuance and credential mediation. A pod-facing identity binding does not remove required node identities and does not by itself establish actual provider principal selection.

## Scope

Applies to eligible governed workloads using supported cloud API identity mechanisms. Inventory workload identity bindings, active issuer, audience or association, provider principal, effective permissions, node fallback and exception ownership.

## Enforcement

- Primary Enforcement Point: Actual workload identity linkage, provider issuance and authorization, and effective workload credential sourcing.
- Implementation Surface: Exercise intended issuance, authorized calls, denied alternate subject or audience and unsupported fallbacks as applicable. Verify provider-side identity and lifetime, applicable network restrictions and role boundaries, and retain sanitized audit evidence.
- Owner Primary: Cloud Infrastructure
- Owner Supporting: Platform Engineering; Security Engineering
