# SAF-K8S-0907-004 - Feature store access boundary enforcement and serving authentication

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.7 - Feature Store Security and Data Access Controls
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Authenticate feature-serving workloads using short-lived audience-bound credentials. Authorize feature definition discovery and reads by principal, tenant, named view and definition version. Enforce separate least-privilege access policies for online and offline data paths, including direct backend access and materialization identities.

## Objective

Restrict feature definition discovery, online serving and offline historical retrieval to explicitly authorized principals and workloads.

## Rationale

Feature registries, online stores and offline engines expose different data and operations. A successful serving check establishes the behavior of that endpoint. Alternate paths and direct store permissions require their own verification.

## Scope

Applies to Kubernetes-hosted and managed feature stores and their registries, serving endpoints, historical queries, materialization jobs and backing stores. Verify each deployed provider and identity path. The runnable example exercises an owned Kubernetes gateway and synthetic backing objects.

## Enforcement

- Primary Enforcement Point: Feature registry and gateway authorization, serving workload authentication and native access policy on each backing store.
- Implementation Surface: Use audience-scoped workload identity, per-tenant and per-view policy, explicit definition versions, independent online and offline store privileges and store-side access evidence. Test both allowed and denied discovery and reads through application and direct backend paths.
- Owner Primary: Data Engineering
- Owner Supporting: ML Platform Engineering; Security Engineering; Privacy Engineering
