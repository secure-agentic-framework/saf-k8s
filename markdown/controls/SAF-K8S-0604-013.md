# SAF-K8S-0604-013 - Hermetic build execution and pinned dependency input control

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.4 - SBOMs and Vulnerability Intelligence
- Maturity: Practitioner
- Classification: baseline

## Statement

Resolve and stage approved dependency inputs before restricted build execution. Pin sources and verify each required artifact against reviewed committed integrity data. Deny uncontrolled network access for dependency-consuming steps and fail when a required artifact or its expected digest is missing or mismatched. Govern builder and other build inputs separately.

## Objective

Constrain live dependency selection and retain verifiable identity for the exact consumed inputs.

## Rationale

A restricted BuildKit RUN network applies to that instruction. Builder, frontend, base image, context and cache inputs can be resolved elsewhere. Verify the complete declared boundary before claiming hermeticity. Verify reproducibility by independently comparing named build outputs.

## Scope

Applies to all CI/CD pipelines producing deployable Kubernetes artifacts, including application images, AI workload images, and infrastructure operator images. Approved mirrors, proxies, or caches may be used when they preserve pinned dependency and integrity guarantees.

## Enforcement

- Primary Enforcement Point: Dependency resolution and integrity verification, build step network policy and complete builder input management.
- Implementation Surface: Review complete lock coverage including transitive dependencies. Stage pinned dependency artifacts and verify immutable expected digests. Test missing and altered inputs and an owned comparison for step network isolation. Verify worker egress, remotely resolved frontends, base images, contexts and caches separately, and compare output bytes if claiming reproducibility.
- Owner Primary: DevSecOps / Release Engineering
- Owner Supporting: Security Engineering; Platform Engineering
