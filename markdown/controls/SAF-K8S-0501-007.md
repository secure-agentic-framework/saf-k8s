# SAF-K8S-0501-007 - East-west AI workload traffic monitoring

- Domain: D05 - Network Security and Communication
- Knowledge Area: 5.1 - Network Policies
- Maturity: Practitioner
- Classification: ai-specific

## Statement

East-west traffic between AI workload segments must be monitored using network flow logging and anomaly detection to identify unexpected cross-segment communication patterns that may indicate data poisoning, model exfiltration, or unauthorized access to training infrastructure.

## Objective

Detect anomalous inter-workload communication between AI segments that bypasses or violates intended segmentation policy, enabling rapid identification of compromise or policy drift.

## Rationale

Namespace isolation under SAF-K8S-0501-002 defines expected within-cluster paths. Enforcement changes and incomplete telemetry can obscure unexpected inter-segment communication. Verify that observed allowed and denied flows are attributable and agree with the intended policies.

## Scope

Applies to all Kubernetes clusters hosting AI/ML workloads with network segmentation in place. Monitoring must cover traffic between training, inference, pipeline, and notebook segments. Includes both permitted flows (for anomaly detection) and denied flows (for policy violation alerting).

## Enforcement

- Primary Enforcement Point: Network flow monitoring and anomaly detection infrastructure (Cilium Hubble, Calico flow logs, or equivalent CNI flow logging).
- Implementation Surface: Cilium Hubble or equivalent flow logging for east-west AI traffic monitoring, anomaly detection rules for unexpected cross-segment communication (training-to-inference, notebook-to-production), SIEM integration for flow log analysis, alerting dashboards covering AI workload traffic patterns, and baseline traffic profiles for normal inter-segment communication.
- Owner Primary: Security Operations
- Owner Supporting: Network Engineering; ML Platform Engineering
