# SAF-K8S-0103-010 - Leader election configuration and lease object RBAC

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.3 - Controller-Manager, Scheduler, and Cloud Controller Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Production Kubernetes clusters must enable leader election for kube-controller-manager, kube-scheduler, and any deployed cloud-controller-manager. Configure lease duration, renew deadline, and retry period for measured API latency. Restrict per-Lease read and update access to authorized component identities and documented operational roles, and verify effective permissions from all applicable bindings.

## Objective

Protect leader election from disruption or manipulation by ensuring safe timing parameters and tightly scoped access to Lease objects.

## Rationale

Leader election is both a configuration-safety problem and an authorization problem. Unsuitable timing can delay or destabilize failover. Broad Lease permissions allow unintended access to the leader election record. Component identities can be certificate-authenticated users or service accounts depending on deployment. RBAC can constrain named get and update, while a top-level create grant cannot be scoped by resourceNames. In upstream Kubernetes v1.36.1, the built-in kube-system leader-locking Roles for kube-controller-manager and kube-scheduler grant namespace-wide Lease access alongside their named ClusterRole rules. Verify the effective authorization from all bindings. This control isolates those leader-election-specific safeguards from broader HA topology requirements.

## Scope

Applies to production clusters running kube-controller-manager, kube-scheduler, and cloud-controller-manager with leader election. Covers leader election configuration, Lease timing, and access to the configured coordination namespace and Lease names. Account for list and watch access separately from named get and update. Review documented administrative or break-glass access.

## Enforcement

- Primary Enforcement Point: Leader Election / RBAC
- Implementation Surface: Component flags or configuration, Lease-specific RBAC roles and bindings, and latency-aware timing evidence. Precreate named Lease objects when compatible with component recovery requirements, or review the necessary create grant separately and use admission if creation must be constrained by name.
- Owner Primary: Platform Engineering
- Owner Supporting: Site Reliability Engineering; Security Engineering
