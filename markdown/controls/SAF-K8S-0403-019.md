# SAF-K8S-0403-019 - Kubernetes Secrets external KMS provider integration

- Domain: D04 - Identity, Access, and Secrets Management
- Knowledge Area: 4.3 - Secrets Management
- Maturity: Foundational
- Classification: baseline

## Statement

Verify that governed Kubernetes Secrets persist under application-layer envelope encryption that uses a supported external KMS authority. Demonstrate the effective write provider and check coverage of previously stored objects after adopting or changing the integration.

## Objective

Keep key-encryption authority external to the API storage boundary and verify effective protection of the governed Secret records.

## Rationale

A self-managed Kubernetes KMS plugin runs with the API server and uses a distinct remote key authority. Local-only storage encryption, a configured provider and the effective stored envelope are distinct. A managed KMS may use a provider-managed or customer-managed key according to the supported implementation and custody policy.

## Scope

Applies to governed Kubernetes Secrets on actual self-managed and managed cluster versions. Identify the selected KMS integration, supported resource scope, key custody and existing-record migration evidence.

## Enforcement

- Primary Enforcement Point: Effective kube-apiserver storage transformation and backend KMS operations, or verified equivalent provider-managed application-layer evidence.
- Implementation Surface: For supported self-managed versions verify KMS v2 selection for writes, approved remote authority, actual encrypted Secret envelopes and rewrite of pre-existing records. For managed services verify the version-specific application-layer scope and documented effective state, with appropriate custody and migration evidence.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Key Management/Cryptography; Cloud Platform Engineering
