# SAF-K8S-0901-006 - Gang scheduling security (Volcano, Kueue)

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.1 - Distributed Training Workload Security
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Gang scheduling systems (Volcano, Kueue) must enforce controls that prevent resource quota manipulation, scheduling priority abuse, and resource starvation attacks during distributed training job scheduling.

## Objective

Ensure that gang scheduling for distributed training cannot be exploited to monopolize GPU resources, starve other workloads, or bypass resource quota enforcement.

## Rationale

Gang schedulers coordinate the simultaneous allocation of multiple GPU nodes for distributed training. Without proper controls, a malicious user can manipulate priority classes to preempt legitimate workloads, inflate resource requests to monopolize cluster GPUs, or exploit gang scheduling semantics to create deadlocks that deny resources to other training jobs.

## Scope

Applies to all Kubernetes clusters using Volcano, Kueue, or equivalent gang scheduling systems for distributed training job orchestration. Covers queue configuration, priority class assignments, and resource quota enforcement. Excludes standard Kubernetes scheduling for non-training workloads.

## Enforcement

- Primary Enforcement Point: Gang scheduler queue configuration, Kubernetes ResourceQuota and LimitRange objects, and priority class admission controls.
- Implementation Surface: Volcano Queue and PodGroup CRDs, Kueue ClusterQueue and LocalQueue configurations, Kubernetes ResourceQuota objects for aggregate namespace GPU/extended-resource limits, and LimitRange objects for applicable per-Pod/container resource bounds; PriorityClass definitions and admission controls restricting priority assignment, fair-share scheduling policies, an admission-enforced workload intake limit where policy bounds backlog, and RBAC restricting CRD operations (Queue, ClusterQueue, PodGroup creation) to platform administrators. Namespace object-count quotas can bound total Job objects. Use a pending-aware admission mechanism for a limit that counts only pending work in one queue.
- Owner Primary: ML Platform Engineering
- Owner Supporting: Platform Engineering; Security Engineering
