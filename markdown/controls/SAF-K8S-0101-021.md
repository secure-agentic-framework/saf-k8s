# SAF-K8S-0101-021 - API server approved admission controller chain configuration

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.1 - Kubernetes API Server Security
- Maturity: Foundational
- Classification: baseline

## Statement

Production Kubernetes clusters must restrict the API server admission controller chain to approved components and govern deviations from the approved baseline. Where Kubernetes v1.37 manifest-based admission is used, review the approved on-disk policies, bindings and kube-apiserver configuration as part of that baseline. Verify that startup enforcement is effective before installing API-hosted policies and that any rules protecting named API-hosted admission resources permit approved changes.

## Objective

Reduce API server policy bypass risk by ensuring only approved admission controllers are enabled and that deviations are explicitly governed.

## Rationale

Unapproved or weakly governed admission controllers can disable, weaken, or bypass policy enforcement at the API server entry point. Constraining the admission chain to approved components preserves centralized enforcement for cluster and workload requests. Kubernetes v1.37 enables the manifest-based admission feature gate by default, but file-backed enforcement requires explicit plugin configuration and valid manifests. File-backed policies can enforce startup checks independently of API-hosted admission objects. CEL-only policies have no webhook callout; webhook failure behavior is covered by SAF-K8S-0605-007.

## Scope

Applies to all production Kubernetes clusters and to non-production clusters that host sensitive data, shared workloads, or provide a path to production. For managed Kubernetes services, this control applies to all customer-exposed API server admission controller settings and to compensating controls where provider-managed settings are not directly configurable.

## Enforcement

- Primary Enforcement Point: Admission Control Baseline Enforcement
- Implementation Surface: Cluster provisioning templates, API server configuration and admission plugin inventory, managed Kubernetes security settings, and periodic configuration assessment. When using manifest-based admission, inventory the approved static directories on every applicable API server and verify both allowed and denied behavior.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Cloud Platform Engineering
