# SAF-K8S-0202-008 - Container runtime socket access protection

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.2 - Container Runtime Security
- Maturity: Foundational
- Classification: baseline

## Statement

Runtime control sockets for rootful daemons must be owned by root and accessible only to authorized host principals. For approved rootless daemons, restrict access to the dedicated daemon identity and explicitly authorized administrators. Prevent workload access to the host socket.

## Objective

Prevent unauthorized local access to the container runtime control socket on cluster nodes.

## Rationale

The container runtime socket provides full control over container lifecycle operations. If non-root users, compromised workloads, or local processes can reach the socket, they can create privileged containers, escape isolation boundaries, or interfere with other workloads. Socket ownership and permission controls are independently auditable from broader runtime configuration settings.

## Scope

Applies to all nodes running containerd or CRI-O in production clusters. For provider-managed runtime sockets, verify the provider's local access boundary and any customer-visible controls. Network isolation addresses separate network paths and does not replace local Unix socket protection. Custom or alternative CRI implementations must demonstrate equivalent hardening.

## Enforcement

- Primary Enforcement Point: Node image build pipeline and node-level runtime socket ownership and permission settings.
- Implementation Surface: Runtime socket and parent directory metadata, effective owner and group membership, ACLs where used, and validation of unauthorized local access denial. Verify workload admission and mount policy separately to prevent exposing the host socket.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; OS/Infrastructure
