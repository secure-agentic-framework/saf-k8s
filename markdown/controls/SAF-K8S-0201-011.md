# SAF-K8S-0201-011 - Kubelet webhook authentication and authorization enforcement

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.1 - Kubelet and Node Configuration Hardening
- Maturity: Foundational
- Classification: baseline

## Statement

Production Kubernetes nodes must enable webhook authentication for kubelet bearer tokens and Webhook authorization for kubelet API requests. Where approved clients authenticate with X.509 certificates, configure the trusted client CA and apply the same request authorization checks. Grant monitoring identities only the node subresources required by their endpoints. With fine-grained kubelet authorization available, avoid the broad nodes/proxy grant for monitoring and document any required exceptions.

## Objective

Reduce node-level attack surface by ensuring kubelet API access is mediated by authenticated identities and authorization decisions.

## Rationale

The kubelet exposes workload and node management operations. TokenReview validates bearer identities and SubjectAccessReview authorizes requests. Fine-grained kubelet authorization became stable in Kubernetes v1.36. Use endpoint-specific permissions such as nodes/metrics, nodes/stats, and nodes/healthz where needed, and audit existing bindings because authorization can still fall back to nodes/proxy for endpoints such as healthz.

## Scope

Applies to all kubelet instances on production cluster nodes, including dedicated GPU and AI inference nodes. For managed Kubernetes services where kubelet flags are provider-controlled, compensating controls such as node network isolation and provider-documented hardening attestation must be in place. Non-production clusters that process sensitive data or connect to production networks are also in scope.

## Enforcement

- Primary Enforcement Point: Node provisioning templates, kubelet configuration files, and configuration management tooling (e.g., Ansible, Terraform, cloud-init).
- Implementation Surface: KubeletConfiguration authentication and authorization settings, node provisioning templates, and effective RBAC review. Verify that a monitoring identity can read its approved endpoints and is denied unused endpoints and broad proxy authorization. Record the applicable Kubernetes version, endpoint-to-subresource mapping, and approved exceptions.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Cloud Infrastructure
