# SAF-K8S-1002-006 - Sensitive metric redaction and access restriction

- Domain: D10 - Observability, Incident Response, and Governance
- Knowledge Area: 10.2 - Monitoring, Metrics, and Tracing
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Organizations must redact or restrict access to sensitive metrics that reveal GPU topology, training hyperparameters, or proprietary AI model behavior data, using Prometheus metric relabeling before ingestion or access restrictions on detailed data. Where teams need only summarized data, expose approved aggregates through scoped access and verify restrictions on the original series.

## Objective

Prevent leakage of competitively sensitive or security-relevant AI infrastructure data through metric exposition, ensuring GPU topology, model hyperparameters, and inference performance data are accessible only to authorized teams.

## Rationale

Metric data can carry high-value intellectual property: GPU NVLink topology reveals hardware layout (competitive intelligence), training hyperparameters reveal model architecture choices (IP), and inference accuracy trends reveal model performance (business data).

## Scope

Applies to all metric labels, dimensions, and time series that expose GPU topology, training job internals, and inference serving internals. Covers both Prometheus-scraped metrics and custom metrics pushed via push gateway.

## Enforcement

- Primary Enforcement Point: Prometheus metric relabeling (metric_relabel_configs) for new scraped samples, and access controls for detailed source and stored metrics. Recording rules write derived summaries to additional series. Apply retention or remediation and access restrictions to historical detail.
- Implementation Surface: Prometheus metric_relabel_configs to remove sensitive series or dimensions before ingestion, with checks for collisions among retained series, recording rules or source aggregation to provide approved summaries, and scoped authorization for source, retained and replicated metrics, including namespace-scoped metric APIs.
- Owner Primary: AI/ML Engineering
- Owner Supporting: Security Operations,Platform Engineering
