# SAF-K8S-0606-018 - Zero-trust CI/CD handoff verification and independent evidence generation

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.6 - CI/CD and GitOps Pipeline Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Authenticate and authorize the responsible actors for each governed CI/CD handoff. Before use, verify the exact artifact or intent and the required evidence against receiving-stage policy. Where release relies on build evidence, bind it to the evaluated subject and collect it through a protected component whose isolation or trust is stronger than the build step it evaluates.

## Objective

Establish which identity performed each handoff, which artifact and evidence were accepted, and which receiving-stage checks supported that decision.

## Rationale

NIST SP 800-204D describes recurring trust establishment and verification of integrity across CI/CD handoffs. Verified evidence supports only its observed, bound claims. The security of evidence generation depends on actual isolation, authorization and key custody.

## Scope

Applies to governed transfers of source, inputs, artifacts, evidence or deployment intent. Document each handoff, the participating actors, the subject and the applicable receiving policy.

## Enforcement

- Primary Enforcement Point: Stage-specific identity authorization, artifact integrity checks and protected verification of build evidence at handoff.
- Implementation Surface: Define approved actors, permissions, evidence producers, subject digests and receiving policy for each handoff. Confirm verified authorization, approved signer or evidence identity, integrity and required claim binding before use. Protect evidence and keys from build-controlled modification and validate the higher-trust boundary with deployed evidence. Use the selected identity and attestation mechanisms appropriate to the pipeline.
- Owner Primary: DevSecOps / Release Engineering
- Owner Supporting: Security Engineering; Platform Engineering

### NIST-800-53R5 SR-4

- Framework: NIST SP 800-53 Revision 5 5.2.0
- Requirement Title: Provenance
- Relation Type: supports
- Strength: moderate
- Applicability: conditional
- Strength Reason Code: partial-control-coverage
- Applicability Condition: The organization uses the verified handoff record to document, monitor, or maintain provenance for the specific system component or artifact being transferred; provenance for other components and lifecycle stages is separately established.

#### Framework Mapping Notes

The control contributes one handoff record linking the authenticated producer/observer identity, artifact digest, signed evidence and receiving decision. It does not establish end-to-end provenance for AI models, training data, tools, dependencies, or all lifecycle stages. NIST SP 800-53 Rev. 5 SR-4 concerns documenting, monitoring and maintaining provenance of systems and system components; retain this conditional contribution only where this handoff is incorporated into that provenance record.

### NIST-SSDF PS.2.1

- Requirement Title: Make software integrity verification information available to software acquirers.
- Relation Type: supports
- Strength: moderate
- Applicability: conditional
- Strength Reason Code: partial-control-coverage
- Applicability Condition: The receiving stage is acting as the software acquirer for the artifact and is provided the integrity-verification information needed to verify it before use; other acquirers and release channels are assessed separately.

#### Framework Mapping Notes

This control demonstrates one receiver using a signed evidence statement and exact artifact digest before accepting a handoff. It does not require particular signing products, transparency logging, or make verification information available to all software acquirers. NIST SP 800-218 SSDF PS.2.1 is applicable only where the verified receiver is an acquirer and this process makes its verification information available to that acquirer.
