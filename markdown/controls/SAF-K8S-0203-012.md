# SAF-K8S-0203-012 - Enforce and audit Linux kernel module loading policy

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.3 - Host OS and Kernel Hardening
- Maturity: Foundational
- Classification: baseline

## Statement

For governed production Linux pools, select and verify an effective kernel policy for loadable modules. Disable module support if unneeded, freeze loading after the approved boot inventory where lifecycle permits, or require trusted signatures where dynamic loading is required. Keep an independently reviewed module inventory.

## Objective

Limit loadable kernel code to the approved operating model and verify the effective preventive boundary.

## Rationale

Modprobe alias suppression and inventories support configuration or audit activities. The kernel can enforce post-boot loading restrictions or trusted signer policy. Signer-based enforcement covers trusted keys and does not establish a per-module name allowlist.

## Scope

Applies to governed production Linux node images and pools. Record supported kernel and provider features, operationally required modules and extensions, key custody, provider-owned evidence, and applicable exceptions.

## Enforcement

- Primary Enforcement Point: Effective Linux kernel module policy, approved image and boot lifecycle, and trusted signer configuration where applicable.
- Implementation Surface: Verify effective kernel policy and expected stock module behavior in an owned fixture where feasible. Record loaded, built-in and packaged inventories, signer trust and required operations separately. Check reboot and update behavior and gather provider-supported evidence.
- Owner Primary: OS/Infrastructure
- Owner Supporting: Platform Engineering; Security Engineering
