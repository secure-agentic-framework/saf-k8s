# SAF-K8S-0704-017 - Least-privilege cloud-to-cluster privileged access boundary enforcement

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.4 - Cloud Provider Security Integration
- Maturity: Practitioner
- Classification: baseline

## Statement

Limit each cloud-authenticated or otherwise externally authenticated principal to the approved effective Kubernetes API permissions across all active authorizers. Review and remediate excessive grants and govern approved privileged exceptions separately.

## Objective

Prevent authorization beyond approved actions, resources and scopes, including alternate and indirect privileged paths.

## Rationale

Provider permissions, resolved Kubernetes identity attributes and bindings can confer overlapping access. Removing one grant may leave another active. Validate the effective decisions and review all relevant authorization stores against approved capabilities.

## Scope

Applies to managed clusters and their cloud-authenticated administrators and automation. Include provider authorization, Kubernetes RBAC as applicable, identity and group claims, broad or indirect permissions, administrative recovery paths and approved exceptions.

## Enforcement

- Primary Enforcement Point: Provider and Kubernetes authorization paths with an approved effective permission matrix and observed decisions.
- Implementation Surface: Inventory relevant principals and all active authorizers. Compare approved verbs, resources, namespaces and elevated capabilities with provider and Kubernetes grants and scoped authorization checks. Investigate excess decisions, remediate the contributing grant and repeat both positive and negative observations.
- Owner Primary: Cloud Platform Engineering
- Owner Supporting: Security Engineering; Platform Engineering
