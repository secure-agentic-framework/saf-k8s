# SAF-K8S-0103-015 - Scheduler extender authentication and custom scheduler approval

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.3 - Controller-Manager, Scheduler, and Cloud Controller Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Require encrypted scheduler extender transport with verified server identity, authenticated scheduler identity and effective caller authorization. Approve custom schedulers and enforce approved Pod scheduler names at the applicable admission and deployment boundaries.

## Objective

Keep scheduler extension decisions and custom scheduler use within reviewed and authorized integration boundaries.

## Rationale

Transport trust, caller authorization, Kubernetes API access and organizer approval apply at distinct points. Scheduler extender configuration can supply client and server trust settings while endpoint policy must enforce the actual caller boundary.

## Scope

Applies to governed scheduler extender endpoints and alternate schedulers. Inventory endpoints, versioned configuration, identities, applicable controller RBAC, approved scheduler inventory and applicable admission paths.

## Enforcement

- Primary Enforcement Point: Effective extender caller and server trust, endpoint authorization, least-privilege API roles and enforced scheduler approval.
- Implementation Surface: Verify TLS trust and authenticated scheduler calls against owned expected routes, endpoint authorization, and evidence of approved Pod placement. Check rejection of unapproved scheduler references and periodically review deployed ownership and integration.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Application Platform teams
