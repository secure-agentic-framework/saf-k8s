# SAF-K8S-0505-003 - Internal service endpoint protection

- Domain: D05 - Network Security and Communication
- Knowledge Area: 5.5 - API Server and Service Exposure Protection
- Maturity: Practitioner
- Classification: baseline

## Statement

Internal services must use ClusterIP type by default, and headless services must be secured with network policies restricting direct pod access to authorized consumers.

## Objective

Limit in-scope Services to internal ClusterIP addressing and enforce authorized endpoint traffic through a supporting network plugin.

## Rationale

ClusterIP supplies a cluster-scoped virtual address and is the API default when Service type is omitted. Selector-backed headless Services publish backing Pod addresses through DNS and EndpointSlices. Service addressing supplies discovery and reachability. Apply NetworkPolicy to the endpoint Pods for traffic authorization.

## Scope

Applies to in-scope internal Services and their endpoints. Inventory virtual IP and headless Services, governed exceptions and directly reachable Pod paths. Verify policy coverage on the installed network plugin.

## Enforcement

- Primary Enforcement Point: Service admission for allowed exposure types and the network plugin data plane for policy on selected endpoint Pods.
- Implementation Surface: Use ClusterIP for internal Services. Where required, add admission policy to enforce allowed Service types and related exposure fields. Apply ingress NetworkPolicy that selects endpoint Pods and allows the intended peers and ports. Verify the matching namespace and workload labels, additive policies, and accepted and rejected traffic by Service address and directly to Pod endpoints.
- Owner Primary: Platform Engineering
- Owner Supporting: Application Development
