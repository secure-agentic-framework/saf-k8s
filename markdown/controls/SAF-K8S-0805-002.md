# SAF-K8S-0805-002 - GPU allocation audit trail and workload identity tracking

- Domain: D08 - GPU, Accelerator, and Confidential Computing
- Knowledge Area: 8.5 - GPU Workload Auditing and Monitoring
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Record attributable accelerator scheduling and allocation evidence with source and time provenance. Correlate the workload lifecycle with supported device allocation evidence, record available sharing-mode history, and identify gaps and inferred intervals.

## Objective

Reconstruct supported accelerator attribution for investigation, cost analysis and governance with clear identity, timing and evidence limits.

## Rationale

Kubernetes API lifecycle records, device allocation observations, provider inventories and telemetry describe different events. A Pod UID distinguishes recreated workloads, while a device or claim identifier and effective sharing configuration require allocation-specific evidence.

## Scope

Applies to governed accelerator workloads. Document cluster, node, namespace, Pod UID, container, workload ownership, resource API and sharing mode. Record source clock, supported device identifier, data access, retention and gaps, including for managed services.

## Enforcement

- Primary Enforcement Point: Scoped Kubernetes API and lifecycle logs, supported allocation and release records or snapshots, effective device configuration history and protected correlated log storage.
- Implementation Surface: Capture relevant API events and effective admitted resource references. Collect version-supported device plugin, PodResources, DRA or provider observations with their provenance. Match stable identifiers across sources and distinguish sampled associations from authoritative allocation and release events. Exercise recreation, missing evidence, ambiguity and retrieval.
- Owner Primary: ML Platform Engineering
- Owner Supporting: Security Operations; Observability Engineering; FinOps
