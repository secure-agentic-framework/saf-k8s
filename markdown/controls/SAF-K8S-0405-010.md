# SAF-K8S-0405-010 - API impersonation audit logging and alerting

- Domain: D04 - Identity, Access, and Secrets Management
- Knowledge Area: 4.5 - Identity Abuse Detection and Mitigation
- Maturity: Practitioner
- Classification: baseline

## Statement

Capture native Kubernetes API audit events for scoped impersonation requests at the level needed to distinguish the authenticated caller, impersonated identity, operation and outcome. Verify coverage, protected collection and delivery of findings for unexpected identity or operation combinations.

## Objective

Preserve attributable impersonation evidence and verify that defined policy findings reach the responsible reviewers within the applicable response objectives.

## Rationale

Authorization to impersonate and operational approval for a particular use are distinct. Native API audit records support attribution, while detection policy, retention and alert delivery depend on the configured log collection and response pipeline.

## Scope

Applies to inventoried Kubernetes API paths and governed identities, including any supported constrained impersonation in use. Define auditable stages, covered operations and event content, log access and retention, explicit reviewer ownership and notification targets.

## Enforcement

- Primary Enforcement Point: Observed native API audit policy and protected collection, correlation and detection at the actual reporting boundary.
- Implementation Surface: Test approved and unexpected cases, original and delegated identities, object and response context, applicable audit coverage, protected retention, pipeline delivery, missing-event monitoring and measured routing to the defined reviewer.
- Owner Primary: Security Engineering
- Owner Supporting: Platform Engineering; Security Operations
