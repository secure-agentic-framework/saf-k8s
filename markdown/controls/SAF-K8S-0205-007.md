# SAF-K8S-0205-007 - Node firewall compatibility validation with CNI and network policy

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.5 - kube-proxy and Node Networking Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Validate node firewall compatibility with the selected CNI, workload policy and Service proxy for each governed node profile. Record required and denied flows, applicable rule hooks and expected behavior, and collect attributable observations before and after changes.

## Objective

Preserve documented cluster connectivity while demonstrating that node and workload enforcement produces the intended results.

## Rationale

Firewall and workload policy may enforce at different hooks on the same traffic path. Routing, encapsulation, proxy implementation and IP family affect where decisions occur. A rule or reachable endpoint alone does not establish interaction between the components.

## Scope

Applies to governed Kubernetes node profiles. Record actual kernel, CNI, proxy mode, firewall ownership, interfaces, address families and required host, workload and Service paths. Review after platform, routing, firewall or policy changes.

## Enforcement

- Primary Enforcement Point: Effective node firewall and CNI enforcement along each documented path, with change review and runtime evidence.
- Implementation Surface: Exercise owned allowed and denied paths before and after representative rule changes. Collect policy state, attributable rules or counters, observed application outcomes, required control flows and rollback results. Track unsupported or externally enforced paths with their evidence owner.
- Owner Primary: Network Engineering
- Owner Supporting: Platform Engineering; Cloud Infrastructure; Security Engineering
