# SAF-K8S-0302-005 - AI workload security context hardening profiles

- Domain: D03 - Workload and Pod Security
- Knowledge Area: 3.2 - Security Contexts and Capabilities
- Maturity: Foundational
- Classification: ai-specific

## Statement

AI workloads must enforce non-root execution, read-only container root filesystems with explicit writable mounts as needed, and approved workload-specific seccomp or AppArmor profiles. Validate profiles against the actual workload, including GPU and RDMA interfaces only where used.

## Objective

Reduce the privileges, writable paths and operations available to AI workloads while preserving the behavior required by each approved workload.

## Rationale

Non-root execution, a read-only root filesystem and a workload-specific profile constrain different parts of the container's behavior. Seccomp restricts system calls. AppArmor applies access rules to confined processes. Profile requirements depend on the workload, kernel, runtime and any accelerator or network driver in use.

## Scope

Applies to regular, init and ephemeral containers in AI and ML workloads on Linux nodes. Validate the profile against the actual supported workload and node configurations, including GPU or RDMA where used.

## Enforcement

- Primary Enforcement Point: Use Pod Security Admission as a baseline and apply workload-specific admission for the effective non-root, read-only root and approved profile settings. Verify that each eligible node can use the selected seccomp or AppArmor profile.
- Implementation Surface: Check effective security context fields for regular, init and ephemeral containers on the relevant admission paths. Require an explicit read-only root per container and approved writable mounts. For a Localhost profile, verify the expected seccomp file or loaded AppArmor profile and record its version on eligible nodes. Exercise required workload operations and a harmless operation denied by the selected profile. For accelerator workloads, preserve the driver, plugin or CDI configuration and workload results.
- Owner Primary: AI/ML Platform team
- Owner Supporting: Platform Engineering; Security Engineering
