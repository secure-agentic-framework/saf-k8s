# SAF-K8S-0503-006 - Cloud load balancer security group configuration

- Domain: D05 - Network Security and Communication
- Knowledge Area: 5.3 - Ingress, Egress, and DNS Hardening
- Maturity: Practitioner
- Classification: baseline

## Statement

Cloud load balancer security groups and firewall rules must be configured to limit source IP ranges to approved networks for all load balancer resources provisioned by Kubernetes Services.

## Objective

Ensure that cloud-provisioned load balancers restrict network-level access to approved source IP ranges, preventing access from unintended network segments even when internal load balancer annotations are correctly applied.

## Rationale

Internal load balancer scope and source filtering address different requirements. Verify that the installed provider and controller apply the intended source restrictions along each listener-to-backend path and that other network rules preserve that boundary.

## Scope

Applies to all cloud-provisioned load balancer resources in production clusters. Security groups must be reviewed for both internet-facing and internal load balancers. Applies to AWS, GCP, and Azure managed Kubernetes environments.

## Enforcement

- Primary Enforcement Point: Effective source filtering in the configured provider's frontend, VPC or VNet, backend interface, and node data plane where applicable.
- Implementation Surface: For AWS NLB, verify frontend security groups and the separate backend security group rules. For GKE passthrough LoadBalancer Services, verify the applicable VPC ingress rules aimed at the Service forwarding address and the node data plane. For AKS, verify the effective VNet or node security rules and host enforcement for the selected source-filtering mode. Reconcile these results with the approved network allowlist and record allowed and denied reachability evidence.
- Owner Primary: Cloud Platform Engineering
- Owner Supporting: Network Engineering; Security Engineering
