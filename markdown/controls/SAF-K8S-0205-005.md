# SAF-K8S-0205-005 - eBPF program integrity verification and loading monitoring

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.5 - kube-proxy and Node Networking Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Restrict program loading and relevant Linux capabilities to approved components on governed eBPF networking nodes. Verify program material at the available trusted load boundary and distinguish load attempts, accepted loads and attachments from point-in-time inventory. Record approved exceptions and provider ownership.

## Objective

Make eBPF program authorization, provenance and runtime observation attributable and verifiable within the supported platform scope.

## Rationale

The kernel limits supported program types, helpers and attachment points. Image digests identify packaged content, while program identity, signature checks, accepted loading and active attachments require separately attributable evidence. A valid signature establishes integrity under the selected trust policy.

## Scope

Applies to governed Linux node versions and supported eBPF components. Document required kernel features, effective capability and host boundaries, approved loader identities, verification and monitoring support, and provider-owned exceptions.

## Enforcement

- Primary Enforcement Point: Effective node and workload capability restrictions, approved loader verification, program inventory and attributed program lifecycle telemetry.
- Implementation Surface: Verify assigned identities and effective capabilities, the approved material and accepted or refused loads as supported. Record program identity, attach scope, monitor completeness and failure behavior. Confirm kernel enforcement only where the deployed implementation supports it.
- Owner Primary: Security Engineering
- Owner Supporting: Platform Engineering; Network Engineering
