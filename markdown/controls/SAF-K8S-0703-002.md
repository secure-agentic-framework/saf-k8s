# SAF-K8S-0703-002 - Pod Disruption Budgets for workload availability

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.3 - Resource Governance and Priority
- Maturity: Foundational
- Classification: baseline

## Statement

Organizations must configure matching PodDisruptionBudget objects for in-scope production workloads and stateful AI services. Select minAvailable or maxUnavailable based on healthy replicas and verify maintenance automation uses the Kubernetes Eviction API.

## Objective

Maintain workload availability during planned maintenance by constraining API-initiated voluntary Pod evictions to the configured disruption allowance.

## Rationale

The API server evaluates the matching PodDisruptionBudget when it processes a voluntary Eviction request. A zero disruption allowance rejects an eviction that would reduce healthy replicas below the configured requirement. Direct deletion, controller rollouts, scheduler preemption and involuntary disruption require separate availability planning.

## Scope

Applies to all production deployments, statefulsets, and long-running AI workloads (inference services, model serving endpoints, distributed training jobs) across all Kubernetes clusters. Batch training jobs with checkpointing may have relaxed PDB settings. Development and ephemeral workloads may be excluded with documented justification.

## Enforcement

- Primary Enforcement Point: The Kubernetes Eviction API applies matching PodDisruptionBudget rules. A release or policy check verifies budgets and selectors are in place for eligible workloads.
- Implementation Surface: policy/v1 PodDisruptionBudget selectors, minAvailable or maxUnavailable, current DisruptionAllowed status and permitted or refused Eviction requests. Review replica counts, scaling, drain and upgrade tooling, budget overlap, and operational exceptions for single-replica or non-interruptible workloads.
- Owner Primary: Platform Engineering
- Owner Supporting: ML Engineering; SRE
