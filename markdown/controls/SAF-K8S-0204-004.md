# SAF-K8S-0204-004 - Forensic capture capabilities for container incident investigation

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.4 - Runtime Threat Detection
- Maturity: Practitioner
- Classification: baseline

## Statement

Maintain authorized and tested incident evidence collection methods for governed Kubernetes platforms. Define the supported filesystem, process-state and network evidence classes, collection effects, retention, custody, and alternatives for inaccessible evidence.

## Objective

Acquire and preserve scoped incident evidence with attributable collection and an explicit impact record.

## Rationale

Volatile data can change before and during collection. Managed platforms and runtimes expose different artifact paths and privileges. A runbook needs tested alternatives when a supported method is unavailable, and network flow retention requires a separate storage pipeline.

## Scope

Applies to identified production compute classes and incident response workflows. Exercise collection at least annually. SAF-K8S sets a 72-hour minimum for retention of applicable production network flow evidence. Document an approved provider-specific alternative and its limits and ownership where necessary. Record supported capture, sensitive data approval, collection impact and storage responsibility.

## Enforcement

- Primary Enforcement Point: Authorized incident response collection paths, tested evidence handling and supported identity and retention controls.
- Implementation Surface: Exercise scoped collection from an owned workload, authorization, reliable timestamps and provenance, integrity and safe handoff. Verify capture completeness, platform-specific state methods, deployed flow retention and loss, evidence access, and approved cleanup under their applicable procedures.
- Owner Primary: Security Operations (SOC)
- Owner Supporting: Security Engineering; Platform Engineering
