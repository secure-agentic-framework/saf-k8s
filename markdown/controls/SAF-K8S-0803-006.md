# SAF-K8S-0803-006 - DPU and SmartNIC host trust boundary definition and policy engine administrative restriction

- Domain: D08 - GPU, Accelerator, and Confidential Computing
- Knowledge Area: 8.3 - High-Performance Interconnect Security
- Maturity: Advanced
- Classification: ai-specific

## Statement

Define effective host and offload-device trust and administrative boundaries for the deployed operating mode. Restrict policy changes on every applicable management path, preserve authorized visibility, and verify which data-plane rules the device actually enforces.

## Objective

Make offloaded policy ownership and effective administrative and data-plane permissions verifiable.

## Rationale

Host, device operating system, out-of-band controller and Kubernetes management surfaces can confer different privileges. Kubernetes RBAC governs Kubernetes API requests. Device access and offloaded enforcement require separate controls and evidence.

## Scope

Applies to governed programmable offload paths and all related host, device, BMC, operator and API surfaces. Inventory operating mode, owners, effective policy, telemetry and approved exceptions.

## Enforcement

- Primary Enforcement Point: Effective vendor device and management access controls, scoped host delegation and Kubernetes operator RBAC, and independent offload observations.
- Implementation Surface: Record the actual host and device ownership boundary and applicable administrative paths. Restrict and audit device policy changes and Kubernetes management separately. Verify effective offload rules and observation coverage and compare with intended host policy.
- Owner Primary: Network Engineering
- Owner Supporting: GPU Infrastructure Engineering; Security Engineering; Platform Engineering
