# SAF-K8S-0502-009 - Kubernetes CNI IPAM capacity sizing

- Domain: D05 - Network Security and Communication
- Knowledge Area: 5.2 - CNI Plugins and Pod Networking Security
- Maturity: Practitioner
- Classification: baseline

## Statement

IP address management for Kubernetes networking must be configured with adequate pod, service, and node CIDR capacity so IP pools support workload scheduling and service operation without avoidable exhaustion.

## Objective

Maintain sufficient IP address capacity for workload scheduling and service operation by correctly sizing pod, service, and node CIDR allocations.

## Rationale

An exhausted Service pool rejects new ClusterIP allocations. A depleted Pod address pool can prevent a scheduled Pod sandbox from obtaining its IP. Node prefix exhaustion can prevent new nodes from receiving PodCIDRs in designs that allocate a prefix per node. Evaluate these limits and their load signals separately.

## Scope

Applies to all Kubernetes clusters. Covers pod CIDR, service CIDR, and node CIDR range sizing, utilization monitoring, exhaustion thresholds, and alerting for IP address pool depletion.

## Enforcement

- Primary Enforcement Point: Kubernetes Service IP allocation, CNI Pod IPAM configuration, and the mechanism that assigns node PodCIDRs where applicable.
- Implementation Surface: Size each Service, Pod and node address pool for the requirements of its allocator. Verify ServiceCIDR capacity and expansion when supported, CNI Pod allocation behavior and node prefix limits. Monitor allocator-specific remaining capacity and relevant errors.
- Owner Primary: Network Engineering
- Owner Supporting: Platform Engineering; Security Operations
