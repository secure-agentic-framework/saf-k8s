# SAF-K8S-0902-002 - Model loading integrity verification

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.2 - Inference Server and Model Serving Security
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Verify model artifacts against an independently approved immutable digest or trusted signature before serving. Restrict serving-process writes where the workload permits and monitor the effective serving and cache paths against the governed baseline. Define the response to a detected mismatch.

## Objective

Load only model artifacts that match trusted expected identity, protect serving paths from unintended changes, and detect and respond to runtime discrepancies.

## Rationale

Startup verification compares the fetched bytes with a trusted reference. The effective read-only mount limits writes from the serving workload. Storage, cache and other authorized or administrative paths require their own write controls and runtime observation.

## Scope

Applies to all model loading configurations on Kubernetes inference platforms. Covers model artifact verification at pod startup, model cache integrity, read-only volume mounts, and file integrity monitoring for model directories. Excludes endpoint access controls and model registry controls covered by KA 9.5.

## Enforcement

- Primary Enforcement Point: Model initialization or startup verification, protected serving and cache mounts, and the deployed file integrity monitor and incident response path.
- Implementation Surface: Pin or verify the actual served artifact against an independently governed digest or trusted signature. Verify before startup and again after approved reload or cache change as applicable. Restrict serving mounts and other writer roles, monitor governed files, and handle discrepancies using the adopted response policy.
- Owner Primary: ML Platform Engineering
- Owner Supporting: Security Engineering; API Platform Engineering
