# SAF-K8S-0205-004 - eBPF-based kernel-level network policy enforcement

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.5 - kube-proxy and Node Networking Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Use a supported eBPF-capable network policy implementation for governed datapaths where required by the platform profile. Specify the supported kernel, agent, policy API, source and destination paths, protocol scope, and positive and negative behavior. Verify effective datapath enforcement after changes.

## Objective

Enforce the approved Kubernetes network access decisions on defined paths and make their effective implementation observable.

## Rationale

Kubernetes policy intent depends on the selected implementation and supported protocols. Some eBPF-based products pair kernel datapaths with application proxies. Compatibility, startup, disruption behavior and comparative performance are implementation- and workload-specific.

## Scope

Applies to governed Kubernetes node and workload paths that use eBPF-capable networking. Record kernel and agent versions, feature prerequisites, network path classes, ingress and egress coverage, policy convergence, and approved unsupported paths.

## Enforcement

- Primary Enforcement Point: Effective CNI policy implementation in the applicable kernel datapath and separately identified companion enforcement points.
- Implementation Surface: Verify required features and selected policy state. Exercise harmless expected allow and deny paths for owned endpoints and observe convergence and applicable failures. Measure performance and system impact separately under representative load.
- Owner Primary: Platform Engineering
- Owner Supporting: Network Engineering
