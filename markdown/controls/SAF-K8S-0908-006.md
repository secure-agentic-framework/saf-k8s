# SAF-K8S-0908-006 - Secure aggregation for privacy-preserving model outputs

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.8 - Model Abuse and Extraction Prevention
- Maturity: Advanced
- Classification: ai-specific

## Statement

Use an approved secure aggregation protocol where sensitive participant contributions must remain hidden from the aggregation parties defined in the threat model. Separately authorize and validate release of the resulting aggregates under an approved disclosure policy.

## Objective

Protect individual contributions during computation and limit information disclosed by released aggregate results.

## Rationale

A secure aggregation protocol can protect each contribution within its stated party and collusion assumptions while returning the intended combined value. The aggregate value itself can reveal sensitive information. Apply separate release safeguards to the selected result and its permitted repeated use.

## Scope

Applies to governed federated and batch serving workflows where the risk assessment requires private contribution aggregation. Define protected inputs, protocol parties, integrity and dropout assumptions, and release conditions. See SAF-K8S-0908-008 for response shaping and SAF-K8S-0908-009 and SAF-K8S-0908-010 when making applicable formal privacy or cumulative release claims.

## Enforcement

- Primary Enforcement Point: Verified aggregation protocol boundaries and an independent authorized aggregate release decision.
- Implementation Surface: Verify deployed trust separation, protected contribution transport, correct aggregation, cohort and result policy, and minimized observations. Evaluate protocol robustness and protection across real output releases separately. For operating request limits, see SAF-K8S-0908-001.
- Owner Primary: Security Engineering
- Owner Supporting: ML Platform Engineering; Privacy Engineering
