# SAF-K8S-0704-002 - Cloud network, Kubernetes API endpoint and Pod traffic boundaries

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.4 - Cloud Provider Security Integration
- Maturity: Practitioner
- Classification: baseline

## Statement

Define intended cloud node and subnet flows, Kubernetes API endpoint reachability, and Pod ingress and egress separately. Assign each flow to its actual enforcement point and verify representative allowed and denied behavior after deployment and relevant changes.

## Objective

Verify effective boundaries across cloud networking, control-plane reachability and workload connectivity with traceable evidence for each layer.

## Rationale

Cloud firewalls and endpoint modes control provider-defined paths. Kubernetes NetworkPolicy depends on the installed enforcement implementation and the selected Pod traffic directions. Authentication and authorization remain separate decisions on a reachable API endpoint.

## Scope

Applies to cloud-hosted Kubernetes environments selected by the platform owner. Identify provider modes, endpoint restrictions, network policy implementation, node and workload paths, address families, exceptions and material changes.

## Enforcement

- Primary Enforcement Point: Provider-native networks and firewalls, the managed or self-hosted API endpoint, and CNI-enforced Pod traffic policy.
- Implementation Surface: Record separate flow and control mappings and verify deployed provider configuration and endpoint reachability. Validate CNI version, workload selectors and both directions of required Pod connections. Test API authorization independently and retain scoped allowed and denied observations for each governed boundary and its exceptions.
- Owner Primary: Cloud Platform Engineering
- Owner Supporting: Network Engineering; Platform Engineering; Security Engineering
