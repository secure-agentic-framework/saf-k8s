# SAF-K8S-0403-020 - Kubernetes Secrets KMS key least-privilege access policy

- Domain: D04 - Identity, Access, and Secrets Management
- Knowledge Area: 4.3 - Secrets Management
- Maturity: Foundational
- Classification: baseline

## Statement

Grant use of Kubernetes Secrets wrapping keys only to approved integration or explicitly authorized recovery identities. Verify actual key and operation policy across applicable identity policies, key policies, grants and provider roles.

## Objective

Limit authorization over Secrets-protecting keys and document separate key administration and qualified recovery access.

## Rationale

A configured KMS provider does not establish least privilege. The actual wrapping authority can evaluate multiple grants and identities. Runtime use, key status lookup, grants, key administration and emergency access have distinct evidence.

## Scope

Applies to KMS keys protecting governed Kubernetes Secrets and their actual control-plane, integration, provider and recovery identities. Record managed-service limitations and evidence ownership.

## Enforcement

- Primary Enforcement Point: The wrapping authority's effective key and operation policy, reviewed granted identities, and attributable provider audit.
- Implementation Surface: Inventory provider and key scopes, inherited and direct grants, identity and trust binding. Exercise an authorized wrap and unwrap or provider-supported equivalent, an unapproved identity, wrong key, unauthorized policy changes and revocation. Review actual key authority events and exception expiry.
- Owner Primary: Security Engineering
- Owner Supporting: Platform Engineering; Key Management/Cryptography; Cloud Platform Engineering
