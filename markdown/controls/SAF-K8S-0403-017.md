# SAF-K8S-0403-017 - AI platform key-domain hierarchy and envelope encryption architecture

- Domain: D04 - Identity, Access, and Secrets Management
- Knowledge Area: 4.3 - Secrets Management
- Maturity: Foundational
- Classification: baseline

## Statement

Implement approved key hierarchy and lifecycle controls for each governed AI data, storage and signing domain. Verify independent domain use, authenticated envelopes where applicable, distinct signing key purposes, protected custody and effective version transitions.

## Objective

Limit key compromise impact within the modeled trust domains and preserve approved data readability and signing continuity during rotation.

## Rationale

Application envelope encryption, Kubernetes API storage, volume and backup encryption, transport and asymmetric signing protect separate boundaries. Rotating a wrapping key can change new writes while existing ciphertext still depends on an older version. Effective isolation depends on both policy and actual key use.

## Scope

Applies to governed training data, checkpoints, model artifacts, inference, signing and platform storage. Record boundaries, providers, key purposes, protection and deployment-specific lifecycle requirements.

## Enforcement

- Primary Enforcement Point: Effective cryptographic operations and trust boundaries at the actual application, storage or signing service, with verified key authority and custody.
- Implementation Surface: Verify distinct approved wrapping and signing domains, actual encrypted data and bound context, separated permissions, HSM or other approved custody, rotation and rewrap or re-encryption, old-data retention and safe retirement. Assess API encryption and each application store separately.
- Owner Primary: Security Engineering
- Owner Supporting: Platform Engineering; ML Engineering; Key Management/Cryptography
