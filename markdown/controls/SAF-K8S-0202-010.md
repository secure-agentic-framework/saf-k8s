# SAF-K8S-0202-010 - Node default seccomp profile enforcement

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.2 - Container Runtime Security
- Maturity: Foundational
- Classification: baseline

## Statement

Supported Linux nodes must apply the container runtime's approved default seccomp profile to eligible unprivileged workloads that omit a profile. Require separate admission rules for explicit overrides and privileged workloads, with documented exceptions.

## Objective

Reduce container escape risk by constraining workload system-call access through default seccomp enforcement.

## Rationale

Default seccomp profiles reduce the kernel attack surface available to workloads before a runtime vulnerability is exploited. Enforcing seccomp inheritance by default is independently auditable from broader mandatory access control activation because it governs system-call mediation for container processes.

## Scope

Applies to supported Linux production nodes and their container workloads. Verify each applicable node pool and runtime configuration, including fresh workloads after changing the default and replacement of existing workloads. Evaluate SELinux and AppArmor controls separately under SAF-K8S-0303-003 and SAF-K8S-0303-007 where applicable.

## Enforcement

- Primary Enforcement Point: Node seccomp default configuration and workload policy enforcement for seccomp profile inheritance.
- Implementation Surface: Verify the effective kubelet seccompDefault setting or the supported platform equivalent, the applied runtime filter and the active admission policy. Confirm the result for omitted profiles, explicit approved profiles, and unauthorized overrides. Check each exception's owner, scope, expiry, and removal.
- Owner Primary: Security Engineering
- Owner Supporting: Platform Engineering; OS/Infrastructure
