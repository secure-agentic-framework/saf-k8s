# SAF-K8S-0704-018 - Break-glass cloud identity governance for Kubernetes administration

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.4 - Cloud Provider Security Integration
- Maturity: Practitioner
- Classification: baseline

## Statement

Inventory emergency Kubernetes access paths and govern their use through documented ownership, authorization, custody, monitoring and review. Bound activated grants where supported and verify closure, revocation or credential recovery after use as applicable.

## Objective

Maintain an available and auditable emergency path with controlled access and independently verified recovery from activation.

## Rationale

Emergency privileges may come from provider authorization, Kubernetes grants or separately protected recovery credentials. Activation capabilities and dependency failures differ. Govern both temporary access and any justified standing recovery exception.

## Scope

Applies to emergency managed-cluster access through provider identities, Kubernetes authorization and recovery mechanisms. Define the approved operating mode, owner, authorized capabilities, required approvals or emergency exceptions and review frequency for each path.

## Enforcement

- Primary Enforcement Point: Emergency access governance, provider and cluster authorization, monitored recovery credential custody, and post-use verification.
- Implementation Surface: Inventory each recovery route and review custody, availability dependencies, approved use and monitoring. Exercise scoped activation and removal for temporary grants. For required standing recovery paths, verify protective custody, alerts, post-use review and applicable credential rotation. Retain approval, authorization and follow-up evidence for each exercise.
- Owner Primary: Cloud Platform Engineering
- Owner Supporting: Security Engineering; Platform Engineering
