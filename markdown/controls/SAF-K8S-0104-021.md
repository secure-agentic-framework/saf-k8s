# SAF-K8S-0104-021 - Kubernetes component version skew compliance

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.4 - CIS Benchmarks and Patch Management
- Maturity: Foundational
- Classification: baseline

## Statement

Production Kubernetes clusters must maintain applicable control-plane components, kubelets, kube-proxy, and administrative kubectl clients within the upstream Kubernetes version skew policy and any additional provider or deployment-tool constraints.

## Objective

Prevent interoperability failures and control-plane instability caused by unsupported version skew between Kubernetes components and clients.

## Rationale

Even when clusters are nominally supported, unsupported skew between API servers, kubelets, control-plane components, and administrative clients can create API incompatibilities, unstable behavior, and failed operations. Enforcing skew compliance keeps component interactions inside tested compatibility boundaries.

## Scope

Applies to production Kubernetes clusters. Inventory all reachable kube-apiserver instances, kubelets, kube-controller-manager, kube-scheduler, kubectl clients, kube-proxy where deployed, and cloud-controller-manager where deployed.

## Enforcement

- Primary Enforcement Point: Component compatibility governance
- Implementation Surface: Version inventories and pre-upgrade and periodic compliance reports. In highly available clusters, verify the API server version spread and evaluate each component against every API server it can reach, including via load balancers. Evaluate kube-proxy against its colocated kubelet as well. Record provider and deployment-tool restrictions separately.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Change Management
