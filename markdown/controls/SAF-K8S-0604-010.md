# SAF-K8S-0604-010 - Automated AI workload rebuild and redeployment patch pipelines

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.4 - SBOMs and Vulnerability Intelligence
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Maintain an automated rebuild and release path for governed AI runtime patches. Identify the exact candidate runtime and approved model artifact. Verify compatibility, model identity and required release evidence before rollout. Use the existing approved model when compatible, and define a hold, remediation or rollback path for incompatible candidates.

## Objective

Roll out compatible runtime patches on time while preserving verified model behavior and identity and retaining recovery evidence.

## Rationale

A separately versioned or otherwise reproducibly identified model lets teams reuse approved model bytes during compatible runtime updates. Compatibility depends on the changed runtime, libraries, accelerator requirements and model format. Verify the release combination and protect the prior healthy release.

## Scope

Applies to AI and ML workload container images, supporting runtime components, and deployment pipelines in Kubernetes. Covers base image and dependency patch rebuilds, redeployment automation, and validation that patched runtime images do not require model retraining. Does not cover vulnerability classification or SLA prioritization, which are addressed by SAF-K8S-0604-008 and SAF-K8S-0604-009.

## Enforcement

- Primary Enforcement Point: CI rebuild and candidate verification, approved release promotion, Kubernetes rollout health and recovery checks.
- Implementation Surface: Pin build inputs and trigger rebuilds for the applicable base and dependency changes. Bind model and runtime identities in the release record. Test model load, behavior and relevant accelerator and operational requirements. Enforce compatibility and approval, measure digest-specific health, recover a known healthy release on failure, and retain evidence of the model and runtime served.
- Owner Primary: Security Engineering
- Owner Supporting: ML Platform Engineering; DevSecOps / Release Engineering
