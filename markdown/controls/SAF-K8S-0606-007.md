# SAF-K8S-0606-007 - CI/CD build activity monitoring

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.6 - CI/CD and GitOps Pipeline Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Monitor governed build execution environments and CI configuration for selected anomalous process, file and connection activity. Define the covered sources, observation and alert objectives, workloads and detection criteria. Verify sensor state, events, alert routing and applicable loss or latency limits.

## Objective

Provide timely, attributable observations and escalation for selected build security events.

## Rationale

API audit and node-level runtime telemetry cover different actions. An observed file access or connection attempt is a signal that requires context and correlation. Effective detection depends on the actual sensor, operating environment, policy, evidence destination and tested latency.

## Scope

Applies to all CI/CD build infrastructure, including self-hosted Kubernetes-based runners, cloud-managed build services, and dedicated build VMs. Covers monitoring of process execution, network connections, and file access within build environments.

## Enforcement

- Primary Enforcement Point: Runtime observation and CI or Kubernetes audit collection, with verified detection and alert delivery.
- Implementation Surface: Pin the deployed monitor and verify node coverage, event collection, workload identity and scoped selections for process, path and network events. Configure CI and Kubernetes audit separately and protect sensitive data. Correlate supported events with policy, verify routing and time bounds, and document coverage gaps and loss handling.
- Owner Primary: Security Engineering
- Owner Supporting: DevSecOps / Release Engineering; SRE / Operations
