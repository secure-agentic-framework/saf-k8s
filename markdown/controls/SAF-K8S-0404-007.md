# SAF-K8S-0404-007 - Automated certificate rotation before expiry

- Domain: D04 - Identity, Access, and Secrets Management
- Knowledge Area: 4.4 - Certificate Management
- Maturity: Practitioner
- Classification: baseline

## Statement

For each supported cluster and workload certificate class, apply an approved renewal mechanism and verify issuance before expiry. Demonstrate timely certificate delivery, activation and relying-party acceptance for the consumers that use the renewed credential.

## Objective

Reduce expiry-related failure by verifying renewal and active use of the resulting certificate within defined time and availability targets.

## Rationale

Renewal mechanisms differ across certificate classes. The issuer schedule, actual issuance, key replacement, distribution, active certificate and application health are independently observable outcomes.

## Scope

Applies to governed API server, etcd, kubelet, webhook, service mesh and application certificates. Identify the actual issuer and controller for each class and record exceptions and managed service boundaries. Expiry monitoring is covered by SAF-K8S-0404-008.

## Enforcement

- Primary Enforcement Point: Effective certificate class renewal policy, observed timely issuance, and verification of active credential use by relying workloads.
- Implementation Surface: Inventory issuers, certificate validity and renewal policy, including cert-manager renewBefore where applicable and independent kubelet or control-plane paths. Observe issuance on schedule with the approved key treatment, service adoption, and trusted client behavior before the old expiry.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Security Operations
