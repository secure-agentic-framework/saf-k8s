# SAF-K8S-0606-019 - Helm chart provenance and signature verification

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.6 - CI/CD and GitOps Pipeline Security
- Maturity: Practitioner
- Classification: baseline

## Statement

Authorize the exact Helm chart artifact and signer before every governed install or reconciliation. Require successful verification using the deployed tool and approved source and identity policy. Fail closed when the required artifact or verification evidence is missing, mismatched, or signed by an unapproved identity.

## Objective

Prevent unapproved Helm packages and chart manifests from entering the governed deployment path.

## Rationale

Package integrity and signer authorization are separate requirements. A native Helm provenance record authenticates a package checksum against the configured OpenPGP key ring. OCI manifest signing and verification can use a separate mechanism with a different subject and identity policy.

## Scope

Applies to approved staging and production Helm chart deployment paths, including internal and external charts. Verify each chart transport and reconciliation tool in use.

## Enforcement

- Primary Enforcement Point: The approved CI or reconciliation path before rendering and deployment of the selected chart artifact.
- Implementation Surface: For packaged chart provenance, run native Helm verification with a governed public key ring and the matching .prov record. An OCI registry can carry Helm provenance as a chart layer; verify that the deployed Helm or controller supports the chosen flow. If using OCI artifact signatures, verify the exact manifest digest and expected signer with the selected verifier. Enforce approved source and identity allowlists, trusted key lifecycle and fail-closed behavior at the installation boundary.
- Owner Primary: DevSecOps / Release Engineering
- Owner Supporting: Platform Engineering; Security Engineering
