# SAF-K8S-0303-008 - AppArmor workload profile assignment and unconfined-mode restriction

- Domain: D03 - Workload and Pod Security
- Knowledge Area: 3.3 - Mandatory Access Controls
- Maturity: Practitioner
- Classification: baseline

## Statement

For each governed AppArmor workload class, require an explicitly approved effective profile for every regular, init and ephemeral container. Define supported placement and deny unconfined execution unless an active workload-scoped exception with approved compensating controls is enforced.

## Objective

Prove profile approval in Kubernetes admission and effective confinement on the actual scheduled runtime.

## Rationale

A Pod-level profile supplies the default and an explicit container profile takes precedence. Omitted AppArmor can leave a Pod unconfined on nodes without support. Admission success alone establishes profile selection. Runtime enforcement depends on node capability and availability of the selected profile.

## Scope

Applies to protected workload classes and their eligible nodes, based on verified AppArmor support and runtime configuration. Support versions and profile availability must be assessed for the actual cluster.

## Enforcement

- Primary Enforcement Point: Workload-class admission, including ephemeral-container updates, controlled placement, runtime enforcement and approved exception lifecycle.
- Implementation Surface: Validate securityContext.appArmorProfile on supported structured APIs and document any legacy annotation migration. Verify defaults and overrides across all container lists, allow only approved profile choices, and test current, expired and unmatched exceptions when exceptions are enabled. Retain separate admission, node readiness and runtime behavior evidence.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Application Development teams
