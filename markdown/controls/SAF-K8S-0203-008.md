# SAF-K8S-0203-008 - Pod metadata endpoint network path blocking

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.3 - Host OS and Kernel Hardening
- Maturity: Foundational
- Classification: baseline

## Statement

Prevent unapproved workload access to node-scoped cloud metadata using effective platform-supported network controls for each governed source class. Preserve explicitly approved workload identity services and required node functions.

## Objective

Deny unintended metadata connectivity while preserving required platform and workload identity paths.

## Rationale

Pod network, host-network and node-local routes can have different enforcement boundaries. Providers can implement metadata proxies and distinct identity modes, and Kubernetes NetworkPolicy applies only to paths supported by the chosen network implementation.

## Scope

Applies to governed cloud workloads and relevant IPv4, IPv6, DNS and proxied metadata endpoints as supported. Inventory ordinary, host-network, local-routing and node service paths, approved exceptions and evidence ownership.

## Enforcement

- Primary Enforcement Point: Effective provider, node, or workload network control at the path that mediates the governed metadata access.
- Implementation Surface: Verify the configured endpoint and policy inventory and approved source classes. Exercise representative allowed and denied owned paths under the actual enforcement implementation, independently verify host and node controls, and preserve required workload identity connectivity.
- Owner Primary: Cloud Infrastructure
- Owner Supporting: Platform Engineering; Security Engineering
