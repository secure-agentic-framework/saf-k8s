# SAF-K8S-0701-007 - High-performance AI storage backend hardening

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.1 - Persistent Storage Security
- Maturity: Advanced
- Classification: ai-specific

## Statement

Inventory the privileges required by each storage integration. Enforce restricted Pod security for ordinary consumer workloads. Where a node-side driver requires host access or privileged operations, confine the component to designated nodes, restrict who can create or modify it, and apply the supported host controls and approved compensating measures.

## Objective

Limit the impact of storage components that require host or elevated Pod access while preserving ordinary workload access to approved storage.

## Rationale

Some Linux CSI node plugins need host-level access for mounting or device operations. The required privileges vary by driver and platform. A workload that consumes a mounted PVC uses its own security context. Restricting privileged driver placement, configuration and workload creation authority reduces unnecessary exposure.

## Scope

Applies to actual block, file, parallel filesystem, NFS and object storage integrations used by AI workloads. Scope privileged deployment, host access rules and designated nodes to the components with documented requirements. Include workload identities, namespaces, provider and host security features, placement rules and approved exceptions.

## Enforcement

- Primary Enforcement Point: Restricted Pod Security policy for ordinary workloads, scoped admission and authorization for driver exceptions, and verified node placement and applicable host controls for privileged storage components.
- Implementation Surface: Inventory supported driver and storage configurations, exact node mounts, devices and privileges, and authorized installer and operator identities. Verify tenant Pod security, designated labels and taints, exception admission, actual node placement and supported AppArmor, SELinux or equivalent controls. Maintain the storage driver risk assessment and compensating measures.
- Owner Primary: Storage Engineering
- Owner Supporting: Platform Engineering; Security Engineering
