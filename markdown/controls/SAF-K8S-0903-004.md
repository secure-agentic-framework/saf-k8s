# SAF-K8S-0903-004 - LLM context window and token resource controls

- Domain: D09 - AI Workload Security: Training, Serving, and Pipelines
- Knowledge Area: 9.3 - Inference Resilience, Adversarial Defense, and Resource Controls
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Kubernetes-hosted autoregressive language-model inference workloads must enforce a maximum input-token limit and per-request output-token budget on every applicable inference path. Count the fully expanded prompt with the deployed model tokenizer and prompt template, and reject over-limit input before model execution. Enforce per-session output budgets for session-based APIs and token-generation rate limits for applicable caller or session scopes using server-controlled identity. Where the serving framework uses a KV cache, set and enforce per-request and aggregate cache and concurrency budgets against measured model-, framework-, and device-specific memory limits. Where accelerators are used, apply the corresponding accelerator-memory and throughput budgets; where they are not, apply documented host-resource budgets. Verify effective limits across all routes and model instances.

## Objective

Keep each accepted prompt, generation, session, and cache within its effective budget across every applicable serving path. Prevent over-limit prompts from reaching model execution, measure generated output and model/cache resource use, and validate limits against the actual model, tokenizer and template, concurrency, hardware, and workload objectives.

## Rationale

For standard full self-attention, total attention arithmetic over a sequence grows quadratically with sequence length; implementations that materialize the full attention score matrix also use quadratic working memory. Tiled exact implementations such as FlashAttention avoid materializing that matrix in GPU high-bandwidth memory, so token count alone does not predict GPU-memory use. In serving frameworks with KV caches, allocation depends on model architecture, active sequence count and length, cache data type and block policy, sharing or eviction behavior, and memory used by model weights and other allocations. Input and output budgets bound admitted request work; they do not by themselves ensure cache or accelerator-memory safety or service availability. Session and generation-rate budgets reduce one caller’s share only when the effective limiter covers every applicable route. The effect of long requests on shared capacity depends on the actual serving and queueing policy, so validate it against the deployed workload.

## Scope

Applies to every Kubernetes-hosted API and model-serving path that accepts autoregressive language-model generation, including gateways, internal routes, streaming endpoints, and active model instances. Enforce effective input and per-request output budgets wherever generation is accepted, using the deployed tokenizer and complete prompt template. Where session or caller identities exist, aggregate output and rate budgets at a server-controlled identity. Where the serving framework uses a KV cache, govern its effective allocation and concurrency limits. Where accelerators are used, measure and bound accelerator memory and throughput; otherwise document the applicable host-memory and concurrency controls. Inventory all routes and instances and verify that no applicable path bypasses the effective budgets. These controls complement authentication, network denial-of-service protection, and availability and recovery measures.

## Enforcement

- Primary Enforcement Point: The serving framework and inference engine enforcing admission, generation, session, rate, cache, and device-resource budgets, with the API gateway applying caller/session budgets as defense in depth. Every applicable route and active model instance must use an effective policy; gateway token checks do not replace engine-level cache and compute controls.
- Implementation Surface: Inventory every API route and active serving-framework/model instance. Record the model, tokenizer version, full prompt template, context limit, serving-framework and engine versions, session identity semantics, queue/concurrency policy, cache type and allocation policy, and available accelerator or host memory. Enforce expanded-input token caps before dispatch and per-request generation budgets on every path, including streaming and alternate endpoints. Aggregate session/caller budgets at server-controlled identities for session APIs and apply token-generation rate limits at the defined caller/session scope. For engines with KV caches, configure and verify effective per-request and aggregate cache limits or concurrency bounds using version-specific serving-framework controls and measured capacity. Apply and verify accelerator-memory and throughput budgets where accelerators are used, or documented host-resource budgets otherwise. Exercise exact-boundary and over-boundary requests across all routes and instances; retain input-token, emitted-token, dispatch, cache, and resource observations, and verify the response and backend work at each limit.
- Owner Primary: ML Platform Engineering
- Owner Supporting: Security Engineering; Platform Engineering; FinOps
