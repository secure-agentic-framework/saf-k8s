# SAF-K8S-0102-022 - etcd backup repository least-privilege access restriction

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.2 - etcd and Cluster State Protection
- Maturity: Foundational
- Classification: baseline

## Statement

Restrict access to every governed etcd backup repository and restore-media copy using the storage system's effective least-privilege authorization. Identify dedicated automation and approved restoration roles and govern exceptional access separately.

## Objective

Limit reading, writing, listing and deletion of retained etcd backups and restore copies to approved identities and required actions.

## Rationale

Etcd snapshots contain Kubernetes state and can contain sensitive information. Each copy inherits the access controls of the destination where it is stored. Repository or media authorization and encryption key custody are independently important safeguards.

## Scope

Applies to governed production etcd backups and restore copies in object stores, filesystems, snapshot services, appliances and offline media. Include effective inherited grants, alternate access mechanisms, restore-role separation and dedicated key access.

## Enforcement

- Primary Enforcement Point: Native authorization at each backup repository or media boundary and separate policy for applicable encryption keys.
- Implementation Surface: Inventory copies and access paths. Scope required operations by identity, repository and artifact. Verify expected routine access, denied unrelated access, constrained restoration and approved exception handling. Review effective grants and keep attributable repository evidence.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Backup and Recovery Operations
