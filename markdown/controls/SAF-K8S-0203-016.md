# SAF-K8S-0203-016 - Node time synchronization with authoritative time sources

- Domain: D02 - Node, Runtime, and OS Security
- Knowledge Area: 2.3 - Host OS and Kernel Hardening
- Maturity: Foundational
- Classification: baseline

## Statement

Synchronize governed Kubernetes node clocks to approved authoritative sources. Define sampling cadence, acceptable offset and freshness, and the required response to stale, out-of-bound or unsynchronized state. Where the selected profile requires regional fallback, verify approved secondary selection after primary loss.

## Objective

Maintain traceable node clock state within the approved accuracy and availability limits used by workload and security processes.

## Rationale

Node clock offset and measurement freshness affect telemetry correlation and time-sensitive validation. Service startup does not establish synchronized time, and timestamp accuracy depends on every participating producer and collector. Clock corrections require operationally safe handling.

## Scope

Applies to governed worker and control-plane nodes. Record controlled OS and provider-managed responsibilities separately. Document the selected time discipline mechanism, source identities and leap handling, accountable owners and permitted exceptions.

## Enforcement

- Primary Enforcement Point: Effective node OS or managed provider time configuration and observed synchronization health, measured offset, source choice and applicable fallback.
- Implementation Surface: Verify the approved source and selected reference, measurement freshness and offset against the profile, no-source behavior and alert delivery. Exercise scoped failure and recovery without modifying production clocks. For selected NIST SC-45(2) applicability, document a secondary in a different geographic region and verify synchronization to it when the primary is unavailable.
- Owner Primary: Platform Engineering
- Owner Supporting: OS/Infrastructure; Security Engineering; Security Operations (SOC)
