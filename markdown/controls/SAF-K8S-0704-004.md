# SAF-K8S-0704-004 - IMDSv2 enforcement on Kubernetes nodes

- Domain: D07 - Storage, Multi-tenancy, and Resource Governance
- Knowledge Area: 7.4 - Cloud Provider Security Integration
- Maturity: Foundational
- Classification: baseline

## Statement

Inventory enabled node metadata services and enforce provider-specific protections. On EC2 nodes with IMDS enabled, require IMDSv2 and verify the effective instance settings. Where metadata is disabled or another provider is used, record the approved protection and evidence for that platform.

## Objective

Reduce node metadata exposure and verify the effective protection for each deployed node role and provider.

## Rationale

Metadata options and workload identity vary by provider. On EC2, requiring tokens adds a session requirement; endpoint state and the token response hop limit apply separately. Defaults and intended templates can differ from a deployed instance. Verify whether workloads require provider-specific access and evaluate separate network and identity boundaries.

## Scope

Applies to governed cloud node pools and any enabled metadata endpoint in their supported modes. Identify the provider, node role, launch or replacement path, endpoint state, documented access controls and approved exceptions.

## Enforcement

- Primary Enforcement Point: Provider node settings, effective runtime configuration and documented metadata protections for each governed pool.
- Implementation Surface: For EC2 verify HttpEndpoint, effective HttpTokens, change state, relevant address families and an approved response hop limit for supported clients. Review launch, account, image and override settings and audit existing nodes. For GKE and AKS verify the documented node and workload metadata protections and collect provider-specific operating evidence.
- Owner Primary: Cloud Platform Engineering
- Owner Supporting: Platform Engineering; Security Engineering
