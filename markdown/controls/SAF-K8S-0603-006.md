# SAF-K8S-0603-006 - TUF-based secure software update systems

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.3 - Attestation, Provenance, and Cryptographic Assurance
- Maturity: Advanced
- Classification: baseline

## Statement

Implement TUF for in-scope update repositories and clients. Bootstrap clients from an authenticated trusted root and enforce the configured signature threshold for each role, expiry, version and metadata bindings, and target hashes and lengths. Set finite download limits and document key custody, rotation and recovery for each role.

## Objective

Ensure clients authenticate update metadata and target content from a trusted root, reject stale or inconsistent metadata, and enforce the approved signing threshold and recovery policy.

## Rationale

TUF separates trust across root, targets, snapshot and timestamp roles and authenticates the metadata relationships that determine which artifacts clients may select. Thresholds limit the effect of compromise below the configured number of distinct trusted keys. Choose thresholds and hardware custody based on the deployment's risk and recovery requirements.

## Scope

Applies to organizations operating internal artifact distribution systems, Helm chart repositories, or custom update channels for Kubernetes operators and AI workload components. Does not apply to organizations exclusively consuming artifacts from third-party registries that implement their own TUF infrastructure, though verification of the third-party TUF root of trust is required.

## Enforcement

- Primary Enforcement Point: Update system metadata signing infrastructure and client-side TUF verification configuration.
- Implementation Surface: Verify authenticated root bootstrap and the configured per-role thresholds. Prefer secure offline custody for root, targets and snapshot keys in accordance with the TUF specification. Document online role custody and any exceptions. Verify root rotation, expiry, rollback rejection, version and hash binding, and client download limits. Assess any required HSM integration, ceremony, audit and recovery separately.
- Owner Primary: Security Engineering
- Owner Supporting: Platform Engineering; DevSecOps / Release Engineering
