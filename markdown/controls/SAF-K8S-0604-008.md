# SAF-K8S-0604-008 - AI workload vulnerability exposure classification

- Domain: D06 - Supply Chain, Images, and Admission Control
- Knowledge Area: 6.4 - SBOMs and Vulnerability Intelligence
- Maturity: Practitioner
- Classification: ai-specific

## Statement

Classify in-scope vulnerability findings using evidenced workload purpose, exact artifact or node identity, component installation locus and observed access paths. Distinguish training, inference and related work, host driver or runtime components, and libraries supplied by containers. Retain unknown or conflicting evidence explicitly.

## Objective

Provide defensible workload, component and reachability context for a separate prioritization and remediation process.

## Rationale

Severity alone omits deployment context. A Kubernetes object kind, label, Service allocation or requested device identifies an API fact. It does not establish workload purpose, observed public reachability, runtime use or the version of a host GPU component. Use corroborating evidence for each determination.

## Scope

Applies to governed AI workloads and infrastructure, including image and node software, device plugins, injected runtime libraries and related entry points. Keep prioritization, service-level deadlines and rebuilds in their separate controls.

## Enforcement

- Primary Enforcement Point: Vulnerability management platform classification policy configuration and reporting views that segment findings by AI workload context.
- Implementation Surface: Correlate release records with live workload ownership, node and runtime image identity, and observed data paths. Use distinct authenticated sources for host, injected and image-supplied inventory and applicable advisories. Record purpose, source, timestamps, classification confidence and private or external reachability by the actual measured path. Keep missing or conflicting evidence explicit and verify deployed cluster and scanner coverage.
- Owner Primary: Security Engineering
- Owner Supporting: ML Platform Engineering; DevSecOps / Release Engineering
