# SAF-K8S-0401-004 - RBAC for AI operator custom resources

- Domain: D04 - Identity, Access, and Secrets Management
- Knowledge Area: 4.1 - Role-Based Access Control (RBAC)
- Maturity: Foundational
- Classification: ai-specific

## Statement

Organizations must govern AI operator custom resource instances through dedicated RBAC that restricts create, update, and delete to authorized ML engineering and platform roles. Discover the installed API groups, resources, and scopes before assigning permissions.

## Objective

Ensure that access to AI-specific custom resources is explicitly governed by RBAC, preventing unauthorized users from deploying, modifying, or deleting AI workloads through operator CRDs.

## Rationale

Custom resource instances such as KServe InferenceService, Kubeflow Trainer TrainJob or legacy operator jobs, KubeRay RayCluster, and Volcano PodGroup express workload intent. The corresponding CustomResourceDefinitions register those APIs and need separate administrative authorization. Without dedicated RBAC policies for these custom resources, any user with broad namespace permissions could deploy unauthorized models, consume expensive GPU resources, or tamper with training pipelines. Default RBAC often does not cover custom resources explicitly.

## Scope

Applies to all clusters running AI/ML operators such as KServe, Kubeflow Training Operator, KubeRay, or Volcano. Covers all custom resource types registered by these operators. Must be enforced in namespaces where ML workloads are scheduled.

## Enforcement

- Primary Enforcement Point: Namespace-scoped Roles and RoleBindings for namespaced custom resource instances. Review cluster-scoped resources and CRD administration separately.
- Implementation Surface: Use the installed API discovery data to grant exact apiGroups, plural resources and verbs. Review patch, deletecollection, status and finalizer permissions as applicable. Admission adds object-level constraints where required. Verify effective RBAC and retain evidence of denied access to custom resource instances.
- Owner Primary: Platform Engineering
- Owner Supporting: ML Engineering; Security Engineering
