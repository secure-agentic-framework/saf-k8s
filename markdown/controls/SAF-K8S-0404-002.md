# SAF-K8S-0404-002 - TLS provisioning for webhooks, API aggregation, and internal services

- Domain: D04 - Identity, Access, and Secrets Management
- Knowledge Area: 4.4 - Certificate Management
- Maturity: Practitioner
- Classification: baseline

## Statement

For each governed admission webhook and registered aggregation endpoint, require the Kubernetes API server to verify the actual TLS serving certificate and expected endpoint identity under approved CA trust. Verify trust and failure behavior on each call path.

## Objective

Authenticate API extension endpoints and protect extension traffic under reviewed trust and failure policies.

## Rationale

The API server's admission and aggregation clients use distinct configurations. Trust-anchor approval and serving-certificate identity are distinct from the webhook decision, fail-open behavior, extension-side caller trust and workload-to-workload security.

## Scope

Applies to configured validating and mutating webhook targets and serving endpoints registered through APIService. Built-in in-process admission plugins, standalone workloads and service-to-service mutual TLS have separate assessment scope.

## Enforcement

- Primary Enforcement Point: Actual API-server outbound TLS verification using reviewed serving certificates, endpoint identities and configured trust anchors.
- Implementation Surface: Inventory targets and trust sources, verify Service DNS or URL hostname as appropriate, require endpoint verification, and exercise unavailable targets, wrong CA or server name and positive extension behavior. Evaluate direct webhook decisions and extension-side caller authentication separately.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering
