# SAF-K8S-0303-003 - SELinux context assignment and multi-tenancy isolation

- Domain: D03 - Workload and Pod Security
- Knowledge Area: 3.3 - Mandatory Access Controls
- Maturity: Practitioner
- Classification: baseline

## Statement

On deployed nodes with the required SELinux support, require effective enforcing policy and verified workload and object labels for each defined isolation unit. Document approved shared categories and verify that the applied runtime and storage labels enforce the intended boundary.

## Objective

Demonstrate the selected workload and data isolation boundary using actual process and object labels and attributable access decisions.

## Rationale

Kubernetes seLinuxOptions requests labels. Admission acceptance does not prove kernel enforcement, and an omitted label may be allocated by the runtime on supported nodes. Shared categories can intentionally allow common access under the loaded policy. Node, runtime and volume behavior depend on the actual configuration.

## Scope

Applies to covered Linux nodes with effective SELinux support and the governed workloads and volumes scheduled there. Identify the isolation unit, actual SELinux policy, runtime, Kubernetes version and storage driver.

## Enforcement

- Primary Enforcement Point: Effective node SELinux policy and runtime and volume labeling, with separately verified Kubernetes admission and scheduling guardrails.
- Implementation Surface: Document explicit or runtime-allocated category policy and approved workload sharing. Verify Pod and container-level requests, effective contexts and enforcing mode, exact denied and allowed owned operations, volume driver and relabel behavior, and current audit coverage. Validate the complete boundary for each supported deployment.
- Owner Primary: Platform Engineering
- Owner Supporting: Security Engineering; Application Development teams
