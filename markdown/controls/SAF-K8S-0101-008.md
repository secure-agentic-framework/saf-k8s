# SAF-K8S-0101-008 - API server audit policy coverage and event detail

- Domain: D01 - Control Plane and Cluster Hardening
- Knowledge Area: 1.1 - Kubernetes API Server Security
- Maturity: Foundational
- Classification: baseline

## Statement

Production Kubernetes clusters must enable API server auditing with Metadata as the default for all resource types. Audit Secrets, TokenReviews, and service-account token issuance at Metadata, with rules ordered before any rule that could capture their bodies. Limit Request or RequestResponse recording to explicitly approved resource, verb, and scope rules whose captured fields have been reviewed for credential exposure. Verify that audit events retain the request target, verb, response status, identity when available, and authorization decision annotations where the API server supplies them.

## Objective

Preserve enough API server audit evidence to reconstruct security-relevant requests and decisions while keeping credential-bearing bodies out of audit records.

## Rationale

Kubernetes uses the first matching audit rule. An early Metadata rule protects credential-bearing endpoints from later body-level rules. Request can retain a submitted body such as a TokenReview bearer token, and RequestResponse can also retain a response such as an issued service-account token. Metadata events can retain request and decision context without either body.

## Scope

Applies to all production Kubernetes clusters, including managed services where the customer controls or can verify API server audit policy settings.

## Enforcement

- Primary Enforcement Point: Audit Policy Definition
- Implementation Surface: Ordered audit policy YAML rules, effective kube-apiserver or managed-service audit settings, and sampled event metadata for permitted and denied requests.
- Owner Primary: Security Engineering
- Owner Supporting: Platform Engineering; Compliance
