# SAF-K8S-0403-026 Secret leak prevention

Run the control by ID on fresh Kind. The case creates three isolated
publication boundaries and passes a public synthetic marker through
each before installing its gate. The enabled Git commit and Git receive
hooks refuse the marker and leave both refs unchanged. Native Kubernetes
admission prevents a governed ConfigMap from being stored. A benign
example passes all three.

The test-scoped marker is public, and the Git remotes are local temporary
directories. Verify real provider patterns, publication paths, exception
authority, and production enforcement separately.

- [Git hooks](https://git-scm.com/docs/githooks)
- [Kubernetes ValidatingAdmissionPolicy](https://v1-36.docs.kubernetes.io/docs/reference/access-authn-authz/validating-admission-policy/)

## Verify an adopting implementation

Enumerate every write and promotion path, including
mirrors, bots, generated artifacts, and direct deployment credentials. For
each path, retain policy/configuration and an inert marker denial showing no
state change, followed by an approved benign promotion. Record scanner rule
coverage, bypass controls, exception owner/expiry, and correlated audit
evidence. Link workload admission and pipeline gates separately.
